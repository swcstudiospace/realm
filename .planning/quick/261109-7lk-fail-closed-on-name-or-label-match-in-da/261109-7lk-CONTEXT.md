# Checkpoint daemonless safety

The daemonless checkpoint stopped proof currently inspects only the expected container name. Realm workload ownership/discovery also uses OpenShell sandbox-name labels, so a differently named but label-matching container could be missed. Normal driver creation assigns matching names and labels; that does not establish the invariant for every existing container. Fail closed: retain the exact-name inspect and additionally query the existing libpod label listing for openshell.ai/sandbox-name equal to the expected session sandbox name, including stopped containers; stopped is proven only if BOTH checks show absence. Bounded errors and malformed or incomplete listings must refuse. Repeat the full proof inside each existing sandboxRunning invocation and retain the checkpoint/session lock semantics. Reuse existing label constants and libpod APIs, no secrets or output leakage. Scope likely src/cli/checkpoint.ts, src/cli/main.ts only if dependency injection needs it, test/cli/checkpoint-stopped.test.ts and docs/checkpoint.md. Tests cover matching label with different container name, name-only match, neither, listing failure/timeout and repeated proof; no live systems.

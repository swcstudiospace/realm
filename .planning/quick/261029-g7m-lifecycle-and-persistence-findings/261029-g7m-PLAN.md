# Quick task 261029-g7m: lifecycle and persistence findings

## Objective

Answer with evidence two questions about the Omp plugin, and propose eight improvements, without changing any code:

1. Does the plugin create the sandbox automatically when Omp opens a new session?
2. Are files kept and recoverable when a session ends abruptly?

The request also asked for the outstanding TODOs, phases and milestones to be completed. The ROADMAP has no incomplete phase, so the gsd-autonomous workflow has nothing to run (its branch for that state prints "All phases complete! Nothing left to do."); this task therefore records the position and the carried items instead of inventing phases.

## Tasks

1. Inventory every outstanding item: phases, TODO-style markers, carried requirements, tech debt, owner decisions (`OUTSTANDING-WORK-INVENTORY.md`).
2. Trace the sandbox lifecycle from the Omp session events to the container, and state the verdict with evidence labels (`SANDBOX-LIFECYCLE-FINDINGS.md`).
3. Map what survives each abrupt end, per state class and termination scenario, with data-loss windows and recovery behaviour (`ABRUPT-END-PERSISTENCE-FINDINGS.md`).
4. Verify the findings by running the plugin: a real Omp session with a scripted local provider (no credentials, no tokens), a daemon kill-and-restart probe, a real-SIGKILL test of the write path, a trace of Omp's own write, an abrupt Omp end, and an environment check. Record the output (`LIVE-VERIFICATION.md`).
5. Propose eight improvements for selection, without implementing any (`IMPROVEMENT-PROPOSALS.md`).
6. Write a runbook that lets the owner repeat the checks on a real host (`docs/integration/omp-lifecycle-runbook.md`), and correct the two statements in `README.md` and `docs/integration/omp.md` that the checks showed to be incomplete.
7. Record the task in `STATE.md`.

## Done when

- every claim in the findings carries a path and line or an execution record, or is marked UNVERIFIED;
- the baseline gates are recorded and green, and no source, test, script, workflow or release file is changed;
- `npm run check:docs` passes;
- no requirement status, ROADMAP entry or version field is changed.

## Out of scope

Implementing any proposal, adding a phase or milestone, changing the status of OMP-05 or any other requirement, and any change under `.github/workflows`, `release` or `scripts/release`.

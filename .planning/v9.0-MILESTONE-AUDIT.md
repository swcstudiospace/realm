## Accepted limitations

- **F-51-1 (STOP-05, STOP-06): cause not established.** The 2026-11-27 window produced 0/36 dirty stops (`AGENTOS_STOP_FAILED` with `failedTeardowns` 1 never recurred), so the new `causeCode` emission was never exercised on a dirty stop; the Phase 51 inference stands unreplaced. The **row-absent pattern** (3 identical stops, daemon exits <210 ms with no stopping/stopped row, ~226 s gap to next up) is recorded as new evidence whose own cause is also not established; its teardown state is unknown, not zero.
- **HTIER-01 (Phase 57):** cold + warm **attribution fail evidence** — the Grok Build host leaves in 1.3–3.7 s before the realm attach settles; no `grok-build` audit line, no presence dir, 0 boot reports in either variant. GAP-40-01 (missing host feature: no Grok Build seam names the host in a shared file; workaround `realm host install grok-build`) and GAP-48-01 stay accepted-residual. Lift requires the attach to complete inside the host's few-second window, not another retest.
- **Phase 58 cleanup-down caveat:** `realm down` TOOL_TIMEOUT twice under load at cleanup of the deciding kimi rerun (whole test 37–42 s under sustained load 20–46; daemon-side control/queue bound, well before the harness 120 s bound). Teardown completes (zero containers, daemon absent). Recorded as a **separate teardown-bound observation** (cf. Phase 56 row-absent stops); it does not reopen GAP-43-03, which closes on the wire-log evidence.
- **Phase 59:** live two-process binding proof (two daemons binding one workspace) not claimed; hermetic suite pins the refusal codes per the phase plan's no-live-run rule.
- **Phase 56:** 20-consecutive shown only mid-window — peak 26 consecutive clean iterations inside a window that ended OTHER-FAILURE at failure-cap 3; the criterion's window form (≥20 consecutive with `failedTeardowns` 0 as the window outcome) is not met.

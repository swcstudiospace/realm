## Locked decisions
- **D-1301 audit is blocking.** A new `audit` job in `ci.yml` runs `npm audit --omit=dev --audit-level=high` at the root (Node 24.x, no matrix) and is added to the release job's `needs`, so a high production advisory blocks a release. `site/` is not audited (its dev-only advisories are red today); Dependabot covers it.
- **D-1302 Dependabot.** `.github/dependabot.yml` covers `github-actions` (root) and `npm` (root and `site/`), weekly, with conventional commit prefixes `ci` and `build`, grouped updates, and an ignore for major versions of `@types/node`. Nothing else is ignored: the owner accepted that Dependabot pull requests go through the Greptile and ship flow.
- **D-1303 TD-07.** "Host snippets" means the four adapter files that ship in the tarball and are not asserted today (`hermes-agent/mcp.snippet.yaml`, `muse-code/mcp-settings.snippet.json`, `prime-agent/MCP.md`, `prime-agent/skills/realm/SKILL.md`). The six `docs/hosts/snippets/*.md` are published by the Pages site and do not join the tarball. `pack-smoke` gains a walk check (every file under `adapters/` and `licenses/` exists in the installed package, so the next added file is caught), `--tarball <file>` and `--expect-version <x.y.z>`; the release job and the Finish worktree run `pack-smoke --tarball ... --expect-version ...` after the build and pack step and before any remote mutation.
- **D-1304 coverage.** `npm run test:coverage` runs the compiled suite under `--experimental-test-coverage --test-coverage-include=dist/src/**` with the lcov reporter; `scripts/check/coverage.mjs` (Node built-ins only, with pure `aggregateLcov` and `compareToFloors` tested against synthetic lcov) sums lines, branches and functions per directory for `src/fs`, `src/core` and `src/tools` and compares them with `scripts/check/coverage-floors.json`. One CI leg (22.x) is the gate leg. The first landing is report-only; the floors come from a CI run (floor = floor(measured) minus a tolerance of 1.0), set in a second small pull request, because this host's gating state and load differ from CI. The script's `--write` mode only raises floors; lowering needs a hand edit with a reason.
- **D-1305 time.** `test/support/timing.ts` exports `TIMEOUT_SCALE` (1 by default; `REALM_TEST_TIMEOUT_SCALE`, a number from 1 to 10, overrides it), `scaledMs`, `testTimeout`, `boundedWait`, `pollUntil` and `ManualClock`. `LibpodClientOptions` gains an optional `now` (default `() => performance.now()`), the one `src` change, matching `src/runtime/agentos.ts` and `src/anda/client.ts`. `test/support/fake-execution.ts` gains a hold gate (`hold(op)` returns a release function; `settled()` resolves when every started call has completed) so the idempotent lifecycle test needs no 9-second wait. The 21 `{ timeout: 10_000 }` caps under `test/acp` and the guard timers the research lists use the helper. The suite is run once in a CPU-limited setup and the load level and result are recorded.
- **D-1306 dead exports (TD-09).** Coverage output cannot find dead exports (an export used only by tests is covered by them); reference analysis can. The method is a built-ins-only script, committed as `scripts/check/export-usage.mjs --list` (informational, no ratchet). Scope: exports used only inside their own file lose the `export` keyword (and are deleted when `noUnusedLocals` then flags them); exports used only by tests are kept as documented seams unless an item is obsolete, decided per directory in the pull request; `src/core/errors.ts`, the schema validator types, the `ports` types and the error catalogue are out of scope. QR-06's wording "found with the coverage output" is amended to "found by reference analysis" in the requirement and in the roadmap criterion, with this reason. One pull request per group of directories, small and rebased often, because other lanes edit the same directories.
- **D-1307 property tests.** `fast-check` 4.10.2 (MIT, two packages in its tree) is added as an exact-pinned dev dependency; the pull request body records the three items `CONTRIBUTING.md` requires. Properties: the canonicalizer (no result escapes the root for random `..`, symlink, NUL, doubled-slash and unicode inputs, the research's C.3) and the policy parser (round trip, unknown keys rejected; the default-mode property reads the schema because Phase 15 flips the default). A deliberate breakage of the canonicalizer is shown to fail at least one property and recorded in the pull request. A NUL after a missing segment is recorded as a finding unless it is a defect (decided in the pull request).
- **D-1308 mutation.** A spike decides between Stryker in an isolated directory with its own `package.json` and lockfile (Stryker's tree is 188 packages and its fit with `node:test` on compiled output is unproven) and an in-repo script. Either way nothing is installed at the root, the workflow `.github/workflows/mutation.yml` is scheduled weekly plus `workflow_dispatch`, has `contents: read`, uploads the report as an artifact only and never fails the run, and Dependabot covers the isolated directory.

## Frozen contracts touched

## Acceptance (the ROADMAP success criteria)
1. `ci.yml` runs the audit; `.github/dependabot.yml` covers the three targets (QR-01, QR-02).
2. `pack-smoke` fails when one of the four files is missing from the tarball, and the release job reruns `check:pack` on the release tarball after the version sync (QR-03).
3. `npm run test:coverage` prints the coverage output and CI fails below a recorded floor, shown by a run against a raised floor; the dead-export work is done by reference analysis with the frozen catalogue unchanged (QR-04, QR-06).
4. The libpod TTL test and the idempotent lifecycle test use injected clocks or a hold gate; the ACP caps and the other fixed waits use the helper; the suite passes CPU-limited (QR-05).
5. The property tests run in `npm test`, a broken canonicalizer fails one, and the scheduled workflow exists (QR-07, QR-08).

## Risks and stop conditions
- A coverage floor set too high blocks every merge; floors come from CI measurements with a tolerance, and the first landing is report-only.
- The audit job can turn `main` red on a new advisory; the answer is a Dependabot pull request or a recorded exception.
- Mutation testing is slow and stays off the critical path.
- `package.json`, `package-lock.json` and `ci.yml` are shared across the pull requests of this phase: edits to them are serialized. Dead-export removal conflicts with the runtime and Omp lanes; slice by directory.
- Stop and report instead of widening scope if a floor cannot be set without a CI run, or if Stryker cannot run on compiled output (then the in-repo script is the fallback and the reason is recorded).

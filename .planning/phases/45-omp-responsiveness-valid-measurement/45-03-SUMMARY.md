## Deviations (read first)

1. **Task 1 was not done as written, and is not marked done.** `45-FEASIBILITY.md` and `45-DESIGN.md` do not exist in the tree (plan 45-01, the feasibility window as the realm account, has not run), so the gate "design frozen" is unmet. On the orchestrator's instruction (provisional execution on the 45-CONTEXT defaults) the harness follows 45-CONTEXT D-45-03 to D-45-10 as written: Branch S, the wrapper `systemd-run --user --scope --quiet --collect --`, the scope's `cpu.pressure` (the cumulative `total` of the some line) and `/proc/PID/task/PID/schedstat` of the main thread. Each is isolated: the argv in `SCOPE_RUNNER_ARGV` and `scopedWrap` (with a hermetic test pinning it by value), the branch in `DESIGN_BRANCH` (the one constant the live file takes it from), the readers in `createContentionSampler` and `readThreadSplit`. `scopedWrap(branch, isolation)` has a seam for the approved root-assisted CPU step (OD-45-1): an argv prefix put before the scope command (for example a `taskset` or cpuset step), empty by default, pinned by a test. When plan 45-01 freezes the design, any amendment is a change to those named places and their tests; Branch X (the owner took the root-assisted isolation) needs its own plan. The thresholds and the Phase 38 constants were compared to the code by the tests below (guard test in `omp-contention.test.ts`), not against a design file.
2. `stallSet` shares are the share of the stall set's **summed intervals** (on-CPU, run-queue and sleep together), as D-45-05 says. The plan text says "of the self part"; with the run-queue excluded the two shares add to 1 and the cause `mixed` would be unreachable, so D-45-05 was followed.
3. `attributeInterval` clamps a thread counter that went backwards by at most `SLEEP_ROUNDING_MS` (readings stamped within a millisecond can be taken in the other order); a larger regression is the inconsistent-reading error.
4. `verifyScopedChild(pid, expectedScopeDir, reader)`: systemd names an auto-named scope after the id of the process it wraps, so the exact directory cannot be known before the start. `expectedScopeDir` is therefore `null` in the live test and the check is: the command name is not `systemd-run`, and the cgroup leaf is `run-p<pid>-i<digits>.scope`. **That naming is from `systemd-run(1)`, not observed on this host**; plan 45-01 or the first calibration run shows it. A different name makes every run refuse loudly (REFUSED), never silently.
5. The scoped control's serving window is the probes sent at or after the ready frame; its loop stops when `MIN_WINDOW_MS + 2 * PROBE_INTERVAL_MS` have passed since ready (or at `CONTROL_MAX_WINDOW_MS`), so the window holds at least `MIN_PROBES` probes and spans `MIN_WINDOW_MS`, like the cold window, and `responsivenessProblems` of the control summary is satisfiable. The Phase 44 control stop rule (5 s after the first answer) is not used by the scoped arm; the unscoped control, baseline and cold tests keep theirs.
6. `mechanicalValidity`: a lost scope or run-queue reading is a V0 refusal only when the mechanics held (so V1 is the first failed rule of a run that never reached its window, keeping the order V0, V1, V2, V5, V3, V4). V5 reads the cold window, and for a calibration control (which has no cold window) its own window. `buildRunRecord` records `mechanics` as the arm test's flag and the metrics being computable (a missing ready time or first answer is V1).
7. `causeOfRun`: a breach whose stall set is empty is the inconsistency error only when it is a latency breach (it cannot be); a shortness-only breach (too few probes, a short window) is `unattributed`.
8. `decideVerdict` with unset bounds returns VOID, reason `uncalibrated`, and an empty run table (it does not judge runs without the bounds). `analyseWindow(attempts, bounds)` takes the bounds as an argument (the caller passes `CALIBRATED_BOUNDS`), and lists pairs that have only one arm in `incompletePairs`.
9. The live arm test adds `XDG_RUNTIME_DIR` (from the test's own environment) to the Omp environment of the scoped runs, which `systemd-run --user` needs; nothing else is added (D-45-03).

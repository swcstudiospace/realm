  <behavior>
    Written first, failing first, in test/support/stall-probe.test.ts, with a manual scheduler, a manual wall clock and a manual CPU reader (no real event loop, no process.cpuUsage):
    1. createSliceRecorder takes now (milliseconds), cpu (cumulative CPU milliseconds) and schedule (takes a callback, runs it later). start records a first reading and schedules a tick; each tick records one slice (wall milliseconds and CPU milliseconds since the previous reading) and schedules the next; stop ends the loop at the next tick and returns the report. A recorder that was stopped records no further slice. Starting twice, or stopping before starting, is an error.
    2. The report holds every slice in order, the count, the largest CPU slice, the largest wall slice and the total CPU. A manual run where one tick follows a 400 ms CPU advance reports a largest CPU slice of 400 and a count that matches the ticks.
    3. CPU and wall are independent: a slice with wall 5000 and CPU 3 reports CPU 3 (descheduled time is not CPU); a slice with wall 400 and CPU 400 reports 400.
    4. blockingVerdict(report, limitMs) returns blocking true when the largest CPU slice exceeds limitMs, false at exactly the limit, and carries the largest CPU slice, the limit and the index of the slice in its message; assertNoBlockingSlice throws an Error with that message when blocking and returns normally otherwise. Boundary cases at the limit and one millisecond above.
    5. STALL_SLICE_CPU_MAX_MS is exported; its value test is added in Task 3 when the value is known (this task exports it with the provisional value 100 and a comment saying so, and the pinning test arrives with the final value).
  </behavior>

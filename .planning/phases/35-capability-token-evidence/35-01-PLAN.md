## Trust Boundaries

| Boundary | Risk |
| --- | --- |
| Window to the account that owns the production stack | A hermetic run overlaps a live run or leaves residue (processes, temporary files) under that account |
| Evidence to the repository | A path, a token or a long hash is committed; a skipped test is written as a pass |
| Harness copy to the account | The run silently depends on the harness checkout or runs as root |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-35-01 | Repudiation | A skipped memory-probe test is recorded as a pass | high | mitigate | Task 4 step A3 requires an ok line, not a skip; the page vocabulary has no pass-by-skip; the summary names the skip reasons |
| T-35-02 | Spoofing | The run was as root although recorded as uid 5002 | high | mitigate | The id of the wrapper is printed at the start of each run and kept; a skip caused by root invalidates the run (Task 4 step C) |
| T-35-03 | Information disclosure | A token shape, a key or a host path reaches the page or the evidence | high | mitigate | The page test scans for the token shape, 32-character hex runs and host paths; Task 4 step E searches the evidence directory; only counts, statuses and digest prefixes are copied |
| T-35-04 | Tampering | A root-only fixture is hidden by weakening its assertion | medium | mitigate | Task 5 step 1 keeps the assertion's meaning and records the earlier failure with its date; the parent reviews the diff of any fixed test file |
| T-35-05 | Denial of service | The run collides with a live run under the same account | medium | mitigate | The shared live lock; the account's processes and the shared state hashes are compared before and after |
| T-35-06 | Information disclosure | ptrace_scope is assumed and has changed | medium | mitigate | The value is read in the window and written to facts.txt; a value other than 1 stops the plan |

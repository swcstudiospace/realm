  <name>Task 1: The probe module: parsing, scanning, reports, redaction</name>
  <files>test/support/memory-probe.ts, test/support/memory-probe.test.ts</files>
  <behavior>
    - Types. A needle is either a text needle (a name and a text, searched as Latin-1 and as UTF-16LE) or a bytes needle (a name and base64 bytes, searched raw). A specification has a kind: target (a pid and the needles, the names of marker environment variables to look for, an optional keyring file path to test for readability, optional bounds that default to 2 GiB and 60000 ms and are overridable so tests can hit them with small values) or descendant-control. A report has: the probe's uid, the Yama ptrace_scope text or unreadable with the errno name, the probe's and the target's parent chains (pids up to 1) and a boolean probeIsAncestorOfTarget; the target's uid and TracerPid from its status file; environ (read: readable or denied with the errno name; markers: name to boolean; tokenShapes: count); mem (open: ok or denied with the errno name; regions: listed, read, failed as a map errno name to count; bytesRead; truncated: true when a bound stopped the scan, with regionsUnread; needleHits: name to counts per encoding; tokenCandidates: a list, capped at 50 with a candidatesTruncated flag); keyFile: readable, denied with the errno name, or not-asked. Every value is a number, a boolean, a short word or an errno name.
    - parseMaps takes the text of a maps file and returns the regions with start, end (numbers), the permission string and the path; it keeps only regions whose permissions are exactly rw-p (private, readable, writable) for scanning, skips zero-length and malformed lines, and counts them as listed only when kept. A region larger than the total bound is scanned until the bound.
    - scanChunks reads a region through a read function (a position and a length returning a buffer or throwing an error with a code) in chunks of 1048576 bytes with an overlap of 512 bytes, so a token that straddles a chunk boundary is found once. A hit is identified by absolute address and encoding and counted once even if it falls in an overlap. A read that throws is counted under its errno name and the scan continues with the next chunk. The scan stops when the total bound or the time bound is reached and says so.
    - The token-shape search finds the prefix rcap1 followed by a dot in Latin-1 and in UTF-16LE (a bytewise search, any alignment), then consumes the following characters of the base64url alphabet and dots up to 600 characters, and keeps a candidate only when it has exactly three non-empty dot-separated parts and the second and third have at least 8 characters (the shape of src/audit/redact.ts and src/capability/token.ts). For each candidate it reports the encoding, the length, the first 8 hex characters of the SHA-256 of the text, and, when the payload part decodes as base64url JSON with the keys of a token payload, the public claims host, kid, the first 8 hex characters of the SHA-256 of sid, and exp (null for each when it does not decode). The text itself is never kept past the hash and the claim decode.
    - Redaction is structural: the report builder accepts only the typed fields above, so no function in the module can place a needle or a candidate text into a report; a test serialises a report built from a buffer that contains a known token and a known key and asserts the serialisation contains neither text nor the key bytes in hex or base64 form.
    - The probe's reads are read-only: files opened with the read flag; the module contains no write to a proc file, no signal, no ptrace call, no child process other than the control holder; the control holder is a child node process that receives a synthetic token on its standard input, keeps it in a variable, prints one line ready when it has it, carries one marker variable in its environment and exits when its standard input ends.
    - The descendant control is a function that, inside the probe process, mints a synthetic token with a random throwaway key through the token module (src/capability/token.ts), spawns the holder, waits for ready with a bound, runs the same target probe against the holder's pid with the synthetic token as a needle, kills the holder and returns the report with the control's expected digest prefix. It is the ancestor of the holder by construction.
    - The detached starter takes the probe entry path, a specification and a result file path and returns the parsed report. It spawns a short-lived starter node process whose standard input receives the specification, which spawns the probe entry detached with the specification on the probe's standard input and the result path on its command line, closes the pipe, and exits; the probe is reparented, so it is not a descendant of the caller and the caller is not its ancestor. The starter waits for the result file with a bound and a clear error, never a hang.
    - Edge cases: a pid that does not exist (the report says target gone, every other field not-asked, no throw); a pid of the probe itself (allowed, used by the unit test as a positive self-check); an unreadable maps file; an open of the mem file that is denied (zero regions read, zero hits, the errno recorded); a read error on one region (counted, the scan continues); a total bound of a few bytes (truncated true, regionsUnread correct); a needle of zero length or a name that repeats (rejected before any read); a specification with extra members (rejected); a result file that never appears (the starter times out with an error naming the stage).
    - Unit tests (hermetic, any platform that has /proc; the rest of the logic tests use injected read functions and need no /proc): parseMaps on a fixture with rw-p, r-xp, rw-s and malformed lines; a token split across two chunks is found once; a UTF-16LE token is found; a token inside the overlap is not double counted; a token-shaped string with two parts or a short mac is not a candidate; the claims decode for a real minted token and are null for a shape with a garbage payload; a read error is counted by name and the scan continues; the total bound sets truncated and regionsUnread; the report serialisation contains no needle text, no candidate text, no key bytes; the module's source is not read by any test (observable behaviour only); on Linux a self-probe finds a token held in the test process (the positive self-check), and a probe of a pid that is not alive reports target gone.
  </behavior>

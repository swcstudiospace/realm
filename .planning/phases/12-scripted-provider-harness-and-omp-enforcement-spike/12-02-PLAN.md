<objective>
Close verification gap 1 of `12-VERIFICATION.md` (CR-01, confirmed in source) under the owner's binding ruling of 2026-11-12, and rewrite the tests that pin the defect.

Owner ruling (binding, supplied by the orchestrator): in advisory mode, when the realm status cannot be read (daemon unreachable), a host `edit` and a Realm `write` are REFUSED with no file written. The advisory allowance applies only while the daemon is reachable, as AGENTS.md (Project section) states.

Purpose: a host `edit` can no longer land on the host with no daemon decision and no audit line when the last published mode is advisory and the status cannot be read. The Realm `write` is handled the same way under advisory, so no cached advisory mode can authorise a registered write while the daemon is unconfirmed.

Output: the guard change in `src/omp/plugin.ts`, the six pinned tests rewritten to assert the refusal, a probe that reads the published mode without relying on the defect, and the docs that describe the old allowance.

Requirement scope: this plan addresses HARN-02 and OMP-05 on the code side only. OMP-05's "never silently fall back to unsandboxed mutation" is the requirement this defect breaks. Neither requirement is closed here: the live half (C1 to C4 and HARN-03) is human/live verification in plan 12-03 and is not claimed.

Tracer-first: not applied. This is a gap closure that repairs an existing, already-wired end-to-end path (guard, plugin, daemon client) in place; it adds no new layer.

Frozen contracts: none touched. No change to the daemon control protocol, the tool contract, the catalogue (`src/core/errors.ts`) or the policy schema.

Out of scope for this plan (see `<deferred>`): WR-02, WR-03, WR-04, WR-05, WR-06 and IN-01 to IN-04. Also out of scope: any edit to `.planning/REQUIREMENTS.md`, `.planning/ROADMAP.md`, `.planning/STATE.md`, `AGENTS.md` or `CLAUDE.md`.
</objective>

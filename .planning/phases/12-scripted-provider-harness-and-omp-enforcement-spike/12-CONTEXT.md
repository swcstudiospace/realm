- **D-1201 two tiers of gating.** `REALM_LIVE_OMP=1` opts in to any test that starts a real Omp process; it is hermetic (no Podman, no image, no openshell) and is never set by a test. `REALM_OMP_BIN` optionally names the Omp executable (default `omp` on `PATH`). `REALM_OMP_NET_TRACE=1` opts in to the strace-based network assertion. The optional production-stack case C4 additionally needs `REALM_LIVE_PRODUCTION=1` and its four existing variables (`productionSkipReason`, unchanged). `ompSkipReason` returns the first missing prerequisite, in the order: opt-in variable, Linux, Omp executable present, `omp --version` parses and is at least 18.12.6, built extension present, then for the trace `strace` present and able to trace. Helpers that already exist in `test/support/production-live.ts` (`isDirectory`, `onPath`, `runCommand`, `pollUntil`) are reused, not copied.
- **D-1202 the three cases run against an in-process real daemon with fakes.** `startDaemon` runs in the test process over `FakeExecutionService`, `FakeBridge`, a scripted probe and `sweep: async () => 0`, as `test/daemon/e2e.test.ts` does; Omp is a child process that dials the control socket. `down` over the control channel removes the socket, which is what the live `realm down` does. Cases: C1 advisory with the realm down (the notice `realm status unavailable (REALM_NOT_ACTIVE); the write proceeds under advisory policy` and the file exists), C2 fail-closed with the realm down (the call is blocked with `REALM_NOT_ACTIVE`, the file is absent, the provider's next request carries the error), C3 the realm active (the call proceeds on the host; the offered tool list is recorded as the baseline that Phase 16 changes). C4 (optional, doubly gated) reproduces the live attach and the blocked write on the production stack once. Each case has its own temp profile, daemon and Omp process. The policy mode is always written explicitly, because Phase 15 flips the default.

## Risks and stop conditions
- Omp ready takes 10 to 60 s on a loaded host; three cases need at least three starts. Generous bounds, no speed assertions.
- Enforcement is partial by default: removing `write`, `edit` and `bash` leaves `ast_edit`, `lsp`, `debug`, `eval`, `task` and `local://` writes reachable. The spike records the full list; Phase 16 removes by an allowlist or a computed denylist, and the product claim follows what is proven.
- `strace` may be absent or blocked on a host; the assertion skips with a reason. Parallel test files share the CPU but no ports.
- Stop and report instead of widening scope if the spike shows that the extension API cannot block a built-in at all; that changes D3's outcome and Phase 16's claim.

> Revised after the live proof (39-CONTEXT D-39-13): every mention of coreutils `timeout`, `--kill-after`, the SIGKILL grace and a group kill in this plan is superseded. The in-sandbox watchdog is a bash wrapper that sweeps /proc and signals each process by pid (inside the sandbox a signal to a process group is denied). The image requirement is /usr/bin/bash 5.0 or newer (plus sleep and cat), not /usr/bin/timeout. Read the argv as: /usr/bin/bash, -c, SCRIPT, realm-exec-wd, 28.5, then the caller's argv.

<objective>
Fix the kill path (EXEC-02): a timed-out exec's process tree is ended inside the sandbox by a watchdog that does not depend on the OpenShell gateway, the supervisor or the client being alive, with the reply and the bounds unchanged for callers (EXEC-03). Pin the kill semantics with hermetic tests that run the real coreutils `timeout` against a real local process tree, and update the two argv pins that see the wrapper.

Purpose: the code and the upstream record say a timeout kills only the local OpenShell client (39-CONTEXT E-39-02, E-39-04, E-39-05), so the sleeper of finding F-3 most likely lived on until its own end. Plan 39-01 builds the proof; this plan makes it pass.
Output: one new pure module, a small edit of runSandboxExec, tests, updated pins, a comment fix.
Non-goals: no change to the TOOL_TIMEOUT reply, retryable flag, bounds, audit line or catalogue; no change to buildExecArgv, the runner child or the probe; no per-call timeout parameter; no doctor check; no live run (Plan 39-03); no documentation (Plan 39-03 writes it from the evidence).
</objective>

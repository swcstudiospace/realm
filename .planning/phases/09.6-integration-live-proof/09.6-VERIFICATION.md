# Phase 9.6 verification: integration and live proof (in progress)

Status: in progress. The production realm runs end to end on the host: realm up reaches active, the sandbox runs its workload under the realm policy, the 16 MiB round trip is byte-identical, realm down leaves no residue, and a wrong image digest fails closed. The items below marked OPEN are not done.

Build: 61cce5c (live run 2026-10-27). Podman 5.7.1 (/usr/local/bin/podman; /usr/bin/podman is 4.9.3 and must not be first on the realm PATH). OpenShell CLI and gateway 0.1.5. Host: the realm account, rootless.

## Verified live (names and values only)
- realm up exits 0; realm status reports active ("container running"). The sandbox realm-daemon reaches Ready, and its container runs. Active requires the runner probe to pass, so the runner heartbeat was observed.
- The workload process is the AgentOS runner (node /usr/local/lib/realm/agentos-runner.js) as a child of the in-container runtime (PID 1: openshell-sandbox --bootstrap). The runner runs as uid 1001.
- Capability and enforcement state of the workload: CapEff 0, CapBnd 0, NoNewPrivs 1, Seccomp 2, IPv6 disabled (disable_ipv6 1).
- Realm policy write rules: /tmp writable; /workspace writable and bound to the pinned host root (a file written in the sandbox appears in the host workspace); /etc and /home read-only (EROFS).
- Egress from the sandbox: a non-allowlisted connection is refused (EACCES). The AgentOS path is deny-all by design (no egress list is passed).
- 16 MiB round trip (host to sandbox with sandbox upload, sandbox to host with sandbox download): byte-identical, SHA-256 matched on both legs.
- realm down: exit 0. Zero realm containers, zero sandboxes, zero supervisor processes, zero secret directories, and the daemon stopped.
- Wrong image digest (the configured image replaced by an all-zero digest): realm up fails closed with OPENSHELL_START_FAILED, and zero containers remain.
- The sandbox's exec path works: exec'd processes run under the same policy, and an exit status is propagated (7 observed).

## OPEN
- OMP-LIVE-04 (shutdown leaves the daemon running): observed on two print-mode runs of a live Omp session that loads the built extension with -e under an isolated profile. The daemon stayed up after the Omp process exited. The Omp model call failed on the provider's billing limit, which is unrelated to the realm.
- OMP-LIVE-01 and OMP-LIVE-03: not verified. An earlier attach check counted a control-socket connection, and that claim is retracted: the socket seen belonged to the sandbox's own channel, and the daemon's own socket had no holder during the run. An interactive run under a pseudo-terminal stalled in a stopped state (job control), so the status item was never read. Next: run the TUI under script(1) or in a foreground process group, read the status item, then issue realm-retry after a realm down and a realm up.
- PRD-ENF-03, keyctl EPERM: not run (no keyctl tool in the image). The owner decided on 2026-10-26 to amend the /tmp expectation to the realm policy (/tmp writable, /workspace writable, /etc and /home read-only, NoNewPrivs 1, Seccomp 2). The amendment is recorded here; REQUIREMENTS.md is not yet changed.
- Writes to /dev/null are denied inside the sandbox ("cannot create /dev/null: Permission denied"). The realm policy's filesystem rules do not list /dev, so a shell redirect to /dev/null fails. This is a usability defect in the policy, not a boundary weakening. Follow-up: allow /dev/null for write in the policy, with a test.
- Egress allowlist (RT-05, the allowed-host connects case): not testable on the AgentOS path, which is deny-all. The session path has an egress input, but no configuration key sets it. Open decision for the owner.
- The realm daemon reads REALM_DRIVER_STATE_ROOT, REALM_DRIVER_SECRET_ROOT, and REALM_DRIVER_WORKSPACE_ROOT from its environment. Without them a session create refuses with SCHEMA_INVALID. The live runs set them on the realm command line. Open decision: move them into the realm configuration, or keep them as operator environment.
- Host residue: the state directory's workspaces/default folder is no longer used by the driver, and can be removed after it is checked empty.
- Docs cutover (PRD-DOC-01) and the remaining CLEAN-01 review are not complete for the new flow.

## 3. Design

### 3.1 OBS-01: hash chain and `realm audit verify`

**Line format (additive).** New fields first, then the existing ones, then the new optional id:

```
{"seq":12,"prev":"<64 hex>","at":"...","sessionId":"daemon","correlationId":"<uuid>","tool":"write","outcome":"ok","phase":"admission","path":"a.txt"}
```

- `seq`: integer >= 1, strictly +1 per line of the chain. `prev`: lowercase hex sha256 of the **raw bytes of the previous physical line** (no trailing `\n`). First line of an empty file: `seq 1`, `prev` = `AUDIT_GENESIS_PREV` = 64 zeros. `seq` and `prev` are added after redaction (merge outside `redactValue`), so redaction can never alter them.
- No canonical JSON is needed: the hash is over the stored bytes and the verifier hashes the stored bytes.
- `correlationId?` (OBS-02) is an optional string matching `/^[A-Za-z0-9_-]{1,64}$/`, else `SCHEMA_INVALID` (same rule class as the session id, `log.ts:69`).

**Migration, no marker line.** A pre-chain file is a prefix of lines without `seq`. Rule: the writer continues from whatever the last line is.
- Head recovery on every append (new `src/audit/chain.ts`, `readChainHead(fd)`): read the file tail backwards in 64 KiB chunks to the last physical line (cap `AUDIT_LINE_MAX_BYTES` = 4 MiB). `prevHash` = sha256 of that last physical line (torn or not), or GENESIS for an empty file. `nextSeq` = (`seq` of the nearest parseable chained line, scanning back at most 64 physical lines) + 1, or 1 if none is found (legacy tail, empty file, or only garbage).
- The first chained line over a legacy file therefore has `seq 1` and `prev = sha256(last legacy line)`: it commits to the last legacy line only. Legacy lines are unprotected (said in the docs and in the verify output as `legacyLines`).
- `appendAudit` refuses (AUDIT_WRITE_FAILED) a serialized line over `AUDIT_LINE_MAX_BYTES`, so recovery is bounded. The 1 MiB control line cap makes this unreachable in the daemon path; the limit is for in-process callers.
- Stateless recovery (a tail read per append) instead of an in-memory head per file: rejected an in-memory cache because it goes stale if anything else appends and it needs a separate "recover at startup" path; cost of the tail read is one `pread` of normally < 1 KiB, next to an fsync per line (INFERENCE, no benchmark). It also satisfies OBS-01's "recovered from the last line at startup": the first append after start does it. The existing 1-byte read-only open in `endsWithPartialLine` is folded into the same read-only open (one extra open per append is removed, not added).

**Torn tail and the chain.** A crash can leave fragment F (no `\n`). The next append writes `\n`, then its own line with `prev = sha256(F)` and `seq = lastParseableSeq + 1` (F consumes no `seq`; if F is a complete JSON line missing only its newline it parses and counts normally). Verifier rule below tolerates exactly this. R10 durability behaviour and the torn-tail tests keep passing.

**Reconciliation lines.** They are ordinary appends through `appendAudit`, so the chain covers them with no special case; the reconciler's own read of the file (`surplusByKey`) ignores the new fields. Change in `reconcile.ts`: `pairingKey` returns `cid:<correlationId>` when the line carries one, else the legacy `(tool, path, execSummary)` key; `Pending` and the appended line carry the admission's `correlationId`, so a reconciliation line pairs with its admission exactly and is joinable to the log. Legacy lines keep multiset pairing. Single-owner precondition unchanged (run before any dispatcher exists, as the lane's `runStartupMaintenance` does). Rotation: none (out of scope); a future rotation continues the chain by making the new file's first `prev` the old file's last line hash, and `verify` would need a `--continues-from` flag; the design leaves room, nothing more.

**Verifier** (`verifyAuditFile` in `src/audit/chain.ts`, streaming 64 KiB reads through an `O_RDONLY|O_NOFOLLOW|O_NONBLOCK` descriptor, regular files only, constant memory except one line and, with `--anchor`, 32 bytes per anchored line). Per physical line `i` (1-based) with `prevRaw` = sha256 of line `i-1`:
1. Parse JSON object (try/catch returning undefined, the pattern of `reconcile.parseLine`); `chained` = integer `seq` >= 1 and 64-hex `prev`.
2. Before the chain starts: not chained -> `legacyLines++` (or `unparsedLines` if not JSON). First chained line must have `seq 1` and `prev == (i == 1 ? GENESIS : prevRaw)`, else break `bad-chain-start` (this catches deletion of the head of a pristine chain).
3. In the chain: a parseable line with no chain fields -> break `unchained-line`. An unparseable line is recorded in `unparsedLines` (possible torn fragment) and checking continues. A chained line: `seq == lastSeq+1` else break `seq-gap` (seq greater: a line was removed) or `seq-regress` (seq <= lastSeq: reorder or duplicate); then `prev == prevRaw` else break `prev-mismatch` (previous line edited). Check seq before prev.
4. A trailing unterminated fragment at EOF is reported as `tornTail: true` (informational).
"First broken line" is the first line whose link fails, i.e. normally the line **after** the damaged one (edit of line j -> `prev-mismatch` at j+1; deletion of j -> `seq-gap` at j+1; swap of j and j+1 -> `seq-regress`/`seq-gap` at j; an edit of the `seq` or `prev` field of j itself -> at j). The output also lists `suspect: [line-1, line]`. The tests must assert this definition, not "the edited line".

**CLI** (new `src/cli/audit.ts`; `src/cli/main.ts` gains `"audit"` in `CLI_COMMANDS`, a `parseArgv` branch like `anchor` (`main.ts:61-78`), the USAGE string, and a `runAuditCommand` beside `runAnchorCommand` `:530-545`):

```
realm audit verify [--session <id> | --file <absolute path>] [--anchor <record.json>] [--head <seq>:<sha256>]
```
- No selector: every `<stateDir>/audit/*.jsonl` in name order. `--session` limits to one (the session id check is `isSessionId`, as `parseAnchorArgs`). `--file` verifies a copy (the session id is then the file stem if valid, else `file`).
- stdout: one JSON line `{"ok":bool,"files":[{"sessionId","ok","lines","chainedLines","legacyLines","chainStartLine","unparsedLines":[...],"tornTail","head":{"seq","lineSha256"},"broken":{"line","reason"}?, "anchor":{"ok","lineCount"}?}]}`. No host path appears in the output. stderr on failure: `realm audit verify: session <id>: line <n> does not chain to line <n-1> (<reason>)` plus one explanatory sentence.
- Exit codes (same convention as `realm anchor`, `CliResult.exitCode` is `0|1|2`): 0 every file verified; 1 any chain broken, anchor/head mismatch, unreadable or non-regular file, or no audit file to verify (nothing proven is not a pass); 2 usage.
- Reasons are a closed enum: `bad-chain-start`, `unchained-line`, `seq-gap`, `seq-regress`, `prev-mismatch`, `line-too-long`, `shorter-than-anchor`, `anchor-root-mismatch`, `shorter-than-head`, `head-mismatch`.

**Anchors, honestly.** Detects: an edit, deletion, insertion of a malformed line, or reorder of any line that has a successor and that the attacker did not repair by recomputing the rest of the chain; deletion of the head of a pristine chain; a torn write is distinguished from an edit only by whether the next line chains to it. Cannot detect (stated in `docs/policy-reference.md`/`runtime-decision.md` and printed nowhere as "secure"): (a) **truncation of the tail** (the remaining prefix is a valid chain), including deletion of the whole file or its replacement with an empty or fresh file; (b) anyone with write access to the file who recomputes every `prev` from the edit point forward (an unkeyed chain has no secret); (c) forged lines appended at the tail (a valid extension); (d) edits to the legacy prefix before the chain start; (e) that the recorded events are true or that `at` is accurate (a compromised daemon writes false lines the chain faithfully covers). A keyed HMAC does not fix (b) against a same-uid attacker who can read the key or the daemon's memory; rejected. The proposals' benefit text "prove ... not edited or truncated without a network" is therefore wrong for truncation; its own risk paragraph says to pair verify with the anchor. Both anchors below are cheap and offline to check:
- `--anchor <record.json>` takes the record `realm anchor` prints (`record` in its dry-run JSON, or the on-chain memo): `verify` checks `sessionId`, that the file has at least `lineCount` lines (else `shorter-than-anchor`: truncated since the anchor) and that `merkleRoot` of the first `lineCount` lines equals `rootSha256` (else `anchor-root-mismatch`). It does not fetch anything; trusting the record's time/origin means fetching the Solana transaction by hand. `anchor.ts` change: export the leaf hash and a `merkleRootOfLeaves` so the streaming verifier does not hold lines in memory; `merkleRoot` composes them (no behaviour change; `test/audit/anchor.test.ts` unchanged).
- `--head <seq>:<sha256>`: the operator copies the `head` printed by a previous verify to an off-host place (cron to a remote, a git repo, a ticket). Verify checks that line `seq` exists and its raw-line hash equals the value, so truncation below `seq` and any rewrite of lines up to `seq` are detected. Rejected as automatic: a head file next to the audit file (same trust domain, only catches accidents) and journald/syslog forwarding (needs a spawn or a host-specific socket; the daemon logs the head at startup/shutdown into `daemon.log` as an `audit.head` event, which helps the operator copy it but is the same trust domain).

### 3.2 OBS-02: logger, correlation ids, log file

**Modules (new directory `src/observe/`, AGENTS.md Layout gets a line).**
- `src/observe/logger.ts`: `LogLevel = "debug"|"info"|"warn"|"error"`; `LogSink { write(line: string): boolean }`; `Logger { debug|info|warn|error(event: string, fields?: LogFields): void; child(fields: LogFields): Logger }`; `createLogger({ sink, level, now })`; `nullLogger`. `LogFields` is `{ code?: ErrorCode; [key: string]: string | number | boolean | null | readonly (string|number)[] | undefined }` with the reserved keys `ts`, `level`, `event`, `code` excluded by type and, at runtime, written first so a field can never override them.
- Line format: `{"ts":"<ISO>","level":"info","event":"tool.result","code":"PATH_ESCAPE","correlationId":"...","sessionId":"daemon","tool":"write","outcome":"refused","durationMs":3}`. The first three keys are always `ts`, `level`, `event`, then `code` when present (typed `ErrorCode`: a non-catalogue code cannot be logged), then the rest. This fixed prefix is what `ensure.ts` matches, and `JSON.stringify` escapes `\n` and quotes inside values, so a field value can neither create a second line nor forge the prefix (test: a value containing `\n{"ts":...` stays inside one line).
- `src/observe/log-file.ts`: `createFileSink({ path, maxBytes, ... })`: opens `<stateDir>/daemon.log` itself with `O_WRONLY|O_APPEND|O_CREAT|O_NOFOLLOW`, 0600, `fchmod` 0600 (same hardening as the audit file), tracks size from `fstat` plus bytes written, and when `size + line > maxBytes` (default 4 MiB, a constant) renames `daemon.log` to `daemon.log.1` (replacing it) and reopens: at most two files. Both the daemon's inherited stdout/stderr (opened by the spawner) and the sink append to the same inode until a rotation; after a rotation the inherited descriptors follow the renamed file, so only non-logger output (a Node crash trace) lands in `daemon.log.1`. A refused symlink or open failure falls back to the stderr sink.
- `src/observe/ids.ts`: `newCorrelationId = () => randomUUID()` (node:crypto), injectable for tests.
- No dependency: `package.json` unchanged (check in the PR diff; `CONTRIBUTING.md` justification not needed). `process.env` is not read in `src/observe`: `src/daemon/main.ts` (an allowed edge) reads `REALM_LOG_LEVEL` (default `info`; invalid value -> `info` and one `warn`) and passes `logLevel` down. ### 3.3 OBS-03: metrics over the control socket

- New control method `metrics` (no params). `CONTROL_METHODS` gains it; `CONTROL_TIMEOUT_MS.metrics = 5_000`; `DaemonClient` gains `metrics(): Promise<MetricsSnapshot>` with a strict `isMetricsSnapshot` check (like `isDaemonStatus`); the daemon `switch` gains one case. The `status` reply is untouched (rejected "a field on status": polled, strictly validated, would grow every poll).
- `src/observe/metrics.ts`: pure in-memory registry (`createMetrics({ now, monotonicMs })`), no I/O, never throws (it is called from bus listeners). Snapshot type:

```ts
interface Timing { count: number; sumMs: number; maxMs: number; bucketUpperBoundsMs: readonly number[]; bucketCounts: readonly number[] } // bounds 5,25,100,500,2000,10000,60000,300000 + overflow
interface MetricsSnapshot {
  schema: 1; startedAt: string; now: string; uptimeMs: number;
  controlRequests: { method: ControlMethod; count: number; refused: number }[];
  toolCalls: { tool: ToolName | "unknown"; outcome: "done" | "refused" | "failed"; code?: ErrorCode; count: number }[];
  transitions: { from: State; to: State; count: number }[];
  timings: { attachMs: Timing; toolCallMs: Timing };   // attach = the whole `up` handler: probe + create + start
  healthProbeFailures: { code: ErrorCode; count: number }[];
  logLinesDropped: number;
}
```
- What is counted and where: `toolCalls` and `toolCallMs` around `handle.dispatcher.call` in the daemon `tool` case (`done`; `refused` with `outcome.code`; `failed` for a thrown defect); `attachMs` around the `up` case; `transitions` from the existing `controller.events.subscribe`; `healthProbeFailures` from the health hook; `controlRequests` in `dispatch`. All reset on daemon start (`startedAt` says since when); nothing is persisted.
- Memory bound: every key is drawn from a closed set (6 methods, 7 tool names including "unknown", done/refused/failed x 31 codes, 6x6 states, fixed histogram buckets); never keyed by path, session id or error text. Worst case about 250 toolCalls rows, under 30 KiB of reply against the 1 MiB cap. Phase 18 may add a per-session breakdown, capped to the number of live sessions.
- CLI: new `realm metrics` (`CLI_COMMANDS` gains `"metrics"`, one `deps.send` of `{ method: "metrics" }` with `CONTROL_TIMEOUT_MS.metrics`, `renderResult` to stdout like `status`). With no daemon: exit 1 with `REALM_NOT_ACTIVE` (there is nothing local to report, unlike `status`). Surfaces: **none** show metrics: MCP/ACP/Omp tools are the frozen six; a seventh tool changes `tools.schema.json`, both surfaces and the equivalence tests for no requirement. `realm status`/Omp status carry only the new code in `reason`. A Prometheus text format is not built (nothing can scrape a Unix socket without a bridge).
- Why no HTTP listener: `AGENTS.md` "There is no telemetry that sends data off the machine" and the control socket's authentication is filesystem mode (0700 dir, 0600 socket); a TCP port is reachable by other local users and by the sandbox's network namespace paths and would need its own authentication. Test (new, Linux, not Podman-gated): helper `listeningSocketsOf(pid)` reads `/proc/<pid>/fd` socket inodes and joins them against `/proc/net/tcp`, `tcp6`, `udp`, `udp6` (state `0A` for TCP LISTEN; any bound UDP) and `/proc/net/unix`; the unit test snapshots the test process's inode set, runs `startDaemon` with fakes, and asserts the only added listener is one unix socket at the control path. The same helper runs in the live suite against the real daemon pid (scenario 10 below) and asserts zero TCP/UDP listeners.

### 3.4 OBS-04: the gateway-or-driver-loss code

**Name and mapping (D5-approved addition; the name is mine to propose).** `OPENSHELL_GATEWAY_LOST`: prefix follows `OPENSHELL_START_FAILED` and `OPENSHELL_LABEL_AMBIGUOUS`; "LOST" says the session had a gateway and lost it (the probe path), unlike `ANDA_UNREACHABLE`. ## 5. Risks and edge cases

| Risk | Consequence | Test that catches it |
|---|---|---|
| Torn tail then append: new line chained to the fragment | false "broken chain" after every crash, or a glued line | log test: truncate the last line at several offsets (inside JSON, exactly before `\n`, complete line without `\n`); append; verifier reports ok with `unparsedLines` or none, `tornTail` false afterwards; seq continues |
| Verifier misses an edit/deletion/reorder | integrity claim false | verify tests for edit of line j (breaks at j+1, `prev-mismatch`), delete j (`seq-gap` at j+1), swap j/j+1 (`seq-regress`), delete the first lines (`bad-chain-start`), insert a forged unchained JSON line (`unchained-line`), edit the last line (documented as undetected: assert ok, so the limit is pinned) |
| Truncated tail passes | false assurance | test: truncate to line k; plain verify ok; with `--anchor` (lineCount > k) `shorter-than-anchor`; with `--head` `shorter-than-head` |
| Legacy file migration | chain breaks on first append, or old files rejected | test: a file of 5 legacy lines, append, verify ok with `legacyLines 5`, `chainStartLine 6`, first `prev` = sha256(line 5) |
| Reconciliation lines outside the chain | `verify` fails after Phase 14 reconcile | test: plant an admission, run `reconcileAuditLogs`, verify ok; run again, 0 appended; reconciliation line carries the admission's `correlationId` |
| Pairing key swap breaks legacy pairing | duplicate reconciliation lines | reconcile tests: id-keyed and legacy-keyed admissions in one file |
| Huge line / hostile tail | unbounded read in head recovery | test: a 5 MiB last line: append refuses nothing new (line is old) and chain restarts per rule without allocating more than the cap; append of an oversize line is `AUDIT_WRITE_FAILED` |
| Two processes append (violates single owner) | forked chain (`seq` repeats) | verify test with a duplicated `seq` -> `seq-regress` |
| Logger throws inside a bus listener | state transition throws out of `controller.transition` | test: sink that throws; transition completes, `droppedLines` is 1 |
| Log injection | forged log line or forged `daemon.failed` | test: field containing newline and a fake prefix stays one line; `daemonStartFailureSince` ignores it |
| Secret in a log field | leak | redaction test over field values and keys |
| Log growth / rotation hides a start failure | unbounded file, or `DAEMON_START_TIMEOUT` instead of the real code | file-sink rotation test (cap 1 KiB: two files, 0600, no data lost between); `start-failure.test.ts` case: size < offset reads from 0 |
| Metrics unbounded | memory | test: 10k calls with random paths/tool junk produce the same row count; unknown tool name -> `"unknown"` |
| Metrics method changes the channel contract | stale tests / client strictness | update `channel.test.ts:120-126`, add client and daemon tests; `isMetricsSnapshot` rejects extra/missing fields |
| Network listener appears | policy breach | `/proc` listener test (unit with fakes; live against the real daemon) |
| Gateway classification wrong way round | gateway loss reads as crash loop, or runner loss reads as gateway loss | supervisor tests: runner exited + gateway down -> `OPENSHELL_GATEWAY_LOST`; runner exited + gateway up -> `AGENTOS_CRASH_LOOP`; probe rejects + gateway down -> lost; stop during classification returns false; a held supervisor keeps its code; driver tests with a fake runner scripting `status` exit 0/1/reject/hang |
| `openshell status` hangs | health tick stuck | bounded by `GATEWAY_STATUS_TIMEOUT_MS`; test with a hanging runner |
| Existing hold tests assume one code | false failures | run `agentos-supervisor`, `controller-health`, `stale-container`, `daemon-health`, `session-execution` suites; the fake defaults to gateway up so they keep `AGENTOS_CRASH_LOOP` |
| Coverage floors (Phase 13: `src/fs`, `src/core`, `src/tools`) and dead-export report | `dispatch.ts`/`errors.ts` edits drop coverage | tests above exercise every new branch in `dispatch.ts` |
| Live gateway stop affects every other live run on the account | other scenarios' runner children die | account-wide live lock; restore in cleanup even on failure |

Data-loss/secret/deadlock/orphan summary: the chain adds a read before each write but no lock and no new await, so no deadlock; a failed head read fails the admission closed (`AUDIT_WRITE_FAILED`, the tool does not run), consistent with S-21; the log sink and metrics are never on a path that can block a tool call; rotation renames only inside the 0700 state dir; the verifier opens files read-only.

## Tasks

### T1. One definition of the Merkle leaf and node hashes
- Files: `src/audit/anchor.ts`
- Action: export from `anchor.ts` a function that returns an incremental leaf hash (SHA-256 with the `0x00` prefix already fed in), a `nodeHash(left, right)` function (SHA-256 of `0x01 || left || right`), and `merkleRootOfLeaves(leaves)` that folds leaf hashes into the root with the existing promote-unpaired rule. `merkleRoot(lines)` composes them: leaf-hash each line, then `merkleRootOfLeaves`. No behaviour change.
- Done when: `test/audit/anchor.test.ts` passes without edits. Its independent helpers (around lines 52-64) and its `merkleRoot` cases (around lines 255-260) pin the prefixes and the tree shape.
- Verify: `npm run build && node --test dist/test/audit/anchor.test.js`

### T2. The streaming verifier imports the hashes
- Files: `src/audit/chain.ts`
- Action: delete the chain module's `LEAF_PREFIX`, `NODE_PREFIX`, `newLeafHash` and `nodeHash`, and import the leaf-hash and node-hash functions from `anchor.ts`. Keep `StreamingMerkleRoot`, `scanAnchoredPrefix` and `checkAnchor` as they are, apart from the import. `anchor.ts` must not import `chain.ts`; check for an import cycle before finishing.
- Done when: `src/audit/chain.ts` contains no prefix constant; the test "every prefix of a 40-line file verifies" in `test/audit/chain.test.ts` and the anchor tests still pass.
- Verify: `npm run build && node --test dist/test/audit/chain.test.js dist/test/audit/anchor.test.js`

### T3. Oversize and over-bound tail fail closed, with tests
- Files: `src/audit/log.ts`, `test/audit/log.test.ts`, `test/audit/chain.test.ts`
- Action: add these two tests and make them pass. Their names must contain the words shown, because the verify command selects them by name.
  (a) "an oversize append fails with AUDIT_WRITE_FAILED and leaves the file unchanged": an `appendAudit` whose serialized line is larger than `AUDIT_LINE_MAX_BYTES` throws `AUDIT_WRITE_FAILED`, and the file's bytes are identical before and after.
  (b) "an over-bound tail fails closed with AUDIT_WRITE_FAILED and leaves the file unchanged": a session file whose last physical line is longer than `AUDIT_LINE_MAX_BYTES`; `appendAudit` throws `AUDIT_WRITE_FAILED` and the file's bytes are identical afterwards. The head read must not hash a partial tail.
  Check the mapping from the chain-bound error to `AUDIT_WRITE_FAILED` in `src/audit/log.ts` (`writeAuditLine` and its caller). If the mapping is missing, fix it in `log.ts`; that is the only production change this plan allows, and only for that mapping. Report it in the completion notes.
- Done when: both tests exist, run, and pass, and no existing test is deleted or has its expectation changed.
- Verify: `npm run build && node --test --test-name-pattern "oversize|over-bound" dist/test/audit/log.test.js dist/test/audit/chain.test.js`

# Phase 16 plan 02 (unit O2): actual Omp consumer controls

Context: `16-CONTEXT.md`, section "Decisions added 2026-11-01". O2 starts after O1 has landed and the parent has recorded its verification. O2 changes test support and the Omp guard suite only. It changes no product code.

## Scope and ownership

O2 owns the five files above and nothing else. It shares wave 2 with O4 (`16-04-PLAN.md`), which owns `src/omp/plugin.ts`, `src/omp/extension.ts` and their tests. The two sets are disjoint.

Hard limits:
- No live run. The Omp guard suite is gated by `REALM_LIVE_OMP=1`. Executing it here is not allowed, so every verification command below runs it in its skip path only.
- HARN-03 network repair is NOT authorized. Do not edit any proxy, DNS or network-trace code. The zero-offender exit condition stays as recorded.
- Native C4 CREATE is kept as it was supplied. Its explicit native patch variant is `PI_EDIT_VARIANT=patch`, and its target does not exist before the call. Do not add a snapshot tag or a Realm `read` that imitates a native read.
- No provider credential, token or account value may appear in any capture, log or fixture.

## Tasks

### T1. Scripted provider exposes the tool results of its next request
- Files: `test/support/scripted-provider.ts`
- Action: add a bounded helper that records, per request, the tool-result messages the provider received, keyed by tool call id. It exposes the text and any digest or byte metadata Omp sent back. It keeps the existing C1 to C3 and C4 behaviour and the existing chunk sequence. It does not change the request handling.
- Verify: `npm run build && env -u REALM_LIVE_OMP node --test dist/test/integration/omp-live-helpers.test.js`

### T2. Hermetic tests for the new helpers
- Files: `test/integration/omp-live-helpers.test.ts`
- Action: add tests that feed recorded request bodies to the T1 helper and assert the extracted tool-result text, and that a body with no tool-result message yields an empty list, not an error. These tests run without Omp, without the opt-in and without a provider.
- Verify: `npm run build && env -u REALM_LIVE_OMP node --test dist/test/integration/omp-live-helpers.test.js`

### T3. Guard suite: callable tools across a mode change, and model `bash` denial
- Files: `test/integration/omp-guard.test.ts`, `test/support/omp-rpc.ts`
- Action: add one gated case that starts advisory, changes the policy to fail-closed through the daemon's own status and the existing reattach path, and asserts on the offered tool names and on the model-issued `bash` result. The `bash` result must contain `POLICY_DENIED`. The case must fail if the result contains Omp's "Tool bash not found" instead. The offered schemas and results are captured only through the existing bounded RPC facilities in `omp-rpc.ts`. Assert a registered `write` then `read` with a required `maxBytes`, and check the provider's next request for the text and digest. This case is gated like the others and skips without the opt-in.
- Verify: `npm run build && env -u REALM_LIVE_OMP node --test dist/test/integration/omp-guard.test.js`. The expected result is exit 0 with the case skipped, and the skip reason names `REALM_LIVE_OMP`.

### T4. C4 native CREATE assertions, unchanged setup
- Files: `test/integration/omp-guard.test.ts`
- Action: keep the existing C4 case as supplied, using `PI_EDIT_VARIANT=patch` and a nonexistent target. Its assertions become: the advisory notice shows; the bytes exist on the host at the target; the provider's next request carries the successful result. Remove any dependency on a snapshot tag from a Realm read.
- Verify: `npm run build && env -u REALM_LIVE_OMP node --test dist/test/integration/omp-guard.test.js`

### T5. Bounded capture of offered schemas, with no credentials
- Files: `test/support/omp-profile.ts`, `test/support/omp-rpc.ts`
- Action: record the offered tool schemas and results through the existing bounded facilities only. Strip any `authorization`, `api-key`, `token` or `secret` header or field before a capture is kept. Cap the size of each capture using the existing limits.
- Verify: `npm run build && env -u REALM_LIVE_OMP node --test dist/test/integration/omp-live-helpers.test.js`

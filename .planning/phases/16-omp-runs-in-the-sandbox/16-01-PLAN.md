### T1. Keep fail-closed `bash` callable so the guard can refuse it with a catalogue code
- Files: `src/omp/tools.ts`
- Action: in `failClosedToolNames`, add `bash` to the set of names fail-closed keeps active. It is not added to `PASS_THROUGH_HOST_TOOLS`, so the tool_call backstop refuses it with `POLICY_DENIED`. Keep removing `edit`, `eval`, `ast_edit`, `lsp`, `debug`, `task` and `web_search`. Rewrite the JSDoc above the function to say that fail-closed blocks host `bash` through the guard, that the guard is not process containment, and why removal alone (which yields Omp's native "Tool bash not found") does not satisfy the catalogue requirement.
- Done when: `failClosedToolNames(["read","bash","edit","write","grep"])` returns `bash`, `read`, `write`, `grep` in that set and excludes `edit`.
- Verify: the suite command above.

### T2. Guard path for model-issued `bash` carries the catalogue code
- Files: `src/omp/plugin.ts`
- Action: confirm `guardHostToolCall` returns `{ block: true, reason: "POLICY_DENIED" }` for `bash` in fail-closed when the status reads (any state), when the status cannot be read, and when no mode is known yet. Confirm advisory passes `bash`. Do not treat Omp's "Tool bash not found" text as the catalogue code anywhere. Add tests to `test/omp/plugin.test.ts` that call `guardHostToolCall` directly for each of the four cases.
- Done when: those four assertions exist and pass; the existing backstop test for a non-read-only tool still passes.
- Verify: the suite command above.

### T3. Fence every awaited setter and keep the owed-tool bookkeeping truthful
- Files: `src/omp/plugin.ts`
- Action: in `applyHostMode`, after each `await pi.setActiveTools(...)` and its readback, do the following. (a) Set `tools.removed` from the actual readback result before returning, whether or not the owning attempt is still current, so a later owner plans from what Omp really holds. (b) Keep the existing rule that `session.mode` is published only after success. (c) Keep the existing rule that a failed readback throws `POLICY_DENIED`. A setter that completes after its owner was superseded, timed out, shut down or replaced by a new session must not cancel itself. It leaves the set reconciled by the next current owner, which plans from actual state on its next status read (the poll bounds this to `STATUS_POLL_MS`).
- Done when: tests in `test/omp/plugin.test.ts` cover a setter that resolves after its attach budget expired, after `session_shutdown`, and after a new `session_start`; in each case the next session's first status read leaves the active set equal to the plan and `tools.removed` equal to the owed list.
- Verify: the suite command above.

### T4. Restore only what the extension owns; never revive what the user disabled
- Files: `src/omp/tools.ts`, `test/omp/tools.test.ts`
- Action: change `planHostTools` so fail-closed `wanted` is `(active ∩ keep) ∪ (registered Realm tool names)`, and no longer adds every allowlisted name. A read-only built-in the user disabled manually therefore stays disabled, while the five Realm tools are always put back (P16 d). Advisory keeps `active ∪ (owed ∩ registered)`, which already restores only owed names; keep that rule and add the case where an owed name has disappeared from the registry, which must be dropped from `owed` and not restored.
- Done when: unit tests in `test/omp/tools.test.ts` cover manual deactivation of `glob` in fail-closed (stays off), a dropped Realm tool in fail-closed (restored), and an owed tool that disappeared (not restored, dropped from owed).
- Verify: the suite command above.

### T5. Registered read results: content and metadata for every wire shape
- Files: `src/omp/tools.ts`, `test/omp/tools.test.ts`
- Action: read the registered `read` result renderer. Make it correct for: a `Uint8Array` payload, a serialized Node Buffer (`{ "type": "Buffer", "data": [...] }`), an empty payload, a payload the daemon marked truncated, and invalid UTF-8 bytes. For each, the model-visible text must be the decoded UTF-8 text (invalid sequences replaced, as the decoder defines), and `details` must carry the SHA-256 of the full bytes, the byte count and the truncation flag. Realm truncation describes daemon read completeness only. Write the tests against rendered output, not against source strings. Do not change the schema or the frozen input shape. If the current code already satisfies a case, the test documents it; if not, fix the renderer.
- Done when: `test/omp/tools.test.ts` asserts the rendered text and the details for all five shapes.
- Verify: the suite command above.

### T6. Lifecycle matrix: drift, mode cycles, deferred setters, disappearance
- Files: `test/omp/plugin.test.ts` (tests only; `src/omp/plugin.ts` changes come from T2 and T3)
- Action: add tests that drive the real plugin with the existing `FakePi`, `FakeCtx` and `FakeDaemon` doubles. Cases: (a) active-tool drift in the same mode is restored on the next guarded call; (b) fail-closed then advisory then fail-closed, asserting the active set and the published mode after each step; (c) a failed restore followed by an unavailable daemon leaves the set as the plan says and a host `edit` follows the last published mode; (d) a deferred setter that outlives its timeout, then a retry, then shutdown, then a new session; (e) a registered tool that disappears from `getAllTools()` is not restored; (f) a user-deactivated tool stays deactivated across a mode cycle; (g) a refused setter never publishes the new mode.
- Done when: each case is a separate `void test(...)` with an assertion on the active set, the published mode and the `tools.removed` list.
- Verify: the suite command above.

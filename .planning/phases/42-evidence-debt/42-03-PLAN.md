## Trust Boundaries

| Boundary | Risk |
| --- | --- |
| Window to the account that owns the production stack | A hermetic test touches the real home or the production state, or the run overlaps a live run |
| Evidence to the repository | A path, a token or a long hash is committed; a skip is written as a pass |
| Harness copy to the account | The run silently depends on the harness checkout, runs as root, or has a gate variable open |
| Test fix to the finding | A failure is hidden by weakening an assertion or adding a root special case |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-42-15 | Information disclosure | A token, a key or a host path reaches the page or the evidence | high | mitigate | Only counts, statuses and test names are copied; Task 4 step G searches the evidence; the page test scans for the token shape, long hex runs and host paths |
| T-42-16 | Tampering | A root-only fixture is hidden by a skip or a weaker assertion | medium | mitigate | Task 5 keeps the assertion's meaning and records the earlier failure with its date; the parent reviews the diff of every fixed test file |
| T-42-17 | Denial of service | The run collides with a live run under the same account, or hangs | medium | mitigate | The shared lock; a 90-minute stop; the account's processes compared before and after |

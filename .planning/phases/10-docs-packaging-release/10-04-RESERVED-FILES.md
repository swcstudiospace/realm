## Decisions
- **Merge method for pull request 6: a merge commit.** Squash would reduce the 0.2.0 notes to one line (simulated: the squash subject only) and strand the SHAs these records cite; a merge commit lists each commit (127 entries at the branch head before this change (the rehearsal, which added one commit, listed 128; this change's own commits add a few more), grouped). AGENTS.md now states the rule: a multi-commit pull request of meaningful Conventional Commits lands with a merge commit, a single-commit pull request may squash. rf4 recommended squash; its own numbers contradict that for this branch.
- **No build-provenance attestation in this change.** rf3 proposed `actions/attest` in the release job. It needs `id-token: write`, which every step of the job would then hold, including the steps that run dependency code, and it cannot run before the first release on main. The safe design is a separate unprivileged build job and a privileged publish job. That job split also closes the remaining channel v1 found (build code and the push step share a user, so a planted hook or `$GITHUB_PATH` entry could reach the push step); the push step now pins git's configuration and hooks, which narrows it, and the split is a recorded follow-up.
- **Pages dispatch.** The release job dispatches Pages exactly when the tip of main is a release commit (`chore(release): v...`): that content passed verify and was released. Two earlier formulations were wrong. The rehearsal's (published, or skip) broke the recovery path in which a rerun repairs a release and then plans as superseded. The next one (published, repaired, or skip) still skipped Pages when the release succeeded but `gh workflow run` failed, because the rerun finds the release, repairs nothing and plans as superseded (main already holds its own `[skip ci]` release commit); Greptile found that in review of this change. The tip-of-main rule covers a publish, a repair and a retry of a failed dispatch, and never deploys a newer push whose verify has not finished. It was exercised against a bare remote with a stub `gh` in five tip states (ordinary commit, release commit, the same retried, a newer unreleased push, that push released).

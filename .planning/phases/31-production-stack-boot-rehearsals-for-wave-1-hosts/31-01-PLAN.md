It returns an object with `baseUrl` (`http://127.0.0.1:PORT/v1`), `requests()` (a copy of the records so far: method, path, whether an Authorization header was present as a boolean, and the peer address; never a header value, never a body) and `close()` (resolves when the server is closed and idle sockets are destroyed).

    - `writeFakeMcpServer(dir, logFile)`: writes `dir/fake-mcp-server.mjs`, a Node script (builtins only) that speaks line-delimited JSON-RPC on stdio: it answers `initialize` (echoing the requested protocol version, capabilities with tools, a server name), answers `server/discover` with a result a modern client accepts, answers `tools/list` with the six `REALM_TOOL_NAMES` (each with an empty-object input schema and a description that carries the literal marker `FAKE-DESCRIPTION-MARKER`), ignores notifications, and answers any other request with an empty result. At start it appends one JSON line to `logFile`: its own pid, its argv after the script name, the sorted NAMES of its environment variables (never values) and the basename of its working directory. It appends `EOF` when stdin ends and exits 0 (or with the code named by an optional `--exit-on-eof N` argument, used by hermetic test 5). It returns the script path.
    - `writeWireRecorder(dir, options)`: writes `dir/realm` (mode 0755, a POSIX sh script) and `dir/wire-tee.mjs`. The shell script is exactly: a shebang, then `exec` of the Node path, the tee script, the log path and the target argv prefix (each shell-quoted with the same quoting as `realmShim` in `host-live.ts`), then `"$@"`. `options` holds the Node path, the target argv prefix (for production `[node, cliPath]`; for the validator session `[node, fakeServerPath]`) and the log file. The tee script spawns the first target element with the rest of the prefix plus the received arguments (stdio piped, stderr inherited), forwards the host's stdin to the child byte for byte and the child's stdout to the host byte for byte, and only reads a line-buffered copy of each direction to write the log (it never alters the forwarded bytes). It appends one JSON line per complete message to the log file with `fs.appendFileSync`: `{ dir, kind, method?, id?, toolNames? }` where `dir` is `host-to-realm` or `realm-to-host`, `kind` is `request`, `notification`, `response` or `other` (an unparseable line), `method` is the JSON-RPC method (never params), `id` the request id, and `toolNames` only on a response whose request was `tools/list` (matched by id): the array of `name` strings of `result.tools`. It ends the child's stdin when the host's stdin ends, exits with the child's exit code (or 128 plus the signal number), and forwards SIGTERM and SIGINT to the child. Returns the shim path.
    - `readWireLog(file)`: parses the log (a missing file is an empty list; a malformed line is skipped, never thrown) and returns the events.
    - `wireSummary(events)`: returns `{ hostMethods }` (the methods the host sent, in order, each once at first appearance), `{ toolNames }` (the names from the first `tools/list` response, sorted, or an empty list) and `{ answered }` (true when a `tools/list` response with a non-empty `toolNames` was logged).
    - `runHostUntil(bin, args, env, cwd, options)`: like `runHost` in `host-live.ts` (read lines 556 to 670 first and reuse its process-group helpers by exporting them from `host-live.ts`; do not copy them) with `options.ready` (an async predicate), `options.timeoutMs` and `options.pollMs`. It starts the host as the leader of its own process group, polls `ready` every `pollMs`, and when `ready` answers true, or the host exits on its own, or `timeoutMs` passes, it signals the group (SIGTERM, then SIGKILL after 2 s), sweeps the group with SIGKILL at the end, and returns the `HostRunResult` fields plus `endedBy` (`ready`, `exit` or `timeout`). It never rejects.

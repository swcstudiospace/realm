<objective>
Add MCP tool annotations (`title`, `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) to every Realm MCP tool, emitted identically in both protocol eras, and prove them: pinned per tool against the tool contract, honest against the dispatcher's real behaviour, correct on the wire, and mutation-resistant.

Purpose: a host that chooses to use the hints can skip a prompt for `read`, `list` and `status` and prompt for `exec`, `write` and `retry`, without Realm's containment depending on that choice (29-CONTEXT D-29-01).
Output: one type, one frozen table, one pin module with a checker, one new test file, two extended test files.
Non-goals: no `check:mcp` change and no docs (plan 29-02); no change to enforcement, the frozen schema, `ToolOutcome`, result shapes, error codes, ACP, or policy; no dynamic annotations; no `outputSchema`, `icons` or `_meta` on descriptors; no CHANGELOG or version edit; no host is run.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Risk |
| --- | --- |
| Realm descriptors to the host's consent logic | An understated hint lets a host skip a prompt for a mutating tool; an overstated one only costs an extra prompt |
| Hint to enforcement | A future reader treats a hint as a guard and drops a check |
| Descriptor text to the model | Injected text through a field the workload can influence |

## STRIDE Threat Register

| ID | Category | Threat | Severity | Disposition | Mitigation |
| --- | --- | --- | --- | --- | --- |
| T-29-01 | Tampering | `readOnlyHint: true` on a tool that mutates | high | mitigate | Behaviour tests (workspace bytes unchanged for read, list, status; the read-only set is a literal list); contract-derived rules (write non-read-only and destructive; exec destructive); the mutation set flips every hint of every tool |
| T-29-02 | Elevation of privilege | A hint is used as a security control and a check is removed | high | mitigate | No `src` code reads a hint (grep in the Task 1 done criterion); the comment states the rule; the hostile-argument wire test proves a read-only-hinted tool still refuses a path escape and `exec` shell form is still refused; docs in plan 29-02 |
| T-29-03 | Spoofing | A rug pull: the table changes after the host approved the server | medium | mitigate | The table is a frozen constant; the wire tests pin the exact objects in both eras; no code path edits a descriptor at run time |
| T-29-04 | Tampering | Injected text through `title` | medium | mitigate | Fixed ASCII literals; the checker enforces the charset and the equality of the two titles; no workload data reaches a descriptor |
| T-29-05 | Information disclosure | Annotations leak a path, policy or secret | low | accept | Six fixed literals identical for every project; `exec`'s open-world value is the same for every policy |
| T-29-06 | Denial of service | A client rejects the extra fields and fails the whole tool list | medium | mitigate | Only specification fields in the shape the three served revisions define (29-CONTEXT E-02); both eras tested on the wire; the built-server gate and the optional host connectivity recheck are plan 29-02 |
| T-29-07 | Repudiation | The hint table and the real behaviour drift apart over time | medium | mitigate | Behaviour tests exercise each read-only tool and write idempotence; adding a read-only tool without a behaviour test fails the literal-list test; the tool-name set is pinned to the frozen schema |
| T-29-08 | Elevation of privilege | A hostile sibling server shadows Realm's tools | medium | accept | Host duty; annotations cannot help (the host decides per server); recorded in docs (plan 29-02); unchanged from the Anda research |

Accepted residuals: a host may ignore the hints or trust them from a server it should not; Realm's guarantee is the containment, not the hint.

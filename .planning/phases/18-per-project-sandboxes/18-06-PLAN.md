# Phase 18 plan 06 (unit H1): the daemon's per-project handles and selected dispatch

## Reconciliation against the code (read-only, 2026-11-02)

- `src/daemon/daemon.ts` `startDaemon` builds one handle with `buildDaemonHandle({ ...options, … })`, binds `config.workspaceRoot` once (`boundRoot`, line 238), and holds one health timer, one startup notice, one `upId` and one metrics object. `dispatch` routes `status`, `up`, `tool`, `down`, `metrics` and `doctor` to that single handle. The stop path `stop(id, socket, reason)` (lines 423 to 452) closes the handle, answers the down on its socket, closes the server and removes the socket file. `runStartupMaintenance` attributes orphan-sweep lines to `options.sessionId` (line 836); plan 06 replaces that input, and plan 09 implements the attribution.
- `StartedDaemon` (line 181) exposes `handle: RealmHandle`. Its consumers at HEAD are the tests listed in T2, and `src/daemon/main.ts`.
- `buildDaemonHandle` (line 194) and `defaultExec` use the single `config.workspaceRoot`. `supervisorsOver(driver)` already keys supervisors by session id. `pinnedWorkspaceRoot` appears in `BuildDaemonHandleOptions` (line 114) and reaches `StartDaemonOptions` through the extension; plan 04 removed the one spread of it in `defaultExec`.
- `src/realm/compose.ts` `createRealmHandle` builds a `LifecycleController`, a `ToolDispatcher`, one `LockTable` and binds `config.workspaceRoot` under the policy. It is already per-handle, and `RealmHandle.close()` delegates to the controller stop path; it is unchanged.
- `src/daemon/main.ts`: the constant `SESSION_ID` (value `"daemon"`) is passed to `start` as `sessionId`, in the same call as the single `pinnedWorkspaceRoot: roots.workspaceRoot` property. `requestDown` sends `down` to the own socket for both the signal and the failure paths (`awaitStop`, lines 241 to 295). `emitAuditHead(stateDir, writeStderr)` is called at start (line 110) and at shutdown (line 118), and reads `audit/daemon.jsonl` through `readAuditHead`.
- `up` at HEAD: the first `await` is `probeResult = await probe()` in `src/daemon/daemon.ts`, which runs before `handle.controller.create`. Admission therefore moves before the probe (T1 and T2).
- `LifecycleController.destroy()` stops the container, releases the session's locks, deletes the record (`src/lifecycle/controller.ts`). `stop()` keeps the record. Session down uses `destroy()`; daemon shutdown uses `stop()`, as contract C5 states.
- A record names its project: `SessionRecord.workspaceRoot` (`src/contract/validate.ts`), so the collision check of step (3) reads it through `store.load(id)`.
- `INITIAL_REASON` ("no workspace") is exported from `src/core/state-machine.ts`, so the daemon can build the unbound snapshot without touching the controller.
- Handles are built inside `up`, so a test cannot patch a handle's controller before the session exists. A seam for the builder is therefore added (`buildHandle`, T1).

### T1. Sessions, selection resolution and admission in one place
- Files: `src/daemon/sessions.ts`, `src/daemon/daemon.ts`
- Action: create `src/daemon/sessions.ts` exporting:
  - `interface SessionEntry { readonly sessionId: string; readonly pinned: PinnedRoot; readonly handle: RealmHandle; readonly health: SessionHealth }`.
  - `class SessionRegistry` with `get`, `set`, `delete`, `values` and `size` over a `Map` keyed by session id.
  - `resolveSelection(input: { selection: ControlSelection; policy: Policy; ceiling: PinnedRoot; registry: SessionRegistry }): { readonly sessionId: string; readonly pinned: PinnedRoot; readonly entry: SessionEntry | null }`, which runs exactly these steps. (a) If `registry.get(selection.sessionId)` exists, call `verifyPinnedAt(entry.pinned, selection.workspaceRoot)`; a mismatch throws `POLICY_DENIED` (rename or swap refused); return the entry. (b) Otherwise call `bindWorkspaceUnderPolicy(policy.workspaceRoots, selection.workspaceRoot)` (`POLICY_DENIED` outside every policy root), then require `isInsideRoot(ceiling, pinned.realPath)` (`POLICY_DENIED` outside the configured workspace root; equality accepted), derive `id = sessionIdOfWorkspace(pinned.realPath)`, and require `id === selection.sessionId` (`SCHEMA_INVALID` otherwise); return it with `entry: null`.
  - `reserveAdmission(ledger: AdmissionLedger, sessionId: string): boolean`, which reads `ledger.isCommitted(sessionId)`, calls `ledger.reserve(sessionId)`, and returns true when the id was not committed before the call. It is the only path to `reserve`.
  - `settleFailedCreate(ledger, sessionId, handle)`: when the handle's controller is not unbound, or a record still names a container, call `ledger.markUnproven(sessionId)`; otherwise call `ledger.release(sessionId)`.
  - `class SessionHealth`: the existing `healthTimer`, `healthTick`, `startHealthLoop`, `stopHealthLoop` and the lifecycle subscription of `startDaemon`, moved into a class constructed per entry from its handle and disposed by `dispose()` on session down. Its ticks and log lines carry `sessionId` in place of `upId`.
  - The unbound snapshot for `status` and `down` is built with `{ state: "unbound", reason: INITIAL_REASON, lastTransitionAt }` using the clock.

### T2. Selected dispatch, session down, daemon stop and signal shutdown
- Files: `src/daemon/daemon.ts`, `src/daemon/main.ts`, `test/daemon/daemon.test.ts`, `test/daemon/main.test.ts`, `test/daemon/daemon-health.test.ts`, `test/daemon/e2e.test.ts`, `test/integration/omp-guard.test.ts`, `test/support/realm-daemon-fixture.ts`, `test/surfaces/daemon-equivalence.test.ts`
- Action: in `daemon.ts`, `dispatch` takes the request's selection (already validated by `parseControlSelection` in `dispatchLine`; the validator runs for every method except `doctor`, which allows absence). `up`, in this order: (1) refuse `REALM_STOPPING` while stopping; (2) `resolveSelection` (binding and containment, no runtime I/O); (3) if no entry exists, refuse `SANDBOX_NAME_IN_USE` when `store.load(id)` names another canonical path (`SessionRecord.workspaceRoot`) or `readWorkspaceEntry` names another path (both synchronous); (4) `const fresh = reserveAdmission(ledger, id)`, synchronous and before the first `await`; (5) `await probe()`: a thrown error or a failed probe releases the reservation when `fresh` (no container exists, so the release is proven) and replies with the refusal or the probe's code; (6) if an entry exists, `entry.handle.controller.create(pinned.realPath)` unchanged; otherwise build the handle with `buildHandle({ ...the start options, sessionId: id, runtimeInput: { ...runtimeInput, workspaceRoot: pinned.realPath } })`, then `writeWorkspaceEntry(stateDir, pinned, id)`, `registry.set`, and `await controller.create(realPath)`. A failure in (6) after the handle exists calls `settleFailedCreate` and rethrows; a failure of `buildHandle` or `writeWorkspaceEntry` before `create` releases the reservation when `fresh`. On a successful create of a new session, call `onAuditHead(id)`. Reply `{ ...statusOf(snapshot), boundRoot: pinned.realPath, sessionId: id }`. The order is the reason for step (4): C7 requires admission before the first `await` of `up`, and the probe is that await; the outside-root and collision refusals stay before any reservation, so they never take a slot.

  `status`: a selection outside the roots is refused by step (2) of `resolveSelection`; an entry gives the snapshot of its handle with `boundRoot` and `sessionId`; no entry gives the unbound snapshot with the same two fields, the bound root being the selection's realpath. `tool`: no entry gives `REALM_NOT_ACTIVE`; otherwise the existing call path against `entry.handle.dispatcher`, with the log fields carrying `sessionId`. `metrics`: the selection is resolved (refusals as above) and the daemon-wide snapshot is returned. `doctor`: with a selection, the agent-OS reading of that entry's supervisor; without one, `{ bound: false }` (C4).

  `down` (C5): (1) the selection is resolved (refusals as above); (2) no entry: reply the unbound snapshot with `boundRoot` and `sessionId` (idempotent, CORE-06); (3) entry: `await entry.handle.controller.destroy()`; on failure call `settleFailedCreate` (the session stays registered and its slot stays committed) and refuse with the thrown code; on success call `removeWorkspaceEntry(stateDir, id)`, `ledger.release(id)`, `registry.delete(id)`, `entry.health.dispose()`, `onAuditHead(id)`, and reply the unbound snapshot with `boundRoot` and `sessionId`. In both successful branches, when `registry.size === 0` the daemon stop is armed after the reply has been written, so the reply always goes out first. This is C5's rule: a down that leaves no live session stops the daemon, including a down that names no live session, as HEAD's `down` always did; a down while another session is live never stops it.

  Shutdown: HEAD's `stop(id, socket, reason)` (lines 423 to 452) is kept for the zero-session down, which answers the down on its socket and then resolves `done`. A new in-process `stopAll()` calls `controller.stop()` on every entry, disposes each entry's health, closes the server, removes the socket file, and resolves `done`; it writes no reply. `StartedDaemon.stop(): Promise<void>` is `stopAll()`. Add `StartedDaemon.session(sessionId: string): SessionEntry | undefined`, which reads the registry. `StartedDaemon` loses `handle`. Add `onAuditHead?: (sessionId: string) => void` to `StartDaemonOptions`, invoked on each session create (after success) and on each session destroy (after the record and the registry entry are removed). The daemon reads no audit file; the caller does.

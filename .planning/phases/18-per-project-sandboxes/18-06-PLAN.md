# Phase 18 plan 06 (unit H1): the daemon's per-project handles and selected dispatch

## Reconciliation against the code (read-only, 2026-11-02)

- `src/daemon/daemon.ts` `startDaemon` builds one handle with `buildDaemonHandle({ ...options, … })`, binds `config.workspaceRoot` once (`boundRoot`, line 238), and holds one health timer, one startup notice, one `upId` and one metrics object. `dispatch` routes `status`, `up`, `tool`, `down`, `metrics` and `doctor` to that single handle. The stop path `stop(id, socket, reason)` (lines 423 to 452) closes the handle, answers the down on its socket, closes the server and removes the socket file. `runStartupMaintenance` attributes orphan-sweep lines to `options.sessionId` (line 836); plan 06 replaces that input, and plan 09 implements the attribution.
- `StartedDaemon` (line 181) exposes `handle: RealmHandle`. Its consumers at HEAD are the tests listed in T2, and `src/daemon/main.ts`.
- `buildDaemonHandle` (line 194) and `defaultExec` use the single `config.workspaceRoot`. `supervisorsOver(driver)` already keys supervisors by session id. `pinnedWorkspaceRoot` appears in `BuildDaemonHandleOptions` (line 114) and reaches `StartDaemonOptions` through the extension; plan 04b removed the one spread of it in `defaultExec`.
- `src/realm/compose.ts` `createRealmHandle` builds a `LifecycleController`, a `ToolDispatcher`, one `LockTable` and binds `config.workspaceRoot` under the policy. It is already per-handle, and `RealmHandle.close()` delegates to the controller stop path; it is unchanged.
- `src/daemon/main.ts`: the constant `SESSION_ID` (value `"daemon"`) is passed to `start` as `sessionId`, in the same call as the single `pinnedWorkspaceRoot: roots.workspaceRoot` property. `requestDown` sends `down` to the own socket for both the signal and the failure paths (`awaitStop`, lines 241 to 295). `emitAuditHead(stateDir, writeStderr)` is called at start (line 110) and at shutdown (line 118), and reads `audit/daemon.jsonl` through `readAuditHead`.
- `up` at HEAD: the first `await` is `probeResult = await probe()` in `src/daemon/daemon.ts`, which runs before `handle.controller.create`. Admission therefore moves before the probe (T1 and T2).
- `LifecycleController.destroy()` stops the container, releases the session's locks, deletes the record (`src/lifecycle/controller.ts`). `stop()` keeps the record. Session down uses `destroy()`; daemon shutdown uses `stop()`, as contract C5 states.
- A record names its project: `SessionRecord.workspaceRoot` (`src/contract/validate.ts`), so the collision check of step (3) reads it through `store.load(id)`.
- `INITIAL_REASON` ("no workspace") is exported from `src/core/state-machine.ts`, so the daemon can build the unbound snapshot without touching the controller.
- Handles are built inside `up`, so a test cannot patch a handle's controller before the session exists. A seam for the builder is therefore added (`buildHandle`, T1).

(a) If `registry.get(selection.sessionId)` exists, call `verifyPinnedAt(entry.pinned, selection.workspaceRoot)` and require `sessionIdOfWorkspace(entry.pinned.realPath) === selection.sessionId`, otherwise `POLICY_DENIED`; a mismatch throws `POLICY_DENIED` (rename or swap refused); return the entry. The lock is released after the reply is computed. `status`, `tool` and `metrics` take no lock. A waiter is a queue entry with its own timer. `withSessionLock(sessionId, fn, waitMs)` removes a queued entry whose timer fires before the grant: the entry leaves the queue, its promise rejects with `TOOL_TIMEOUT` (retryable), and its `fn` never runs. The timer is cleared at the grant. Two bounds are named in `src/daemon/sessions.ts`. They are derived from `src/daemon/channel.ts` and do not depend on the policy budget: `UP_LOCK_WAIT_MS = CONTROL_TIMEOUT_MS.up - 2 * probeTimeoutMs - DAEMON_REPLY_ALLOWANCE_MS` (215 s with the defaults), and `DOWN_LOCK_WAIT_MS = CONTROL_TIMEOUT_MS.down - DAEMON_REPLY_ALLOWANCE_MS` (40 s), where `DAEMON_REPLY_ALLOWANCE_MS = 5_000`. A request is a waiter when the lock is not free on arrival. Only a waiter applies the post-grant checks in T2.
  - Why the lock suffices: under it, steps (2) to (6) of `up` run only after every earlier request for the same id has finished, so the registry read in step (2) is current and no request relies on another request's reservation. `fresh` is true only when this request's `reserveAdmission` created the reservation.
  - `reserveAdmission(ledger: AdmissionLedger, sessionId: string): boolean`, which reads `ledger.isCommitted(sessionId)`, calls `ledger.reserve(sessionId)`, and returns true when the id was not committed before the call. It is the only path to `reserve`.
  - `settleFailedCreate(ledger, registry, stateDir, sessionId, handle, fresh)`: when `fresh` is true (this request holds the reservation) and the handle's controller is not unbound, or a session record exists for the id, call `ledger.markUnproven(sessionId)` and keep the registry entry; when `fresh` is true otherwise (no container exists), call `ledger.release(sessionId)`, `registry.delete(sessionId)` and `removeWorkspaceEntry(stateDir, sessionId)`, because step (6) calls `registry.set` before `create`, and a surviving entry would keep `registry.size` above zero so the stop arming in `down` never fires; when `fresh` is false, change nothing in the ledger. A failed create whose slot is kept as unproven holds that slot until a `down` removes the session, so with `maxSessions` 2 one failed create can hold a slot; `status` for that session reports the error snapshot with its reason.
  - `class SessionHealth`: the existing `healthTimer`, `healthTick`, `startHealthLoop`, `stopHealthLoop` and the lifecycle subscription of `startDaemon`, moved into a class constructed per entry from its handle and disposed by `dispose()` on session down. Its ticks and log lines carry `sessionId` in place of `upId`.
  - The unbound snapshot for `status` and `down` is built with `{ state: "unbound", reason: INITIAL_REASON, lastTransitionAt }` using the clock.

### T2. Selected dispatch, session down, daemon stop and signal shutdown
- Files: `src/daemon/daemon.ts`, `src/daemon/main.ts`, `test/daemon/daemon.test.ts`, `test/daemon/main.test.ts`, `test/daemon/daemon-health.test.ts`, `test/daemon/e2e.test.ts`, `test/daemon/realm-daemon-fixture.test.ts`, `test/integration/omp-guard.test.ts`, `test/support/realm-daemon-fixture.ts`, `test/surfaces/daemon-equivalence.test.ts`
- Selection for `up`, before step (2) of the `up` action below: dispatch canonicalizes the requested path with `bindRoot` and builds `selection = { workspaceRoot: realPath, sessionId: sessionIdOfWorkspace(realPath) }`, which `resolveSelection` consumes. The wire never carries a `sessionId` for `up` (C4 in `18-01-PLAN.md` line 75): the daemon derives the id here.
- Action: in `daemon.ts`, `dispatch` takes the request's selection (already validated by `parseControlSelection` in `dispatchLine`; the validator runs for every method except `doctor`, which allows absence). `up`, in this order: (1) refuse `REALM_STOPPING` while `downRequested` is set; (2) `resolveSelection` (binding and containment, no runtime I/O); (3) if no entry exists, refuse `SANDBOX_NAME_IN_USE` when `store.load(id)` names another canonical path (`SessionRecord.workspaceRoot`) or `readWorkspaceEntry` names another path (both synchronous); (4) `const fresh = reserveAdmission(ledger, id)`, synchronous and before the probe's first `await`; (5) `await probe()`: a thrown error or a failed probe releases the reservation when `fresh` (the release is safe because any container created for the id is counted through its session record, which the controller writes before the container exists; controller.ts persists before createContainer, so the release does not let the count exceed the bound) and replies with the refusal or the probe's code; (5a) after a successful probe and before step (6), re-check `downRequested`, which `stop`, `stopAll` and the arming in `down` set; if it is set, release the reservation when `fresh` (no container exists for the id, so the release is proven) and refuse with `REALM_STOPPING`; (6) if the entry that `resolveSelection` returned in step (2) exists (it is current under the lock), call `entry.handle.controller.create(pinned.realPath)` unchanged on that entry; otherwise build the handle with `buildHandle({ ...the start options, sessionId: id, runtimeInput: { ...runtimeInput, workspaceRoot: pinned.realPath } })`, then `writeWorkspaceEntry(stateDir, pinned, id)`, `registry.set`, and `await controller.create(realPath)`. A failure in (6) after the handle exists calls `settleFailedCreate(ledger, registry, stateDir, id, handle, fresh)`; a `create` that throws rethrows after that call, and a `create` that returns an error snapshot for a RealmError other than `REALM_STOPPING` (the `enterError` rule in `controller.ts`) is settled the same way and that snapshot is the reply; a failure of `buildHandle` or `writeWorkspaceEntry` before `create` releases the reservation when `fresh`. On a successful create of a new session, call `onAuditHead(id)`. Reply `{ ...statusOf(snapshot), boundRoot: pinned.realPath, sessionId: id }`. The order is the reason for step (4): C7 requires admission before the probe's first `await`, and the probe is that await; the outside-root and collision refusals stay before any reservation, so they never take a slot.

  Post-grant checks (waiters only; a request that found the lock free applies none). `isLiveState(state)` is exported from `src/lifecycle/controller.ts` as the predicate at line 200 (`connecting`, `active` or `degraded`), and `create` uses it, so the daemon and the controller agree. Let `remaining = CONTROL_TIMEOUT_MS[method] - (now - dispatchedAt) - DAEMON_REPLY_ALLOWANCE_MS`. For `up`: if the entry is live, run the probe (step (5)) and reply the snapshot, with no reservation, because the id is already committed. If the entry is absent or not live and `remaining < 2 * probeTimeoutMs + policy.startupBudgetMs`, refuse with `STARTUP_BUDGET_EXCEEDED` (retryable) before step (4). For `down`: if the entry is absent, reply the unbound snapshot and call no destroy; if the entry is present and `remaining < TEARDOWN_TIMEOUT_MS + DAEMON_REPLY_ALLOWANCE_MS`, refuse with `TOOL_TIMEOUT` before destroy, applying nothing. A request that found the lock free skips these checks, so a policy budget above the client bound never refuses an uncontended `up`.

  `status`: a selection outside the roots is refused by step (b) of `resolveSelection`; an entry gives the snapshot of its handle with `boundRoot` and `sessionId`; no entry gives the unbound snapshot with the same two fields, the bound root being the selection's realpath. `tool`: resolveSelection first (its refusals as in step (a) and (b)); then no entry gives `REALM_NOT_ACTIVE`; otherwise the existing call path against `entry.handle.dispatcher`, with the log fields carrying `sessionId`. `metrics`: the selection is resolved (refusals as above) and the daemon-wide snapshot is returned. `doctor`: with a selection, the agent-OS reading of that entry's supervisor; without one, `{ bound: false }` (C4). `doctor` takes no lock, and with a selection its reading is advisory: it may run while an `up` or `down` of that session is in progress and reports the supervisor as it stands at that moment.

  `down` (C5): (0) the wait for the lock is bounded by `DOWN_LOCK_WAIT_MS` (40 s); a waiter whose wait expires applies nothing and replies `TOOL_TIMEOUT` (retryable). A destroy is bounded by `TEARDOWN_TIMEOUT_MS` (30 s, `src/lifecycle/controller.ts`), and the post-grant check in T2 starts a destroy only when the remaining budget covers that bound. (1) the selection is resolved (refusals as above); (2) no entry: reply the unbound snapshot with `boundRoot` and `sessionId` (idempotent, CORE-06); (3) entry: `await entry.handle.controller.destroy()`. The slot these ledger calls act on is the one the session owns from its `up`, not a reservation of this down, so the calls do not depend on `fresh`, and each runs only when the destroy outcome requires it: on failure call `ledger.markUnproven(id)` (the session stays registered and its slot stays committed) and refuse with the thrown code; on success call `removeWorkspaceEntry(stateDir, id)`, `ledger.release(id)`, `registry.delete(id)`, `entry.health.dispose()`, `onAuditHead(id)`, and reply the unbound snapshot with `boundRoot` and `sessionId`. In both successful branches, when `registry.size === 0` and `ledger.reservedCount() === 0`, the decision to arm is taken synchronously: `downRequested` is set before the lock is released, and after the reply has been written, `stop(null, undefined)` runs directly. The arming never calls `shutdown`, whose guard (`src/daemon/daemon.ts`, lines 457 to 462) returns early when `downRequested` is set, so the reply still goes out first. This is C5's rule: a down that leaves no live session stops the daemon, including a down that names no live session, as HEAD's `down` always did; a down while another session is live or admitting never stops it.

  Shutdown: HEAD's `stop(id, socket, reason)` (lines 423 to 452) is kept for the zero-session down, which answers the down on its socket and then resolves `done`. A new in-process `stopAll()` sets the stopping flag, as `stop` does, then calls `controller.stop()` on every entry, disposes each entry's health, closes the server, removes the socket file, and resolves `done`; it writes no reply. `StartedDaemon.stop(): Promise<void>` is `stopAll()`. Add `StartedDaemon.session(sessionId: string): SessionEntry | undefined`, which reads the registry. Add `StartedDaemon.committedCount(): number` and `StartedDaemon.isCommitted(sessionId: string): boolean`, each delegating to the admission ledger (`AdmissionLedger.committedCount` and `isCommitted`, plan 03); done-when cases (g) and (k) read them. The `startedWith` fake in `test/daemon/main.test.ts` (T2, below) also returns `committedCount: () => 0` and `isCommitted: () => false`, since `StartedDaemon` now has those members. `StartedDaemon` loses `handle`. Add `onAuditHead?: (sessionId: string) => void` to `StartDaemonOptions`, invoked on each session create (after success) and on each session destroy (after the record and the registry entry are removed).

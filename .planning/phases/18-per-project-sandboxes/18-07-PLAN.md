## Tasks

### T1. Canonical identity and pin regressions in the root module
- Files: `test/fs/root.test.ts`
- Action: add these cases, using real temporary directories created under `mkdtempSync(join(tmpdir(), ...))` and realpath-normalized as the existing cases do. (a) A symlink to a project directory: `bindWorkspaceUnderPolicy([root], link)` returns the same `realPath` and `dev`/`ino` as binding the project directly, and `sessionIdOfWorkspace` of both `realPath` values is equal. (b) A project nested inside another project under the same root: both bind; their `realPath` values differ; their session ids differ. (c) A sibling directory whose name is the root name followed by `2` is refused with `POLICY_DENIED` by `bindWorkspaceUnderPolicy([root], sibling)`. (d) The configured root itself is accepted (equality). (e) After binding a project, rename the project directory and call `verifyPinnedAt(pinned, originalPath)`: it throws `POLICY_DENIED`. (f) The rename-aside method of `test/fs/root.test.ts` (lines 87 to 93), applied to a bound project: rename the project directory to a sibling name, create a new directory at its original path, then call `verifyPinnedAt(pinned, originalPath)`: it throws `POLICY_DENIED`. The original is renamed, never removed, so its inode stays allocated and the new directory cannot reuse its device and inode; a remove-then-create sequence is not used, because it can reuse the inode and make the case flaky. (g) A request that is not absolute is refused with `POLICY_DENIED`. Each case asserts the returned values or the thrown code.
- Done when: the cases (a) to (g) above are present in `test/fs/root.test.ts` and pass with `node --test dist/test/fs/root.test.js`; the existing cases are not changed.
- Verify: `npm run build && node --test dist/test/fs/root.test.js`

### T2. Two projects give two distinct sandbox bindings
- Files: `test/runtime/sandbox-binding.test.ts`
- Action: add cases to the existing file. Build two project roots `A` and `B` as real directories under one temporary root `R`, with a secret root and a sandbox state root as the file already does. (a) For sandbox name `realm-<sessionIdOfWorkspace(A)>`, `sandboxBindingOf({ workspaceRoot: A, stateRoot, secretRoot }, nameA)` gives `workspaceRoot === A`; for `B` and `nameB` it gives `workspaceRoot === B`; the three paths `stateDir`, `channelDir` differ between the two bindings. (b) `sandboxNameOfSession(sessionIdOfWorkspace(A)).length <= 19` and the same for `B`. (c) A sandbox name for a different session id maps to a different `stateDir` under the same state root, and the binding of a name with a path separator throws (the existing check). Use `sessionIdOfWorkspace` and `sandboxNameOfSession` from `src/session/paths.ts`.
- Done when: the cases pass with `node --test dist/test/runtime/sandbox-binding.test.js`; the existing binding cases are unchanged.
- Verify: `npm run build && node --test dist/test/runtime/sandbox-binding.test.js`

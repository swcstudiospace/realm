# Phase 18 plan 10 (unit O1): the Omp surface checks the selection and follows a switch

## Reconciliation against the code (read-only, 2026-11-02)

- `src/omp/extension.ts`: the closure `attachDaemon(workspaceRoot)` in the default export derives its selection with `selectionOf(workspaceRoot)` and calls `daemonAnswers(connectDaemon, selection)`, `connectDaemon(socketPath, selection)` and `client.up()`. Plan 05 made those changes. On refusal it calls `client.status()` and keeps the client only when `status.boundRoot` equals the realpath of the workspace. It does not yet compare a session id; this plan adds that check.
- `src/omp/plugin.ts`: the attach is started in `session_start` with `options.attachDaemon(ctx.cwd)`; status is read with `client.status()` in the status paths; tool calls go through `client.call(call)`. The header comment lists the verified host names as `session_start`, `session_shutdown` and `tool_call`. The plugin has no `session_switch` handler today.
- `docs/integration/omp.md`, row S2b: `session_switch` fired once, with a new session id and the same restricted set, and `session_start` did not fire again. That row is the evidence for T2.
- `test/omp/plugin.test.ts` and `test/omp/extension.test.ts` drive the plugin through `attachDaemon` fakes.

## Scope and ownership

Owns the four files listed. The derivation of the selection and the call sites in `src/omp/extension.ts` are plan 05's. This plan adds the session-id check of a refused `up` and the switch handler. The plugin keeps its state machine and its timers. Contract item C4 of `docs/integration/runtime-decision.md` binds the attach.

Owner rules: no live step, no build or test run inside the replan, no git command, no commit. The host's `session_switch` payload is not assumed: where the host supplies no working directory on a switch, the plugin keeps the attachment and the record says so (T2 below).

## Tasks

### T1. attachDaemon checks the session id of a refused up
- Files: `src/omp/extension.ts`, `test/omp/extension.test.ts`
- Action: in `attachDaemon(workspaceRoot)`, reuse the selection that plan 05 derives (`selectionOf(workspaceRoot)`, which rejects a missing path with `POLICY_DENIED` before any socket is opened). On a refused `up`, `client.status()` must answer with `status.sessionId === selection.sessionId` and `status.boundRoot === selection.workspaceRoot`; only then is the client kept and the refusal returned as `{ client, refusal }`. Otherwise the client is closed, the refusal is rethrown, and no later request is sent. A status reply without `sessionId` (an older daemon) fails the same way.
- Done when: `test/omp/extension.test.ts` asserts through the fake `connectDaemon` and the fake daemon status: (a) an attach for directory D sends `up` with D's realpath, and the client's `status` and `call` requests carry `sessionId` equal to `sessionIdOfWorkspace(realpath(D))`; (b) a refused up whose status names the same session and root returns `{ client, refusal }`; (c) a refused up whose status names a different session id closes the client and rethrows the refusal, and no later request is sent; (d) a directory that does not exist rejects with `POLICY_DENIED` before any socket is opened; (e) a daemon status without `sessionId` (an older daemon) closes the client and rethrows.
- Verify: `npm run build && node --test dist/test/omp/extension.test.js`

### T2. Switching the working directory re-attaches; the plugin's state is unchanged
- Files: `src/omp/plugin.ts`, `test/omp/plugin.test.ts`, `test/omp/extension.test.ts`
- Action: register a handler for `session_switch` next to the existing `session_start` registration, using the same `pi.on` form. The handler reads the working directory from the context it is given. If the context carries a working directory that differs from the directory the current attachment was made for, the handler ends the current session the way `session_start` does (`endSession()` followed by the same attach path) with the new directory. If the context carries no working directory, or the directory is unchanged, the handler keeps the attachment and does nothing. Record in a comment, with the evidence reference `docs/integration/omp.md`, row S2b, that the host's `session_switch` payload is read defensively and that a payload without a directory keeps the attachment. In the header comment of `src/omp/plugin.ts`, replace the verified-names line that lists `session_start`, `session_shutdown`, and `tool_call` with the same list plus `session_switch`, citing that S2b row. Store the attached directory on the session object when `session_start` attaches; do not add any other state. The status item, the tool-set refresh and the timers are not changed.
  Types and fake host. `OmpExtensionApi` in `src/omp/plugin.ts` (lines 85 to 88) gains the overload `on(event: "session_switch", handler: (_event: unknown, ctx: OmpSessionContext) => void): void;` after the `session_start` overload. `registerRealmPlugin` registers `session_switch` next to `session_start` (`pi.on("session_start", …)` at line 657), so the registration order is `session_start`, `session_switch`, `session_shutdown`, `tool_call`. `FakePi` in `test/omp/plugin.test.ts` (lines 241 to 260, `implements OmpExtensionApi`) gains the same overload, a `switchHandlers` array, and a `session_switch` branch placed before its catch-all, which would otherwise push the handler into `toolCallHandlers`. `recordingPi` in `test/omp/extension.test.ts` (lines 371 to 390) records every event name, so `REGISTERED_EVENTS` (line 399) becomes `["session_start", "session_switch", "session_shutdown", "tool_call"]`, the list that both `deepEqual` assertions at lines 406 and 416 compare against.
- Done when: `test/omp/plugin.test.ts` asserts through the fake host: (a) a `session_start` with cwd A and then a `session_switch` with cwd B re-attaches with B (the fake `attachDaemon` records B) and the previous client is closed; (b) a `session_switch` with cwd A (unchanged) does not call `attachDaemon` again; (c) a `session_switch` whose context has no cwd does not call `attachDaemon` again; (d) the existing `session_start` tests pass unchanged.
- Verify: `npm run build && node --test dist/test/omp/plugin.test.js dist/test/omp/extension.test.js`

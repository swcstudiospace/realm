### T2. Surface tests: CLI, MCP, ACP and Omp on two projects
- Files: `test/surfaces/daemon-equivalence.test.ts`, `test/mcp/server.test.ts`, `test/acp/agent.test.ts`
- Action: in `daemon-equivalence.test.ts`, use two projects A and B under one fixture root and daemon. For each project, compare the selected `status` and `up` replies from the CLI `sendRequest` path, the MCP client path (`connectFor(project)`), and the Omp client calls (`selectionOf(project)`, `connectDaemon(socketPath, selection)`, `up()`), including actual re-up from unbound for each path, not only idempotent up. Check that active A and B replies differ only by `sessionId` and `boundRoot`. Before each re-up, send `down` via the CLI path with the selected project's `selectionOf(project)`; assert its reply and subsequent CLI, MCP-client and Omp-client status agree on the selected project's unbound state, identity and root, while the other project's active status remains unchanged. After each re-up assert the selected project's active reply and status agree across paths and the peer remains unchanged. Exercise both A and B. Do not add a destructive MCP or Omp down capability or claim that either issues down.
- Action, TS7022 correction: at the reported line 316, explicitly annotate the conditional result as `const up: unknown`, retaining the existing CLI/MCP/Omp branch calls and comparisons; `result()` returns `Promise<unknown>`, so this avoids implicit inference without an assertion or a change in runtime behavior.
- Action, audit isolation: in `test/mcp/server.test.ts`, add a server whose dispatcher is A's client and another whose dispatcher is B's client; each answers a `tool` call and writes its audit line to its own project's file, and neither file contains the other's line. In `test/acp/agent.test.ts`, add the same two-project case for the ACP agent. Use the fixture from T1 and temporary project directories under one root. Each assertion checks a reply value or an audit line.
- Done when: after the independent plan review and authorization gate, the complete verification below passes; the lifecycle assertions cover both project directions and every specified path and state, and each MCP and ACP case asserts its own session's reply and audit file and the absence of the peer's audit line. No existing case expectation is changed except where it asserted a selection-free request. MCP/Omp-issued down remains explicitly unverified.
- Verify: `npm run build && node --test dist/test/surfaces/daemon-equivalence.test.js dist/test/mcp/server.test.js dist/test/acp/agent.test.js`

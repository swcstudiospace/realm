## Tasks

### T1. The two-project scenario (authored)
- Files: `test/integration/production-driver.test.ts`
- Action: add one scenario, gated by the existing `productionSkipReason` so the default run skips it. Build two project directories `A` and `B` under one configured root `R` (`R` is the config's `workspaceRoot` and the policy's only root). Write the same file name with different bytes in each (`marker.txt`). Steps, each asserted: (1) `realm up --workspace A` exits 0 and `realm status --workspace A` reports `active` with `sessionId === sessionIdOfWorkspace(realpath(A))`; (2) `realm up --workspace B` exits 0 and reports `active` with B's id, and the two ids differ; (3) the inspected containers for `sandboxNameOfSession(idA)` and `sandboxNameOfSession(idB)` each carry one mount whose source is the realpath of their own project and whose destination is `/workspace`; the two sources differ; (4) inside A's sandbox, `cat /workspace/marker.txt` returns A's bytes and inside B's sandbox it returns B's bytes; (5) a file `only-in-a.txt` written inside A's sandbox is absent in B's sandbox and absent on the host under B; (6) `realm down --workspace A` exits 0; `realm status --workspace B` still reports `active`; B's sandbox still answers a `cat` of its marker; A's sandbox is gone; A's record file and registry entry are gone, and A's audit file `audit/<idA>.jsonl` is kept; (7) cleanup: `realm down --workspace B`, then the residue wait for the two derived names only. Use the existing `realmCli`, `sandboxExec` and `waitForNoResidue` helpers; add a `down` helper that takes the workspace. Every name asserted is computed with `sandboxNameOfSession(sessionIdOfWorkspace(realpath(...)))`.
- Done when: the scenario is in `test/integration/production-driver.test.ts` with a `test(...)` name beginning "production live: two projects", its skip gate is the existing one, and `npm run typecheck` exits 0. No run of the scenario is performed.
- Verify: `npm run typecheck`

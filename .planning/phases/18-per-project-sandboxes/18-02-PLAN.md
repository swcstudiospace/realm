# Phase 18 plan 02 (unit I1): canonical identity and the workspace registry

## Reconciliation against the code (read-only, 2026-11-02)

- `src/session/paths.ts` has `SESSION_ID_PATTERN`, `isSessionId`, `recordFileName`, `sessionsDirOf` and `controlSocketPath`. It has no id derivation from a workspace. The fixed id `daemon` is set in `src/daemon/main.ts`, not here.
- `src/fs/root.ts` already binds a canonical path (`bindRoot`) and verifies a pin (`verifyPinnedAt`). This plan uses both and changes neither.
- `src/fs/atomic-write.ts` (`atomicWriteFile`, `observeSha256`, `syncDirectory`) is the atomic-write primitive the record store uses (`src/session/store.ts`). The registry reuses it.
- No registry exists. No code writes `<stateDir>/workspaces/`.

## Scope and ownership

Owns `src/session/paths.ts`, the new `src/session/workspace-registry.ts`, and their two tests. No other unit in its wave owns these files. The driver consumer is plan 04; the daemon consumer is plan 06. This plan adds no daemon, driver or CLI behaviour.

Standing rules: contract items C1 and C3 of `docs/integration/runtime-decision.md`, both engineering decisions recorded in plan 01, bind every task. No live step, no build or test run inside the replan, no git command, no commit.

## Tasks

### T1. One id function from a canonical workspace path
- Files: `src/session/paths.ts`, `test/session/paths.test.ts` (created by this plan; the file does not exist at HEAD)
- Action: add to `src/session/paths.ts` the exported constants `WORKSPACE_SESSION_PREFIX = "p"` and `WORKSPACE_ID_HEX_LENGTH = 12`, and the exported function `sessionIdOfWorkspace(canonicalPath: string): string`. The function requires an absolute path that is already normalized (`path.posix.normalize(p) === p` and no trailing separator unless the path is `/`); otherwise it throws `SCHEMA_INVALID`. It returns `"p" + sha256(utf8(canonicalPath)).hex.slice(0, 12)`. Use `node:crypto` `createHash("sha256")`. Export `sandboxNameOfSession(sessionId: string): string` that returns `` `realm-${sessionId}` `` and throws `SCHEMA_INVALID` unless `isSessionId` holds and the result is at most 19 characters. Do not import from `src/runtime/openshell.ts` (that would invert the dependency); the constant `19` is restated with a comment naming `GATEWAY_SANDBOX_NAME_MAX_LENGTH` and the test asserts both values agree. Keep the existing exports unchanged.
- Done when: `test/session/paths.test.ts` contains these cases and they pass: two strings that are the same directory after realpath give one id (use a real temporary directory and a symlink to it, canonicalizing with `realpathSync`); two different directories give different ids; the id matches `isSessionId` and has length 13; `sandboxNameOfSession(sessionIdOfWorkspace("/a"))` has length at most 19; a relative path, a path with a trailing separator and a path with `..` each throw `SCHEMA_INVALID`; the constant `19` equals `GATEWAY_SANDBOX_NAME_MAX_LENGTH` imported from `src/runtime/openshell.ts` in the test only.
- Verify: `npm run build && node --test dist/test/session/paths.test.js`

### T2. The workspace registry: write, read and verify one entry
- Files: `src/session/workspace-registry.ts`, `test/session/workspace-registry.test.ts` (both created by this plan)
- Action: create `src/session/workspace-registry.ts` with these exports. `workspaceRegistryDirOf(stateDir: string): string` returns `join(stateDir, "workspaces")`. `interface WorkspaceEntry { readonly schema: 1; readonly sessionId: string; readonly workspaceRoot: string; readonly dev: number; readonly ino: number }`. `writeWorkspaceEntry(stateDir: string, pinned: PinnedRoot, sessionId: string): WorkspaceEntry` checks `sessionId === sessionIdOfWorkspace(pinned.realPath)` (else `SCHEMA_INVALID`), creates the directory with mode 0700 (`mkdirSync` recursive, then `bindRoot` and a check that its mode is 0700 and it is not a symbolic link), and writes the JSON with `atomicWriteFile` at mode 0600 with `expectedPriorSha256` from `observeSha256` as `SessionStore.save` does. `readWorkspaceEntry(stateDir: string, sessionId: string): WorkspaceEntry | null` opens the file with `openCanonical` (as `SessionStore.load` does), parses it, and refuses with `SCHEMA_INVALID` any entry whose `schema` is not 1, whose `sessionId` differs from the requested id, or whose `sessionIdOfWorkspace(workspaceRoot)` differs from `sessionId`. `removeWorkspaceEntry(stateDir: string, sessionId: string): void` removes the file if present and syncs the directory. `listWorkspaceEntryIds(stateDir: string): readonly string[]` returns sorted ids of regular `.json` files whose stems pass `isSessionId`; an absent directory lists nothing. `verifyWorkspaceEntry(entry: WorkspaceEntry): PinnedRoot` builds `new PinnedRoot(entry.workspaceRoot, entry.dev, entry.ino)` and calls `verifyPinnedAt` on it with `entry.workspaceRoot`; a mismatch throws `POLICY_DENIED` from `verifyPinnedAt`, unchanged. Import `PinnedRoot`, `bindRoot` and `verifyPinnedAt` from `src/fs/root.ts`; `atomicWriteFile`, `observeSha256` from `src/fs/atomic-write.ts`; `openCanonical` from `src/fs/canonicalize.ts`. Do not add a dependency.
- Done when: `test/session/workspace-registry.test.ts` passes these cases, each asserting the observable result: a written entry reads back equal to what was written, its file mode is 0600 and its directory mode is 0700; an entry written for one directory and renamed to another session's file name is refused with `SCHEMA_INVALID`; an entry whose `workspaceRoot` was moved after writing is refused with `POLICY_DENIED` by `verifyWorkspaceEntry`; a directory replaced at the same path is refused by `verifyWorkspaceEntry`, where the replacement uses the rename-aside method of `test/fs/root.test.ts` (rename the entry's directory to a sibling name, then create a new directory at the path), so the original inode stays allocated and the new directory cannot reuse its device and inode; a symbolic link planted at the entry file name is refused with a catalogue code and no file outside the directory is read; `removeWorkspaceEntry` on an absent id is a no-op; `listWorkspaceEntryIds` ignores a non-`.json` file and a file whose stem fails `isSessionId`.
- Verify: `npm run build && node --test dist/test/session/workspace-registry.test.js dist/test/session/paths.test.js`

# Phase 18 plan 04 (unit D1): driver mount from the trusted registry, and the session's own bind

## Reconciliation against the code (read-only, 2026-11-02)

- `src/runtime/driver/compute-driver.ts`: `ComputeDriverConfig.workspaceRoot` is documented as the pinned workspace root, the mount for every sandbox. `planCreate` builds `sandboxBindingOf({ workspaceRoot: config.workspaceRoot, … })` (line 905) and returns `spec.workspaceDir` from the binding (line 919). `createSandbox` refuses while the process-global `rootReserved` is set (line 370) and sets it before the first await (line 373); `pinnedRootHeld` (line 734) refuses while any live container holds `config.workspaceRoot` (`holdsPinnedRoot`, line 1034). `buildSandbox` asserts the pinned root with `assertPinnedWorkspaceRoot(this.config.workspaceRoot)` at its `create.workspace` stage (line 404). `ensureWorkspace` (line 611) also asserts `config.workspaceRoot` with `assertPinnedWorkspaceRoot`; that is the ceiling check, which stays true after this change, so the line is kept. `deleteWorkspace` is always refused and is unchanged.
- The in-flight reservation is keyed by sandbox name only, and the liveness check (`pinnedRootHeld`) reads containers only. Under C1 of plan 01 a directory has one sandbox name, and under C3 the registry check refuses a second name whose entry points at a directory it does not name. So two names on one workspace cannot both pass: the name key refuses a second create under the same name while the first is in flight, and the per-workspace container check refuses a second name once a container is live. This plan implements the per-resolved-workspace liveness check and keeps the name key; it adds no second reservation key, because a key that no valid entry can reach would be dead state.
- `src/runtime/driver/main.ts` derives `roots` with `runtimeRootsOf` through `rootsFromConfig` (which returns the value unchanged) and passes `workspaceRoot: roots.workspaceRoot` to the driver config (line 95). `RuntimeRoots` has no `stateDir` at HEAD; T1 adds it. The daemon and the driver read the same `config.json`, so both derive the same `stateDir` (`src/runtime/host-paths.ts`, `readHostRuntime`, and `loadRuntimeConfig`).
- `src/runtime/session-execution.ts`: `SessionExecutionOptions.pinnedWorkspaceRoot`, `requirePinnedWorkspaceRoot`, and `requireSameDirectory(req.workspaceRoot, pinnedWorkspaceRoot)`, the create-time refusal this plan removes; `sandboxBindingOf({ workspaceRoot: pinnedWorkspaceRoot, … })` in `create`. The verifier `verifyOrRemove` compares the inspect with the binding (`src/runtime/hardening.ts`, `isMountOf`).
- The driver's refusal check names (`src/runtime/driver/refusal.ts`) already include `create.workspace`; no new check name is needed.
- The existing tests exercise one pinned root (`test/runtime/driver/compute-driver.test.ts`, `test/runtime/session-execution.test.ts`, fakes in `test/runtime/driver/fakes.ts`). `test/runtime/driver/socket-server.test.ts` builds its driver through `driverConfig()` (fakes.ts) and creates no sandbox, so it needs no change.

## Scope and ownership

Owns the files listed. Its signature changes are `ComputeDriverConfig.stateDir` (required), `RuntimeRoots.stateDir`, and the removal of `SessionExecutionOptions.pinnedWorkspaceRoot`. Every consumer of each is migrated in this plan: the one conditional spread of the removed option in `src/daemon/daemon.ts` (`defaultExec`), every test fixture that builds a driver config, every test that compares a whole `runtimeRootsOf` result, and every test that creates a sandbox. The consumers of `pinnedWorkspaceRoot` are, closed: `src/runtime/session-execution.ts`, `src/daemon/daemon.ts` (`BuildDaemonHandleOptions`, `StartDaemonOptions`, `defaultExec`), `src/daemon/main.ts`, `test/daemon/main.test.ts`, `test/runtime/session-execution.test.ts` and `test/runtime/openshell-routing.test.ts`. This plan owns the first, the `defaultExec` spread, and the two runtime tests; plan 06 owns the daemon option, the `main.ts` pass and `main.test.ts`. The mount authority is contract C3, and the single-owner count is C7 and C10 of `docs/integration/runtime-decision.md`.

Owner rules: no live step (no `REALM_LIVE_*`, no container, no gateway), no build or test run inside the replan, no git command, no commit. The driver never imports the admission ledger.

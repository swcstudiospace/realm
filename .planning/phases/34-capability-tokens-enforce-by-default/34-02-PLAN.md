<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Policy file to daemon | The posture (enforce or off) is decided by one document the operator owns |
| Daemon to key file | The daemon creates the key file at start under the state directory |
| Client to control socket | A tokenless or stale client is refused; a labelled client attaches |

## STRIDE Threat Register

| ID | Category | Component | Severity | Disposition | Mitigation |
| --- | --- | --- | --- | --- | --- |
| T-34-05 | Elevation of privilege | A missing or unreadable policy file silently weakens the posture | high | mitigate | A missing file loads as enforce (the safe reading); any other read failure is POLICY_DENIED as before; the default is one definition pinned equal to the schema |
| T-34-06 | Spoofing | Eager creation follows a symlink or writes through a loose directory | high | mitigate | The existing keyring module lstat-guards, checks owner and mode and creates exclusively; the unavailable case is a test; the doctor reports each class as a fail |
| T-34-07 | Denial of service | A keyring that cannot be created refuses every host | medium | mitigate | Logged at start with an event name, doctor fail with the class and a fix, status, up, down and doctor keep working; the availability cost is the price of failing closed and is documented |
| T-34-08 | Information disclosure | A log line, doctor detail or reason text carries a key, token, path or policy value | medium | mitigate | The keyring_ready line carries the kid only; the unavailable line carries no detail; the doctor keeps its no-leak assertions; the new reason text names no value |
| T-34-09 | Repudiation | The opt-out is invisible after the flip | medium | mitigate | The doctor item is a warn whenever the mode is off, and D34-1 and the policy reference name the opt-out |
| T-34-10 | Tampering | A second default drifts from the schema | medium | mitigate | One constant, imported by the doctor, pinned equal to the schema default by a test |

Accepted residuals: a same-user process still reads the token or the key file or attaches as any host (stated first in every document); a user who sets mode off is back on the 0.4.x posture and is warned by the doctor.
</threat_model>

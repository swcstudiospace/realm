# Plan 15-13: CLI wiring for realm init and realm doctor --fix (ONB-01, ONB-02)

## Objective

Reconcile the CLI wiring for both commands and close the test gaps. The wiring is already in `src/cli/main.ts`:

- `CLI_COMMANDS` includes `init` (`:47`); the usage string names it (`:51`).
- `parseArgv` accepts `doctor` with no words, or exactly `--fix` or `--fix --dry-run` (`:76-81`). `init` takes its own words (`:73-75`).
- `runCli` dispatches `init` before it resolves config (`:680-682`). `runInitCommand` maps usage to exit 2 (`:659-661`), `InitRefusal` to exit 1 with the code on stdout (`:666-667`), and success to exit 0 with the summary JSON on stdout (`:663-664`).
- With no valid config, `doctor --fix` exits 1 with `SCHEMA_INVALID` and names `realm init` (`:690-694`). An ordinary `doctor` runs the one-item local report and exits 0 (`:695-700`; plan 15-07 owns that branch).
- `runDoctorFix` runs `applySafeFixes` with `home: deps.env["HOME"] ?? ""` (`:515-518`), so an absent HOME fails closed. A refusal exits 1 through `failureFor` (`:525-535`).
- `runDoctor` returns 0 on the local path (`:487-491`), so P15-O3 holds.

No source change is planned. The gaps are tests: `test/cli/cli.test.ts` has no CLI-level assertion for `init` (exit codes, no config read, no daemon contact), and no test for `doctor --fix` with an absent HOME. If a new test exposes a defect, the minimal fix goes into `src/cli/main.ts`. Edits there must stay in the `init`, `doctor --fix` and exit-code paths; plan 15-07 owns the `runCli` config-absent branch that also contains `doctor`.

Decisions this plan serves: D-1507 (local-only `--fix`, dry run, exit codes), P15-O3 (doctor exit 0 unless `--fix` refuses), P15-O1 (`--image` required through the CLI), P15-O2 (init reaches no daemon and provisions nothing).

## Artifacts this phase produces

- `test/cli/cli.test.ts`: two added tests (ONB-01 and ONB-02 titles).
- `src/cli/main.ts`: unchanged unless a test exposes a defect.

No documentation, no new file.

<threat_model>
- init that reads a stale or foreign config before writing. Mitigation: dispatch before config resolution (`main.ts:680-682`). Test: the new "never reads config" assertion with a counting `readConfig`.
- init or doctor --fix that contacts the daemon and inherits its environment. Mitigation: neither path calls `send`, `spawn` or `connectSocket`. Test: `effects` stays `[]`.
- doctor --fix with an unknown home mutating an unintended directory. Mitigation: an empty home refuses every target (`fix.ts:124`). Test: the new no-HOME test.
- A misleading exit code that hides a refusal. Mitigation: refusal exits 1 with the code on stdout. Tests: existing `:1236` and `:1215`; the new refusal assertions.
</threat_model>

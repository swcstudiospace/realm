# Plan 15-05: allowlisted daemon environment, proven on both start paths (ONB-07, D-1505)

## Objective

Prove ONB-07 on both start paths with real child processes. D-1505 is the locked decision: one allowlist in `src/daemon/spawn-env.ts`, used by the CLI spawn and by the Omp extension, with sentinel tests. The code for that is shipped. This plan adds the proof and changes no source file. The removal of the gateway endpoint name from the allowlist is in plan 15-06.

### Verified at HEAD (reconciled; cited from the current read)

- `src/daemon/spawn-env.ts:8-18` holds `ALLOWED_EXACT`, `:20` the `REALM_HOST_PIN_` prefix, and `:22-33` `daemonSpawnEnv`.
- CLI path: `src/cli/main.ts:342-347` `spawnDetachedDaemon` calls `launchFilteredDaemon`; `:351-369` spawns `process.execPath` with `env: daemonSpawnEnv(source)` (`:366`).
- Omp path: `src/omp/extension.ts:28-31` calls `startDetachedDaemon(daemonEntry, stateDir)`; `src/cli/main.ts:373-375` calls `launchFilteredDaemon(entry, stateDir, process.env)`. The extension path is allowlisted. It is not a defect.
- The research's `startDetachedDaemon(entry, stateDir, env)` signature was not adopted and is not needed. Plan 15-07 owns `src/cli/main.ts` and keeps the current signature.
- `test/daemon/spawn-env.test.ts:35-92` runs real detached children through `launchFilteredDaemon` and through `startDetachedDaemon`, and asserts the sentinel is absent on both. Its source object sets `REALM_DRIVER_SECRET_ROOT: "/stale/secrets"` at `:53`, but the child never reports that value.

### Gaps this plan closes

1. The CLI leg is not driven through `runCli(["up"])`. The real CLI start path is `runCli` with the default spawn, and no test runs that with a real child.
2. The stale `REALM_DRIVER_SECRET_ROOT` is in the test source but is never asserted absent in the child.
3. `daemonSpawnEnv` has no unit test of its exact selection.

## Artifacts this phase produces

- `test/daemon/spawn-env.test.ts`: a real-process test through `runCli up`; the `staleSecretRoot` assertion on both legs; a unit test of the exact selection.
- No source file changes. `src/daemon/spawn-env.ts`, `src/cli/main.ts` and `src/omp/extension.ts` are verified as shipped and are not edited by this plan.

## Decision coverage

- D-1505 (ONB-07): this plan proves the allowlist on both start paths.
- D4 and D1: no default-mode or catalogue change.

<threat_model>

- Trust boundary: the long-lived daemon inherits its environment from whichever process started it. A provider key or any secret-shaped variable in the caller's environment must not reach the daemon or its children. The allowlist is the only mechanism; a denylist is rejected because a new secret name would leak by default.
- Tampering: a stale `REALM_DRIVER_*_ROOT` must not reach the daemon, so the daemon cannot read a root from the environment.
- Information disclosure: the sentinel tests write only the fields the probe script chooses (the sentinel value, not an environment dump), so no secret value is printed by a test.
- The names in the allowlist are paths, digests and a log level (`REALM_LOG_LEVEL`). None is a credential.

</threat_model>

# Plan 15-11: realm init (ONB-01)

## Objective

Reconcile ONB-01 for `realm init` (PR C unit C1) against the code at HEAD 1fa69c1 and close the gaps the reconciliation found:

1. No preflight rejects a state directory whose daemon sockets cannot be bound (unix socket paths are limited to 107 bytes). `src/cli/init.ts` has no such check.
2. No test refuses a `config.json` inside the workspace root.
3. No test refuses a symbolic link as `--workspace`.
4. No test pins that an existing config directory keeps its mode.

The shipped behaviour is kept. Do not re-implement it: argument parsing, the preflight refusals, the `wx` plus `linkSync` no-clobber publish, rollback, the 0700 and 0600 modes, and image validation through `loadRuntimeConfig` all stay as they are.

Decisions this plan serves:
- D-1507: preflight before any write, no overwrite, policy then config, 0700 and 0600 modes.
- D4: `policy.json` names `"mode": "fail-closed"` explicitly.
- P15-O1: `--image` is required and checked by the daemon's own loader. There is no digest lookup and no digest is invented.
- P15-O2: "clean host" means init writes only the two templates and the private directories. It provisions no Podman, gateway, supervisor, driver or image.
- D1: no catalogue, tool-schema, session-record or control-protocol change. Refusals reuse `SCHEMA_INVALID`, `POLICY_DENIED`, `WRITE_NOT_ATOMIC` and `CLEANUP_FAILED`.

<threat_model>
- Overwrite of a foreign file through a symlink or a race. Mitigation: `lstat` preflight (including dangling links), `wx` temp file, `linkSync` no-clobber. Tests: `init.test.ts:355-441`, `:626`, `:657`, `:687`.
- An agent in the workspace rewrites `config.json` or `policy.json`. Mitigation: containment on resolved paths (`init.ts:263-278`). Tests: `:522-549` and the new config-inside-workspace test.
- A socket path that the daemon cannot bind, found late and opaquely. Mitigation: the new preflight, computed from the same derivations the daemon and driver use. Tests: the two boundary tests (107 and 108 bytes).
- Tightening or changing a directory the init did not create. Mitigation: `directoryIfSafe` refuses a non-0700 private root without changing it; the config directory's mode is never touched. Tests: `:440` and the new existing-config-directory test.
- A policy published without its config. Mitigation: policy is published first and removed if the config publish fails (`init.ts:433-443`). Tests: `:626`, `:657`.
- An invented or mismatched digest. Mitigation: validation through `loadRuntimeConfig` (`init.ts:240-248`). Test: `:474`.
- Secret leakage. Init prints paths and the mode only; `InitRefusal` details name files and flags, never contents. Test: `:112` (stdout parse), and the refusal tests assert the code line.
</threat_model>

  <action>
In `preflight` (src/cli/init.ts), after the roots are derived and the directory checks pass, and before the existing-file loop at `:289`, add one check:

1. Derive the three host socket paths the daemon's own session uses:
   - `controlSocketPath(stateDir)`;
   - the sandbox name `realmSandboxName("daemon")`, then `channelPathsOf(secretDirOf(roots.secretRoot, sandboxName))`, taking its `controlSocket` and `sshSocket`.
   The literal `"daemon"` is the daemon's session id (src/daemon/main.ts:25). The CLI does not import the daemon module.
2. For each path, when `Buffer.byteLength(path, "utf8") > UNIX_SOCKET_PATH_MAX_BYTES`, throw `new InitRefusal("SCHEMA_INVALID", ...)`. The detail names which socket it is (control, channel control, or ssh) and its byte length, and says `pass a shorter --state-dir`. It names no file contents.
3. Define `const UNIX_SOCKET_PATH_MAX_BYTES = 107;` in init.ts. Its comment says: sun_path holds 108 bytes including the terminating NUL; the limit equals src/runtime/driver/channel.ts:55-56, which does not export it. Do not change channel.ts.
4. Record the arithmetic in a comment. With default roots the binding path is `<stateDir>/secrets/realm-daemon/channel/control.sock`, which is 42 bytes longer than the state directory. A state directory longer than 65 bytes is therefore refused. The control path `<stateDir>/run/control.sock` is 17 bytes longer and the ssh path is 34 bytes longer.

No write happens before the check, and a path is never truncated or shortened.

Add to test/cli/init.test.ts (titles cite ONB-01):
- "a state directory that puts the daemon channel socket over 107 bytes is refused and writes nothing". Use `stateDir = join(f.root, "s".repeat(66 - Buffer.byteLength(f.root) - 1))`, so `Buffer.byteLength(stateDir) === 66`. Assert exit 1, stdout `SCHEMA_INVALID\n`, stderr matching `/107 bytes/` and `/--state-dir/`, and that `stateDir`, `f.configPath` and `f.policyPath` do not exist.
- "a state directory that puts the daemon channel socket at exactly 107 bytes is accepted". Use a state directory of 65 bytes. Assert exit 0 and `Buffer.byteLength(join(stateDir, "secrets", "realm-daemon", "channel", "control.sock")) === 107`.

Both tests first assert `Buffer.byteLength(f.root) < 60` with the message "scratch root too long for the boundary test", so the boundary is exact and no test is skipped.

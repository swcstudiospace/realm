# Plan 15-06: doctor checks for the roots, the driver socket and the gateway (ONB-04, D-1506)

## Objective

Bring the three runtime items to the design in `15-RESEARCH.md` section 3.4, which D-1506 locks: `runtime-roots`, `driver-socket` and `gateway` in `src/doctor/runtime-checks.ts`, appended after `kernel-hardening`, with a one-item report when config cannot be loaded. The report is 14 items. This plan runs after plan 15-05 in wave order and also removes `REALM_DRIVER_GATEWAY_ENDPOINT` from the daemon allowlist (the removal moved here from 15-05), in the same change that stops the gateway item reading it.

### Verified at HEAD (reconciled)

- Registration: `src/doctor/checks.ts:44-58` `CheckId` lists fourteen ids. `:150-162` `REGISTERED` holds the eleven registered checks. `:187-195` `runChecks` appends `runtimeChecks(...)` after them, so the three runtime items are last and in order. This placement is correct.
- `src/doctor/runtime-checks.ts:12` `RuntimeCheckId` is the three ids; `:27-35` `RuntimeCheckOptions`; `:73-83` `defaultStat`.
- `:131-164` `rootFinding` checks unset, relative, absent, unreadable, symlink, directory, the workspace owner, and the private mode 0700. `:168-173` `omittedFinding` warns when a private root is omitted from config (kept: pinned by `test/doctor/runtime-root-checks.test.ts:146`).
- `:177-192` `runtimeRootsCheck(config, stat)`. Shipped behaviour and pinned tests: a missing config is one item (`test/doctor/runtime-root-checks.test.ts:37`); a 0755 workspace passes; the detail never carries a path.
- `:194-233` `driverSocketCheck(env, stat, connect, timeoutMs)` reads `REALM_DRIVER_SOCKET` from env. Mode 0600 socket in a 0700 parent, a refused dial is a fail.
- `:274-285` `runtimeChecks`: when `config` is undefined it returns one `runtime-roots` item with detail `runtime config is absent` and the `realm init` fix.
- `src/cli/main.ts:683-707` (read in plan 15-07) reports an invalid config with the same detail, so the detail is wrong for an invalid file.
- Gateway: `:255-271` `gatewayCheck` is a TLS dial of `REALM_DRIVER_GATEWAY_ENDPOINT` (`defaultConnectGateway` `:85-115`). It never runs `openshell`, has no `not_configured` case and no timeout test. The design (`15-RESEARCH.md:149`) requires `openshell status -o json` with status parsing.
- `src/doctor/checks.ts:97-102` `DoctorOptions` has `statPath` and `connectGateway`, and no `configPath`, `configProblems` or `driverSocketPath`.

### Gaps this plan closes

1. No 107-byte channel-path check. `runtime-roots` never builds a socket path. The driver refuses such paths in `assertSocketPathsFit` (`src/runtime/driver/channel.ts:160-164`, limit `:56`).
2. No overlap check on effective roots or against `config.json`. The loader (plan 15-04) refuses explicit overlap only; derived defaults can still sit inside the workspace, and the sandboxed agent could rewrite `config.json` if it sits inside the workspace (`15-RESEARCH.md:207`).
3. No canonical check (`realpath(root) === root`). The driver refuses a non-canonical root (`15-RESEARCH.md` section 2.2).
4. No owner check on the private roots, and none on the driver socket or its parent.
5. The gateway item does not run `openshell`. Its test (`test/doctor/runtime-root-checks.test.ts:249-263`) pins the TLS dial, so that test is replaced.
6. An invalid config produces the "absent" detail. The one-item report must name the problem keys (from plan 15-04's `describeRuntimeConfigProblems`).

### Decisions taken in this plan

- The driver socket path comes from `REALM_DRIVER_SOCKET` only, as shipped. The research's `<stateDir>/gateway/driver.sock` fallback is NOT added: the installed unit always names the socket, `docs/integration/openshell.md:229` documents the variable, and a fallback guesses a path the driver may not bind. The owner may revisit this (open question).
- The gateway item parses `status` from `openshell status -o json` and never the exit code alone; the probe receives `selectOpenShellEnvironment(env)` (PATH, HOME, XDG_RUNTIME_DIR) as the openshell item does.
- An omitted private root still warns (shipped). Explicit roots and the effective overlap checks fail.
- Exit behaviour is unchanged (P15-O3): the doctor never exits non-zero for a check status.

<threat_model>

- Trust boundary: the doctor reads config and the host's socket, directory and gateway state, and runs `openshell` as a child process. The child receives only the allowlisted OpenShell environment and a timeout; it is never given a shell, and its output is parsed for one field and then discarded.
- Information disclosure: no detail or fix carries a path, a root value, a socket error message or any command output. Each detail is a fixed phrase naming a key or a condition (the tests assert the absent path).
- Elevation: a symlinked, foreign-owned or non-canonical root, or a socket in a foreign directory, is refused as a finding, not repaired (repair is `doctor --fix`, plan 15-12 and 15-13, and it refuses symlinks).
- Denial of service: the gateway probe is bounded by `probeTimeoutMs` in addition to the runner's own timeout, so a hung `openshell` cannot hold the report.
- Socket path length: the check uses the same `assertSocketPathsFit` the driver uses, so the doctor and the driver agree on the 107-byte rule.

</threat_model>

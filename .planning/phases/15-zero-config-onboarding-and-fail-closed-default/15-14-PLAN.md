# Plan 15-14: docs for realm init and realm doctor --fix (ONB-01, ONB-02)

## Objective

Bring the three docs that describe the operator's onboarding path in line with the shipped `realm init` and `realm doctor --fix`. The README quickstart is not in this plan (plan 15-16 owns it). Only the lines listed below change.

Facts the docs must state, verified at HEAD:
- `realm init` requires `--image` (`src/cli/main.ts:51`, `src/cli/init.ts:78-99`). It writes `config.json` and `policy.json` with `mode` `fail-closed` explicit (`src/cli/init.ts:478-479`). It creates the state directory, `secrets` and `sandboxes` at 0700 and never changes an existing directory it did not create (`src/cli/init.ts:186-209`, `:307-342`).
- `realm init` refuses an existing `config.json` or `policy.json` in any form, a symbolic link on any path, a config inside the workspace, a state directory inside the workspace, and a daemon socket path over 107 bytes (`src/cli/init.ts:232-303`, plus plan 15-11's check).
- `realm doctor --fix [--dry-run]` touches only the state directory, `run` and `sessions` (`src/doctor/fix.ts:65`). It refuses symbolic links, non-directories, foreign owners and unsafe targets (`src/doctor/fix.ts:123-166`). Exit codes: 0 when nothing is refused; 1 on a refusal, a failure, or no valid config (the message says `run realm init`, `src/cli/main.ts:693`); 2 on usage (`src/cli/main.ts:76-81`).
- Neither command provisions Podman, the OpenShell gateway, the host supervisor, the compute driver or the image (P15-O2). Those are outside this repository (TD-02).
- Init's exit codes: 0 written, 1 a catalogue-coded refusal (the code on stdout, the reason on stderr), 2 usage (`src/cli/main.ts:657-671`).

Decisions this plan serves: D-1507 (both commands' contracts), P15-O1 (`--image` is required, no lookup), P15-O2 (clean-host boundary), P15-O3 (doctor exit contract, stated for `--fix`), D4 (the explicit `fail-closed` mode in the written policy).

  <action>
Append two H2 sections at the end of docs/policy-reference.md, after the current last line. Keep each to a short bulleted list with these facts and no other claims.

`## realm init`:
- Syntax: `realm init --image <name@sha256:64-hex-digest> [--workspace <absolute path>] [--state-dir <absolute path>]`. It runs before any config is read.
- `--image` is required. Realm does not look up a digest; pass the digest the driver runs.
- `--workspace` defaults to the current directory, and must be an existing account-owned directory that is not a symbolic link and not `/`.
- `--state-dir` defaults to `$XDG_STATE_HOME/realm` when that is absolute, else `$HOME/.local/state/realm`.
- Writes, in order: the private directories (the state directory, `secrets` and `sandboxes` at 0700; the config directory at 0700 only where init creates it); `policy.json` with `"mode": "fail-closed"` and the workspace as its only root; then `config.json`. Both files are created at mode 0600 and published without overwrite.
- Refuses before any write: an existing `config.json` or `policy.json` in any form, including a symbolic link or a dangling one; a symbolic link on any path; an existing state directory or root that is not an account-owned real directory at 0700 (init never changes it; `realm doctor --fix` tightens only the state directory); a config inside the workspace; a state directory inside the workspace; a daemon socket path over 107 bytes (use a shorter `--state-dir`).
- Does not provision Podman, the OpenShell gateway, the host supervisor, the compute driver or the image. Those are outside this repository and are listed in the README prerequisites.
- Exit codes: 0 written; 1 a catalogue-coded refusal or write failure (the code on stdout, the reason on stderr); 2 usage.

`## realm doctor --fix`:
- Syntax: `realm doctor --fix [--dry-run]`. `--dry-run` is accepted only with `--fix`. It always runs locally, even when a daemon answers.
- Targets: the configured state directory, its `run` child and its `sessions` child. Nothing else: no `policy.json`, no `config.json`, no private roots, no workspace, no socket, and no file.
- A missing target directory is created at 0700. An existing target at another mode is set to 0700.
- Refuses, with nothing applied after the refusal: a symbolic link, a non-directory, a directory owned by another account, the filesystem root, the home directory, the workspace, a target that contains or sits inside the workspace, and an unsafe ancestor. The parent of the state directory must exist. Repairs use a descriptor-pinned `fchmod`.
- `--dry-run` reports the same actions and writes nothing. A second run reports `"fixes": []`.
- Output: stdout one JSON object `{"dryRun":…,"fixes":[…],"checks":[…]}`; stderr one line per fix.
- Exit codes: 0 when nothing is refused; 1 on a refusal, a failure, or no valid config (the message says to run `realm init`); 2 on usage.
- Every other item in the doctor report stays a prose fix for the operator. `realm doctor --fix` does not change ownership and does not provision the private roots.

Use placeholders only (`<scratch>`, `<state dir>`, `<workspace>`). Do not change any existing line of the file.
  </action>

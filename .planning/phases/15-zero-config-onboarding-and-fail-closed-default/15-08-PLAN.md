# Plan 15-08: the live suite's gate and scenario config on the roots in config.json (ONB-03, D-1504)

## Objective

Close the test gaps in the live-suite gate for ONB-03. The gate, the scenario config and the scenario-1 mode assertion are shipped; this plan proves them with hermetic helper tests and removes one stale comment. The live run itself is plan 15-10 (checkpoint L-A) and is not executed here.

### Verified at HEAD (reconciled)

- Gate: `test/support/production-live.ts:31` `LIVE_DRIVER_CONFIG_VARIABLE = "REALM_LIVE_DRIVER_CONFIG"`. `:52-89` `productionSkipReason` names the first missing prerequisite in the order documented at `:49-51`. `:64-70` checks the config path is absolute and an existing file, and that `readableDriverConfig` (`:91-98`) accepts it through `loadRuntimeConfig`.
- Roots: `test/support/production-live.ts:475-495` `readLiveInputs` loads the config and calls `runtimeRootsOf` (`:485`). The stale variables are never read.
- Scenario config: `test/support/production-live.ts:537-541` writes `{ image, stateDir, workspaceRoot, secretRoot, sandboxStateRoot }`; `:545-553` `cliEnvironment` carries the host PATH, HOME and XDG_RUNTIME_DIR, `XDG_CONFIG_HOME`, and `REALM_DRIVER_SOCKET` only when set. No root variable.
- Scenario 1 mode assertion: `test/integration/production-driver.test.ts:252-255` asserts `mode` is `fail-closed`.
- Gate tests exist at `test/integration/production-live-helpers.test.ts:320-330` (gate inputs), `:394-400` (missing, relative or not a file), `:403-406` (REALM_DRIVER_SOCKET), `:412-414` (unreadable and malformed config), `:442` (unset config).
- `createScenarioEnvironment` tests exist at `:125-170`.

### Gaps this plan closes

1. No test of `readLiveInputs` root derivation (grep finds no call in the helper tests). The suite must derive omitted roots the way the daemon does, and must ignore stale variables.
2. No test that a config which is valid JSON but refused by the loader gives the `not a readable runtime config` reason. The gate calls `loadRuntimeConfig`, so this path needs a test.
3. No test that the scenario's `config.json` carries the explicit roots, or that its CLI environment has no root variable.
4. `test/integration/production-driver.test.ts:30` says the scenario environment carries "the three driver roots". That is stale: the roots come from the scenario's config.json.

- D-1504 (ONB-03): the gate and the scenario derive the roots from the config file through the production function.
- D4: scenario 1's fail-closed assertion (`production-driver.test.ts:252-255`) is pinned as shipped; this plan does not change it.

<threat_model>

- Trust boundary: the operator's environment names the live config file. The gate reads that file for the roots only, and the suite writes its own scenario config under a temporary directory.
- Destructive operations: the live suite removes only its own sandbox and temporary directories (documented at `production-driver.test.ts:28-32`). This plan runs no live step and no removal.
- Information disclosure: the helper tests use placeholder paths under `/tmp`-free fixtures created in the test's own temporary directory, and assert on the structure of the scenario config and CLI environment, not on their contents being printed.

</threat_model>

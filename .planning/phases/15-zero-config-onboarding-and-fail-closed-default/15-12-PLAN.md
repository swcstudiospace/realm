# Plan 15-12: realm doctor --fix safe subset (ONB-02)

## Objective

Reconcile ONB-02 for `realm doctor --fix [--dry-run]` (PR C unit C2) against the code at HEAD 1fa69c1. The shipped `src/doctor/fix.ts` already implements the descriptor-pinned safe subset, and `test/doctor/fix.test.ts` already has about 30 cases. This plan adds the cases the reconciliation found missing and adds a static guard that the code keeps its descriptor-only mode changes. It does not change the repair scope.

Scope is deliberately the shipped one: the state directory, `run` and `sessions`. The research (`15-RESEARCH.md` section 3.5) also listed the secret and sandbox roots as targets. The shipped contract excludes them: `test/cli/cli.test.ts:1145-1146` asserts that repair does not provision them, `AGENTS.md:32` says so, and `src/doctor/runtime-checks.ts:59` says `doctor --fix only creates or tightens stateDir, stateDir/run and stateDir/sessions`. ONB-02 names only the state directory. The owner must confirm this scope (see the open questions in the phase summary) before any root is added.

Decisions this plan serves:
- D-1507: `--fix` always runs locally; it uses `lstat` and a no-follow `fchmod`; it refuses symlinks, foreign owners and unsafe targets; it touches only the listed directories; `--dry-run` writes nothing.
- P15-O3: `--fix` exits 1 when it refuses something (wired in plan 15-13).
- D1: no catalogue change. Refusals use the existing `SCHEMA_INVALID` code through `FixRefusal`.

Current state, read for this plan:
- `applySafeFixes(stateDir, dryRun, locations, options)` at `src/doctor/fix.ts:55-110`. Targets are the state directory, `run` and `sessions` (`:65`). The parent of the state directory must exist and be pinned (`:67-70`). Missing directories become `create-directory` actions and existing ones with a wrong mode become `set-mode` actions (`:71-84`).
- The mode-0700 check and the umask-readable check happen before any write (`:88-93`). Every pinned directory is verified before each mutation (`:94-101`).
- `normalizeStateDir` refuses relative and non-canonical paths (`:112-119`). `refuseProtectedTarget` refuses the root, home, the workspace, and any target that contains or sits inside the workspace (`:123-134`).
- `observeDirectory` refuses a symbolic link (`:159`), a non-directory (`:160`), a foreign owner (`:161`) and an unreadable directory (`:162-164`). `pinDirectory` opens with `O_DIRECTORY|O_NOFOLLOW` (`:170`). `verifyPin` checks the descriptor, the named path, the realpath and the `/proc/self/fd` link (`:181-192`). `applyAction` creates through `/proc/self/fd` (`:200-202`) and uses `fchmodSync` (`:214`).
- The CLI passes `home: deps.env["HOME"] ?? ""` and the workspace from config (`src/cli/main.ts:515-518`). An empty home makes every target fail `unsafe-target`, which is the intended fail-closed result.
- Existing tests cover: 0755 to 0700 with the previous mode named (`test/doctor/fix.test.ts:68`); missing run and sessions (`:81`); missing state directory (`:96`); second run (`:112`); dry run identical and writes nothing (`:126`); symlinked state and child (`:150`, `:163`); a file at the state path (`:175`); a missing parent (`:183`); trailing separator and dot (`:201`); unreadable and locked modes (`:217`, `:227`, `:237`, `:251`, `:262`, skipped only when running as root with the existing `LOCKED_SKIP` guard); umask (`:280`); home, workspace, ancestor and root refusals (`:293-322`); foreign owners (`:333`); repair of run and sessions without touching unrelated directories (`:355`); swap races (`:373`, `:393`, `:413`, `:459`); special bits (`:447`); a regular-file child before siblings (`:487`, for `sessions`).

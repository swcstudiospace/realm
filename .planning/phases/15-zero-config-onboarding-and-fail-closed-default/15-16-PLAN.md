# Plan 15-16: PR D (ONB-05, ONB-06): install evidence and quickstart

## Objective

Close ONB-05 and ONB-06 as evidence and documentation, with no code change. The plan has two live checkpoints that a human runs (not the executor), then one documentation task that uses only the evidence they return:

The human sets `REALM_EVIDENCE_DIR` to an absolute scratch directory outside the repository before Task 1. Every verify command that reads evidence starts with `test -n "$REALM_EVIDENCE_DIR"`, so it fails closed when the variable is unset.

1. Task 1 (checkpoint L-C2, ONB-06): capture a fresh `init`, `up`, `status`, `down` transcript on the current build on a real Podman 5.x host. This is the procedure L-C of `15-RESEARCH.md` section 6, run on the current build, and it is also the transcript the README needs.
2. Task 2 (checkpoint, ONB-05): run L-D, the isolated-profile Omp install, list and rpc-ui session, without `-e`. It records that the extension loads from the installed plugin.
3. Task 3 (auto, docs): update `README.md`, `docs/hosts/snippets/omp.md`, `docs/integration/hosts.md` and `docs/integration/omp.md` from the returned evidence and from the code, and run `npm run check:docs`.

Nothing in this plan runs against the live stack, the production daemon or a container. The executor pauses at Tasks 1 and 2 and does not run their procedures.

## Open questions

- Q1 (ONB-06 fresh transcript). Decision taken by this plan: a fresh capture on the current build is REQUIRED (Task 1, L-C2). Reason: the README transcript is from 0.3.26, which predates `b6eaf27`, the commit that changed the `init` publish path, the preflight and the mode handling and that added the `doctor --fix` refusals. The output shape did not change, but the requirement is a transcript of the quickstart on the build being documented. Owner may overrule: keep the 0.3.26 transcript as the only ONB-06 evidence, and then ONB-06 is met only for 0.3.26 and the README must say so. The fresh capture can reuse the L-C output of plan 15-15 only if that run recorded the same checkout commit as Task 1 L-C2 (the record is required in Task 1's evidence header).
- Q2 (L-D session environment). The rpc-ui session needs an isolated `HOME` for Omp (the plugin link is under the Omp home), but the Realm daemon the extension spawns inherits `HOME` and needs the realm account's `HOME` for the OpenShell gateway lookup (`README.md:76-77`, `docs/hosts/snippets/omp.md:91-92`). So with an isolated `HOME` the daemon may answer disconnected with an OpenShell reason. The pass criterion for ONB-05 is extension load from the installed plugin (the `realm` status key and the `realm-retry` command are registered), not the active state. Decision taken: accept a disconnected status as the status text, record it, and do not claim activity. Owner may overrule: require an active status, which would need the realm account's `HOME` for the session and a proof that the Omp plugin is still read from the isolated location.
- Q3 (tarball install). Not verified here. `package.json` `files` omits `node_modules` and the lockfile (`15-RESEARCH.md` section 2.5). The README keeps stating only the verified checkout-link path. Owner decides whether a tarball path is needed for ONB-05; out of scope here.

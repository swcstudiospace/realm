# Plan 15-04: roots in config.json (ONB-03, D-1504)

## Objective

Close the ONB-03 gaps that remain at HEAD 1fa69c1 and verify the shipped part. D-1504 is the locked decision: `RuntimeConfig` carries optional `secretRoot` and `sandboxStateRoot`, `runtimeRootsOf` derives `<stateDir>/secrets` and `<stateDir>/sandboxes` when they are absent, the daemon and the driver read the same `config.json`, and the three `REALM_DRIVER_*_ROOT` variables are no longer read.

### Verified at HEAD (reconciled, do not re-implement)

- `src/runtime/config.ts:18-20` and `:33-40`: `secretRoot` and `sandboxStateRoot` are optional and accepted. The closed key set refuses everything else, including the D-80 denied names (`:44-51`).
- `src/runtime/config.ts:94-100`: `runtimeRootsOf` derives the two defaults from `stateDir` and returns `workspaceRoot` unchanged.
- `src/runtime/config.ts:70-71`: explicit values pass `requireAbsolutePath` (`:121-126`), so a relative explicit root is `SCHEMA_INVALID`.
- `src/runtime/driver/main.ts:28-38`: `DRIVER_ENV` names no root variable. `:63-102` `loadDriverProcessConfig(env, version, readConfig)`. `:104-110` `rootsFromConfig` reads `resolveConfigPath(env)` and rethrows any failure as `SCHEMA_INVALID` with no path.
- `src/daemon/main.ts:78-79` and `:92-94`: roots come from `runtimeRootsOf(loadRuntimeConfig(runtimeInput))`. No `deps.env` root read remains. This file needs no edit in this plan.
- `test/daemon/main.test.ts:361-386` (explicit roots reach `startDaemon`, a stale variable is ignored) and `:388-406` (derived defaults with empty variables) already pass.
- `test/runtime/driver/driver-main.test.ts:192` (stale roots ignored) and `:200` (absent config refuses with no fallback to the stale variables).

### Gaps this plan closes

1. No lexical overlap refusal exists. `loadRuntimeConfig` (`src/runtime/config.ts:55-81`) does not compare explicit roots with each other or with `workspaceRoot`. No test in `test/runtime/config.test.ts` names overlap, containment or inside.
2. `describeRuntimeConfigProblems` does not exist. `src/runtime/config-file.ts:12-19` throws `SCHEMA_INVALID` for both an absent file and invalid JSON, so the doctor and the CLI need a key-level description of a parsed object.
3. The driver's config-home fallback is untested: `XDG_CONFIG_HOME` relative or unset must resolve to `HOME/.config/realm/config.json` (`src/runtime/host-paths.ts:15-26`, documented at `docs/policy-reference.md:297-298`). `test/runtime/driver/driver-main.test.ts:72` only ever sets an absolute `XDG_CONFIG_HOME`.
4. The daemon has no test that an overlapping explicit root is refused at start before `startDaemon` runs.

## Artifacts this phase produces

- `src/runtime/config.ts`: exported `describeRuntimeConfigProblems(input: unknown): readonly string[]`; `loadRuntimeConfig` refuses explicit overlapping roots with `SCHEMA_INVALID`; an internal lexical `rootsOverlap(a, b)` helper (not exported).
- `test/runtime/config.test.ts`: new tests named under "ONB-03" (overlap, prefix sibling, key-only problem description).
- `test/runtime/driver/driver-main.test.ts`: new tests for config-home resolution.
- `test/daemon/main.test.ts`: one new overlap-at-start test.
- No new source file. No edit to `src/daemon/main.ts` or `src/runtime/driver/main.ts`; both already read the roots from config.

## Decision coverage

- D-1504 (ONB-03): this plan owns the loader, the overlap rule, and the single-source test coverage.
- D4 and D1: no default-mode or schema change; `config.json` gains no new key here. The catalogue and tool schema are untouched.

<threat_model>

- Trust boundary: `config.json` is operator-owned and read at startup by both processes. A root that overlaps the workspace would let the sandboxed agent reach secret or sandbox state. The loader refuses that for explicit values before any process starts.
- A stale `REALM_DRIVER_*_ROOT` variable must not be honored. Both processes read config only, so they cannot diverge.
- Error text must not carry a value. `describeRuntimeConfigProblems` names keys only, and an unknown key is reported without its name, so arbitrary input is never echoed.
- Lexical comparison is a load-time guard. The driver's realpath checks remain the authority at start (`src/runtime/driver/compute-driver.ts`, `lifecycle.ts`), and plan 15-06 adds the effective-root and canonical checks to the doctor.

</threat_model>

## Sequence
1. Wave 1 lanes edit in parallel; no lane runs a gate. The orchestrator builds once, runs typecheck, the new and touched test files, lint on the changed files and `check:docs`; failures go to corrective tasks. Then one commit per lane (explicit paths), then push and open pull request A.
2. While pull request A is in review, wave 2 is developed on top of it (stacked). After A merges the branch is rebased onto `main`.
3. Wave 2: the orchestrator verifies as in step 1, runs the full unit suite and lint once, then runs the production live suite alone under the live lock (scenario 5 carries the new assertions); the realm stack is not reinstalled for this phase because no driver code changes.
4. Pull request B (wave 2 and the docs), review loop to 5 of 5, merge through the ship flow, verify the release.
5. Records: summary, verification, requirements and roadmap statuses from evidence only.

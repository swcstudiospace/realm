    - `runBootConformance(factory, manifest): Promise<readonly { id: string; ok: boolean; detail: string }[]>` runs these cases, each on a fresh fake daemon and fake timers, and `defineBootConformance(label, factory, manifest)` registers each as a `node:test` case:
      - C1 `attach-budget`: `hang()` attach rejects `STARTUP_BUDGET_EXCEEDED` once the manifest's `startupBudgetMs` (set to 25 ms in the harness manifest) elapses, `status().state` is not `active`, and no timer remains armed.
      - C2 `attach-ok-readback`: after a good attach `status()` reports state `active`, the policy mode read from the daemon, and the sink received exactly one `setStatus` call per distinct state (identical consecutive paints are not repeated).
      - C3 `refused-up-retention`: an attach that returns a refusal keeps the client only when it came back with it; status shows the refusal code; the client is not closed; a rejected attach closes nothing it never held.
      - C4 `terminal-attach-failure`: attach failing with `POLICY_DENIED` leaves status `error`, schedules no re-attach even when re-attach is enabled, and `retry()` then performs exactly one new attach.
      - C5 `guard-fail-closed`: for tool names `undefined, 7, null, {}, Symbol("x")` the verdict blocks with `realm bad tool call` and no daemon call is made; an unknown string name under fail-closed blocks with `POLICY_DENIED`; when `status()` rejects, a non-pass-through name is blocked; the guard never throws; an unreadable status never yields a pass for a guarded name.
      - C6 `shutdown-client-only`: shutdown calls `close()` exactly once, makes no other daemon call (the call log has no `up`, `call` or `down` after shutdown), clears every timer (`pendingCount() === 0`), is idempotent, and a later `guard` blocks.
      - C7 `reattach-off-by-default`: with the default manifest, a `status()` rejection with `REALM_NOT_ACTIVE` arms no wait and makes no new attach call across 1 000 000 ms of fake time.
      - C8 `reattach-bounded`: with `reattach.enabled`, a lost link and failing attaches produce at most `retryCap` (8) attempts; the wait before attempt `n` equals `equalJitterDelayMs(n, base, cap, random)` for `random` 0 and 1 (exact values, so jitter cannot collapse toward zero); after the cap the state is `failed` and no timer remains; a terminal code stops the streak at once; a successful attach resets the streak (verified by a second loss producing again up to 8 attempts).
      - C9 `switch-workspace`: `switchWorkspace(sameRoot)` makes no attach; `switchWorkspace(otherRoot)` closes the old client and attaches for the new root; a status reply naming another `boundRoot` or `sessionId` than the attach was made for is not adopted (client closed, state `error`).

<threat_model>
## Trust Boundaries

| Boundary | Risk |
| --- | --- |
| Agent-issued tool call to the plugin guard | A malicious or confused workload names a tool the guard does not classify, or sends a non-string name, to reach an unguarded host tool. |
| Plugin to daemon control socket | A hung or hostile daemon stalls the host, or a reply names another project's root or session. |
| Re-attach loop to the daemon | A flapping link produces a retry storm that starves the daemon or the host. |
| Shutdown path to the sandbox | A plugin that tears the sandbox down on exit kills work for other attached agents. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-21-07 | Elevation of privilege | guard backstop | high | mitigate | Task 1 `backstopVerdict` blocks non-string and unknown names in fail-closed or unknown mode and never throws; Task 3 C5 (and mutant `waveThroughHook`) enforce it for every conforming host. |
| T-21-08 | Denial of service | attach and status reads | high | mitigate | Task 1 `withStartupBudget` and the guard status bound; Task 3 C1 and C5 prove a hung daemon yields a verdict or a retryable error, never a hang; no timer survives. |
| T-21-09 | Denial of service | re-attach storm | medium | mitigate | Task 1 and C8: cap 8, equal jitter that never nears zero, off by default, terminal codes stop at once. |
| T-21-10 | Spoofing | status or up reply for another project | high | mitigate | C3 and C9: a reply naming another `boundRoot` or `sessionId` is not adopted and its client is closed (the rule `src/omp/extension.ts` applies). |
| T-21-11 | Tampering | destructive shutdown | high | mitigate | C6 and mutant `downOnShutdownHook`: shutdown closes the client only; the sandbox lasts until `realm down`, as in Omp. |
| T-21-12 | Information disclosure | status paint and logs | medium | accept with control | Paints carry state names and catalogue codes only (no daemon free text); the hook receives a sink, not a logger with file access. Redaction of any logged field stays with `src/observe` in the host adapters of later phases. |
</threat_model>

## Task 2 choices

### tsconfig.json

- `target` and `lib`: ES2023.
- `module` and `moduleResolution`: NodeNext (ESM, `.js` extensions required in relative imports later).
- `types`: `["node"]` explicitly. TypeScript 6 defaults `types` to empty, so `node:test` types need this.
- Strictness beyond `strict`: `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns`, `verbatimModuleSyntax`, `forceConsistentCasingInFileNames`.
- `skipLibCheck` is not set, so declaration-file errors are not hidden.
- `rootDir: "."`, `outDir: "dist"`, `sourceMap: true`. `rootDir` is `"."` so that tests under `test/` and source under `src/` both compile to `dist/`.
- `allowJs` and `checkJs`: see the empty-tree issue below.

**Empty-tree issue and the choice made.** With `include` set to `src/**/*.ts` and `test/**/*.ts` and no such files present, TypeScript fails with `TS18003: No inputs were found`. Setting `files: []` fails with `TS18002`. Neither form can pass on an empty tree. The applied choice: `include` lists `eslint.config.js` first, with `allowJs` and `checkJs` on, so typecheck checks a real file on the empty tree (it resolves the `@eslint/js` and `typescript-eslint` imports and the config types). The `src/**/*.ts` and `test/**/*.ts` globs remain in `include`. Plan 01-04 and 01-05 add their files under those globs and need no config change. Side effect: `npm run build` emits `dist/eslint.config.js` and its source map. `dist/` is ignored by git.

### eslint.config.js

- Flat config built with `tseslint.config(...)`.
- Global ignores: `dist/**`, `coverage/**`, `node_modules/**`.
- Base presets: `js.configs.recommended` and `tseslint.configs.strict` (non-type-aware, so probe files outside the tsconfig `include` still lint).
- `no-empty` set to `error` with `allowEmptyCatch: false` for `**/*.ts` (QUAL-01).
- `@typescript-eslint/ban-ts-comment` set to `error` with `ts-expect-error`, `ts-ignore`, and `ts-nocheck` all `true`. This is stricter than D-08, which bans only blanket `@ts-expect-error`. Note for suppression grep: the literal strings `ts-expect-error`, `ts-ignore`, and `ts-nocheck` appear in `eslint.config.js` as keys of this rule. They enforce the ban and are not suppressions.

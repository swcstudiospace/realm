## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tool caller -> dispatcher | Untrusted params cross into the pipeline; schema runs first with zero side effects on failure |
| queue timer -> state | A connecting state crosses into execution only through an observed transition or a bounded expiry |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-09 | T (Tampering) | src/tools/dispatch.ts | high | mitigate | The six-stage order is fixed with refusal-before-side-effects at every stage; the recorded call-order test proves schema runs first and no later stage runs after a refusal, so no call can skip validation, gating, or audit (D-89) |
| T-04-10 | D (Denial of Service) | src/tools/dispatch.ts | high | mitigate | Every awaited stage races withTimeout against TOOL_TIMEOUT, exec passes timeoutMs to the killing runner, and the connecting wait is bounded by toolQueueMs with the timer cleared on settle and the listener unsubscribed, so no queued or hung call leaks a timer, a listener, or a process (D-91, C-2) |
| T-04-11 | R (Repudiation) | src/tools/dispatch.ts | medium | mitigate | Admission is written before execution and the result after; a result-audit failure returns AUDIT_WRITE_FAILED without rollback and the caller treats the outcome as unknown (OQ-P4-07, D-89) |

  <behavior>
    - test/support/cold-attach-probe.ts holds a pure judge and the live driver. The judge, judgeColdTimeline, takes a timeline object: the millisecond marks of the three handshake replies, the realm status text at the moment of the last of them, the list of refused call results seen in the window (tool name, code, retryable, isError), the mark of the first call that succeeded and the number of polls, whether the child process was the same throughout (same pid, no exit), and the elapsed time. It returns pass with a list of facts, or fail naming the first violated rule. The rules: every reply within HANDSHAKE_BOUND_MS of 10000; realm status not active when the replies arrived (otherwise the run was not cold and the verdict is fail with that reason); at least one call refused in the window, and every refused call has isError true, code REALM_NOT_ACTIVE and retryable true; the first success is a done outcome later than the last refusal; the child never exited.
    - The live driver, runColdAttachProbe, spawns the built CLI with mcp, --host claude and --workspace for a new project directory under the scenario's workspace root, with the scenario environment and the production PATH (no recorder, no host binary needed), writes server/discover with modern meta, an initialize with a legacy version and a tools/list at once, records the mark of each reply, reads the realm status through the CLI helper, sends a tools/call for status and for exec (argv true) inside the window, then polls tools/call status every 2 s up to COLD_READY_TIMEOUT_MS until a done outcome, then sends a tools/call for list of the workspace root and expects done. It then reads realm metrics until an attached boot report for the host claude is counted (bounded), checks the presence marker for the child pid exists, closes stdin, and expects the child to exit 0 within 10 s and the marker to be gone. It returns the timeline for the judge and the per-step marks for the diagnostics.

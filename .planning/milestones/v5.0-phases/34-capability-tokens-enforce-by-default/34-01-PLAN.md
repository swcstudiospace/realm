<objective>
Make every test that is not about capability tokens independent of the default of `capabilityTokens.mode`, while the default is still `off`, so that plan 34-02 can flip the default in a commit that touches only the tests that pin the old default.

Purpose: ENF-01 and ENF-02 (the tests change together with the default; every client class works under it). A flip that lands together with forty fixture edits is neither reviewable nor bisectable. This plan finds the tests that would break, proves it with a local probe, and fixes them first.
Output: one shared test support module, the daemon fixture option, the forwarded connect seam in two rigs, and the explicit opt-out in the daemon tests that send tokenless requests on purpose. No src change.
Non-goals: no src, schema, doc or default change; no edit of any Class A test (plan 34-02); no new behaviour test of enforce (plans 34-02 and 34-03); no ROADMAP, STATE or REQUIREMENTS edit; no CHANGELOG or version edit.
</objective>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Test policy documents | Files a test writes for a daemon it starts; they decide the posture the test runs under |
| Client wrappers in test rigs | Code between a host under test and the real client; it can silently drop the host id |

## STRIDE Threat Register

| ID | Category | Component | Severity | Disposition | Mitigation |
| --- | --- | --- | --- | --- | --- |
| T-34-01 | Repudiation | A decoupled test hides a regression in the enforcing path because it now always opts out | medium | mitigate | Only tokenless non-token tests opt out; real-host suites (host-boot-isolation, the boot matrix) keep the default and forward the host id, so they run under enforce after plan 34-02; plan 34-03 adds the per-class enforcement tests |
| T-34-02 | Tampering | The probe is committed by accident and flips the default without the plan's tests | high | mitigate | Task 1 and Task 5 end with a git diff over src and the schema that must print nothing |
| T-34-03 | Information disclosure | The shared opt-out module is imported by a token test and hides a failure | low | mitigate | The module's header says a token test must not use it; the writePolicy merge keeps a document's own capabilityTokens key |
| T-34-04 | Denial of service | A wrapper that drops the host makes a later enforce run refuse every host-boot test | medium | mitigate | The forwarding test counts the capability-attach row, so a wrapper that drops the host fails with the default still off |

Accepted residuals: none. This plan changes no product behaviour.

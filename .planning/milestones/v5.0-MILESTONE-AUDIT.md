# Milestone v5.0 audit: Cold attach, enforced capability tokens and evidence

Scope: phases 33 to 37 (requirements COLD-01..04, ENF-01..04, EVID-01..03, V1LIVE-01..02, SPEC-01). Phase 33 made `realm mcp` answer the MCP handshake before the sandbox is up. ## Integration check (cross-phase)

No separate integration-checker run was made; the checks below are read from git history and the phase reports. Evidence tier: repository read, git history and the dated live windows; the verifiers ran no live step.

- **Phase 33 serve-early and Phase 34 enforce default interplay (test-harness races, fixed).** Phase 36 run 1 (main at `dbdbf23`) failed live closeout C and production live 5 because the live suites called a tool before the serve-early session was ready (`REALM_NOT_ACTIVE`); PR 172 (`7c44538`, `waitUntilServed`) fixed it. Run 2 failed the same two because the status call, now served, was refused `POLICY_DENIED`: the live session carried no host label under enforce; PR 174 (`c9130d1`, the `--host claude` label in `startMcpSession`) fixed it. Run 3 (main at `04ca807`) passed both. Both causes were test-harness findings that Phases 33 and 34 exposed in suites last run before them; no product file changed (`36-VERIFICATION.md` R2).
- **Every shipped client attaches under enforce (the Phase 34 per-client proof).** `test/integration/enforce-default.test.ts` ran against a real daemon over a real socket on a policy file with no `capabilityTokens` key: the 18 `mcp-config` hosts, an ACP host, Omp's attach as the extension builds it and the status-class CLI commands attach; an unlabelled client, the stale frame and a daemon with no policy file are refused as designed, and the opt-out works. `test/host/adapters-labelled.test.ts` guards every shipped launcher. The three exceptions are Muse Code, Prime Agent and Grok Build (GAP-34-01). The proof is the test rig, not the host binaries; two real stale client binaries (v0.4.3, v0.4.9) were refused `POLICY_DENIED` live on 2026-11-18 and admitted under an explicit `off`.
- **Phase 35 evidence on the enforce default.** EVID-03 ran on the effective default with no policy edit: the registered command attached cold and went to active in 8088 ms, an unlabelled session was refused `POLICY_DENIED` with no tool work, and the audit file held one attach line and host claude with kid k1 on every call line. This ties Phase 33 and Phase 34 together on one host (claude); the Phase 35 report states that the interplay was observed once, that it is not the Phase 33 cold-attach proof, and that codex, opencode and the other hosts were not part of it. EVID-01 and EVID-02 ran after the flip (commit `7c44538` and later).
- **Phase 37 spec against `src` states.** The spec states that Realm has five states (unbound, connecting, active, error, stopping) and does not connect to Anda; `src/core/states.ts` freezes the same five and its transition table (9 edges) matches the spec's n6 table as read by the Phase 37 verifier. `andaUrl`, the `ANDA_` codes and the degraded state have 0 occurrences in the spec and the `ANDA_` codes 0 in `src/core/errors.ts`. This is a read, not a permanent check: no test or script compares the spec with the code (D-37-09).
- **Later phases did not change the earlier product behaviour.** Phase 35 changed no source file and no policy default (tests, test support and documents only); Phase 36 changed no file under `src`; Phase 37 changed the spec only. The error catalogue stays at 29 codes after Phases 33 and 34.

## Accepted limitations and unverified items

Each item is listed in full in its VERIFICATION report; none was run by a verifier.

Accepted or carried by owner decision, listed here by name:

- **ENF-04 partial.** PR 168 (plan 34-03) was squashed with a title that has no `!` marker; the flip commit `2637d9a` carries it, landed as a merge commit and is in the changelog. A follow-up marked commit needs an owner decision.
- **Muse Code, Prime Agent and Grok Build have no host id** and stay refused under enforce (GAP-34-01). The docs name the opt-out and the borrowed label; no real session of the three was run against the default.
- **kimi and kimi-code not run** (GAP-24-02): `kimi` is an archived stub; Kimi Code needs an owner decision.
- **Capability tokens give no defence against a same-uid reader.** A process of the same uid that can read the token, the process environment, the key file or run the attach step is not stopped, and a model with a native shell in its host is such a process. EVID-02 settled the memory-read claim only narrowly: a non-descendant same-uid process was denied at the open of the memory file at `ptrace_scope` 1 on Linux 6.8 and Node v24.18.0; other kernels, other `ptrace_scope` values, `process_vm_readv` and `ptrace` attach were not exercised. The attach is unauthenticated (D32-1); an enrollment secret stays deferred.
- **EVID-03 host turn used a scripted loopback provider, no real model.** claude issued the tool call; a model deciding to use Realm was not shown, and no real model turn ran through any host in this milestone. claude 2.1.322 needed `ENABLE_TOOL_SEARCH=false`.
- **EVID-01 Set B not run.** The whole unit suite as a regular user was not run; Set A (24 files, 494 tests, twice) was. It does not gate EVID-01.
- **OI-11 Omp responsiveness: a loaded-host run that failed its thresholds** (6 of 97 probes unanswered, maximum 9868 ms, 95th percentile 8910 ms, longest gap 11369 ms; about 11 s unanswered during the Omp cold attach). It is not a quiet-host measurement and no cause is established; the Omp extension still attaches before answering (Phase 33's serve-early applies to `realm mcp`). Accepted as a loaded run (labelled loaded) and carried into v5.1.
- **Finding F-3.** After the `TOOL_TIMEOUT` reply (28083 ms) the `sleep 47` sleeper was listed on 13 consecutive polls. [INFERENCE] It may have ended by its own run time; it is not proven killed, and the test passes either way. Planned for v5.1 together with OI-11.
- **Daemon teardown flake observed once.** One window run of Phase 34 showed `daemon.stopped` with `REALM_STOPPING` and one failed teardown after about 30 s; the restarted daemon reaped the container. It did not recur, is not attributed to capability tokens and was not investigated.
- **Live evidence is kept outside the repository** (the windows of 2026-11-18, the probe reports, audit-line copies): the repository records counts, results, dates and the pages that cite them.
- **The hosts' real model turn never shown.** No host made a tool call through the not-active window on its own; whether a host's model retries a refused `REALM_NOT_ACTIVE` call (OQ-33-03) is not shown.

# Milestone v6.0 audit: Responsiveness, exec kill proof, host ids and evidence debt

Scope: phases 38 to 44 (requirements OMPR-01..06, EXEC-01..03, HOSTID-01..03, TEAR-01..02, DEBT-01..03, KIMI-01..02: 19 ids). ## Integration check (cross-phase)

No separate integration-checker run was made; the checks below are read from git history and the phase reports. Evidence tier: repository read, git history and the dated live windows; the verifiers ran no live step.

- **Phase 39 watchdog wraps every dispatcher exec.** Every dispatcher exec starts as `/usr/bin/bash -c SCRIPT realm-exec-wd SECONDS WORKLOAD` (`docs/integration/openshell.md`, exec watchdog requirement), so the Omp tool path, the MCP hosts and the ACP path reach the same wrapper. The Omp dispatcher path through the wrapper is proven by production live 7, which passed on the Phase 39 build. The Phase 42 whole-suite run first failed one test under a scrubbed environment (the watchdog `BASH_ENV` case) and the fix in PR 203 (`62b85fe`) made the test deny group kill through an exported bash function; that is a test change, not a watchdog change.
- **Phase 44 changes the Omp extension closure.** Plan 44-02 moved the daemon-launch functions to `src/daemon/launch.ts`; the compiled `src/omp/extension.ts` value imports dropped from 98 to 43, and the attach start moved one `setImmediate` turn later behind an injected deferral guarded by the session-current check. `src/omp/plugin.ts` is now exactly 1000 lines, the module-size ceiling (991 before plan 44-02); the next change to it must go to a new module. The gate-closure and lint allowlists name the new module without widening (`44-02-SUMMARY.md`).
- **Fail closed and the capability tokens.** Fail closed is kept: the deferral never runs a mutation before the session is ready. The capability-token enforce default is unaffected: Phases 39, 41, 42 and 44 changed no policy default or schema; Phase 40 added three host ids to the closed list and the `profiles` schema together and `test/integration/enforce-default.test.ts` attaches and completes a call for every id under the default with no policy file key.
- **Phase 40's 22 host ids are pinned.** The registry (22 hosts, 21 `mcp-config`, 19 recipes) is pinned in `docs/integration/host-plugin-contract.md` and the registry, matrix and recipe tests; the guard test `test/host/adapters-labelled.test.ts` lost its named exception for the three hosts and names only the shared Grok bundle. The Kimi hosts of Phase 43 use the same registry rows; the generated support matrix block carries both.
- **Phase 38 and Phase 44 on one record.** Phase 44 did not turn the VOID into a pass: its documents say "owner override of the VOID outcome (D-44-01); the evidence is one valid run and loaded-host runs; no quiet-host verdict was reached". The Phase 38 decision rule and thresholds stay valid for a future quiet-host window; Phase 44 changed which samples that window reads (from Omp's ready frame), not what it demands.
- **Release line.** `release/milestone.json` stays `{"milestone":"v6.0","minor":6}`; releases 0.6.1 to 0.6.7 were cut during the milestone. The error catalogue stays at 29 codes.

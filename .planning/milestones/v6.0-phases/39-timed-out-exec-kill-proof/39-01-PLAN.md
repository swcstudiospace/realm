  <name>Task 1: The process-tree probe, its parser and verdict, proved on a real local tree</name>
  <files>test/support/process-tree-probe.ts, test/integration/exec-kill-proof-helpers.test.ts</files>
  <behavior>
    - test/support/process-tree-probe.ts exports TREE_PROBE_SCRIPT, treeProbeArgv, parseTreeListing, judgeTree and the type TreeMember. Follow the style of the existing probe in test/integration/live-closeout.test.ts (SLEEPER_SCRIPT, a node script built from string pieces) and of the other support modules (fixed text, no secret, no environment value).
    - The script runs as node -e SCRIPT marker secondsList pgidList. marker is the unique argument the exec carries. secondsList is a comma list of sleeper durations (for example 300,301) or a single dash for none. pgidList is a comma list of process group ids already seen in flight, or a single dash for none. treeProbeArgv builds exactly that argv and refuses (throws a plain Error) a marker that does not match lowercase letters, digits and dashes, 8 to 64 long, a seconds list that is not digits, or a group list that is not digits.
    - A process is a member when any rule holds: (1) one element of its argv equals the marker; (2) its argv has exactly two elements, the first with the base name sleep and the second one of secondsList; (3) its process group id is in pgidList; (4) its parent is a member (repeat until no change, so descendants are found). The probe skips its own pid, every ancestor of its own pid, and pid 1. A zombie has an empty command line and is found only through rules 3 and 4.
    - Output, one line each: first a line count N, then N lines member PID PPID PGID STATE START COMM ARGV where START is field 22 of the stat file (read after the last closing parenthesis, so a command name with spaces or parentheses cannot shift the fields), COMM is the command name with spaces replaced by underscores, and ARGV is the argv joined by single spaces with control characters replaced by question marks and clipped to 160 characters. A process that vanishes while being read is skipped, not an error. Any other read error makes the probe print nothing and exit 1.
    - parseTreeListing(stdout) returns { ok: true, members } or { ok: false, detail }. It fails (never returns zero members) when the count line is missing, when the count differs from the number of member lines, when a member line has the wrong field count or a non-numeric id, or when there is any other non-empty line. An empty tree is the valid answer count 0.
    - judgeTree(flight, after) takes the last in-flight listing and a later listing and returns { dead, running, zombies, sameProcess }. running holds the members of after whose state is not Z or X; zombies the members in state Z or X; dead is true when running is empty; sameProcess lists the running members whose pid and START equal a member of flight (the same process, as opposed to a recycled pid or a later member found by rule). A pid that appears in both listings with a different START is not the same process.
    - A fifth export controlsHold(flight, wanted) returns undefined when the in-flight listing has at least three members, including one member whose argv holds the marker, one member for each wanted sleeper duration, and with the marker member and every duration member in one process group (a wrapper process the sandbox adds above the group, or the timeout process of the fixed build, may or may not be listed and is not required); otherwise it returns a one-line detail naming what is missing. The live scenarios use it as the positive control, and judgeTree and the scenarios take the group ids of the marker member and the duration members as the recorded groups.
    - test/integration/exec-kill-proof-helpers.test.ts (default suite, no gate, no network, regular user) proves: (a) parseTreeListing on valid, empty, count-mismatch, garbage, short-line, and command-name-with-parentheses fixtures; (b) judgeTree on fixtures: all absent is dead, only zombies is dead with the zombies reported, a running member with the same pid and START is not dead and is sameProcess, the same pid with another START is running but not sameProcess; (c) treeProbeArgv refusals; (d) the script against a real local tree: start sh -c with a background sleep and a foreground sleep and the marker as the shell's name argument, detached into its own group; wait (scaledMs) until the probe, run through the current node binary, lists at least three members; assert the probe's own process is not listed although its argv holds the marker; assert controlsHold is satisfied; kill the group with SIGKILL, wait for the shell's exit event, probe again with the recorded group id and assert judgeTree says dead; (e) a surviving control: the same tree left running gives dead false; (f) the orphan case: kill only the shell, probe with the group id and assert the two sleepers are still found through the group rule and the tree is not dead, then kill the group; (g) descendants through rule 4 alone: probe with a dash for seconds and for groups finds the sleepers of a live shell by the marker on the shell. The test fails with a clear message if the process table is not readable (Linux only; the live suite is Linux only). Every group started is killed in t.after, even on failure. All waits go through scaledMs.
  </behavior>

    10. Settle: wait 3000 ms, list again, assert no running member (a listing taken once more, so a transient empty listing cannot pass).
    11. Usable: a dispatcher exec of echo ok exits 0 with ok on stdout; realm status through the existing helper reads state active (as production live 7 does); close stdin; realm mcp exits 0 within MCP_EXIT_TIMEOUT_MS.

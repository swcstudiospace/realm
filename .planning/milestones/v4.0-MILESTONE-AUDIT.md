## Owner decisions of 2026-11-18

No separate integration-checker run was made; the checks below are read from the repository and the phase reports.

The Phase 28 verification pins this with `test/runtime/config.test.ts` and `test/cli/cli.test.ts`. - **Phase 29 annotations are unaffected by Phases 28 and 32.** `git log 63f89c0..HEAD` (63f89c0 is the Phase 29 closure) shows no commit touching `src/mcp/`, `test/mcp/`, `test/support/mcp-annotation-pins.ts` or `src/acp/` after it. - **Phase 32 gate and client wiring and the Phase 29 server path.** The gate lives in the daemon channel (`src/daemon/channel.ts`, `daemon.ts`, `client.ts`), in front of the unchanged dispatcher; `src/mcp/server.ts` carries no capability code, so the descriptors that `tools/list` serves are the same with `capabilityTokens.mode` off or enforce. Evidence tier: a 24-row refusal matrix over a real socket and an end-to-end daemon test, both with fake runtime seams and run in CI as a regular user. Enforce mode has not run against the production stack with a real host (see Accepted limitations).
- **Phase 31 and Phase 32.** The production rehearsals (claude, codex, opencode) ran on 2026-11-18 with capability tokens off. No host has been rehearsed with `enforce` on. The two phases do not conflict; the combination is simply unrun.

## Accepted limitations and unverified items (not blockers)

Accepted limitations:

- **FS-02** (race-resistant path resolution) remains unmet as written and is an owner-accepted approximation of 2026-10-23; carried unchanged (D-27-08, OQ-27-03 default).
- **UI-01** (non-blocking Omp status item) remains an owner-accepted limitation (2026-10-23; re-measured 2026-10-28).
- **Phase 30 criteria outcome DROP, overridden by the owner to BUILD in Phase 32** (2026-11-17, D30-1 and D32-1). By the frozen criteria M1 (no attacker class a token stops that today's model admits) and M2 (no delivery channel both admitted and meaningful) were not met. The criteria and readings were not edited; the override is recorded beside the outcome. The value claimed is per-host least privilege and verified audit attribution only.
- **Capability tokens give no defence against a same-uid reader** of the token, the process environment, process memory or the key file `keys.json`. The attach is unauthenticated: a same-user process can attach as any host and receive that host's profile. The memory-read claim is an inference (the `/proc/PID/mem` probe only runs as a non-root user with `ptrace_scope` 1 or more; the implementers ran as root). Enforce mode is not live-tested on the production stack. The default stays `off`; the owner plans enforce-by-default for the next minor (v5.0 candidate).
- **kimi and kimi-code remain a named gap, GAP-24-02** (kimi is an archived stub; Kimi Code was not installed, an owner decision, and documents no non-interactive MCP validator).
- **Cold first attach exceeds the hosts' connect timeout, GAP-31-04.** Sandbox creation takes about 35 to 60 s against a 30 s OpenCode timeout and a Claude probe that gave up; only a warm attach passed. Owner decision 2026-11-18: plan a v5.0 phase to answer the handshake before `up` finishes. Until then the docs state that `realm up` is run first.
- **`docs/specs/realm-spec.xml` still describes Anda** (52 matches; OQ-28-01 and OQ-27-02, default no edit; recorded as R-27-02). The spec is the product's and changes only on the owner's direction.
- **Live evidence is kept outside the repository** (the 2026-11-18 windows, the OpenCode scratch install): reported in the registry and matrix, not reproduced by files here.

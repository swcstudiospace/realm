## 1. What this audit found by running the shipped build

The requirement table called HOST-01, HOST-02 and TOOL-05 complete, and each had evidence: the host manifests passed their hosts' own validators, and a throwaway client had driven `realm mcp`. No real host had ever been connected to it. On 2026-10-29 the real hosts installed on the verification machine were run against release 0.2.0, each in an isolated home, attached to the realm account's production stack (connection checks only; no model call):

| Host | Release 0.2.0 | Release 0.2.1, installed on the realm account |
|---|---|---|
| Claude Code 2.1.308, `claude mcp list` | failed to connect: "Server's protocol version is not supported: 2026-07-28" | Connected |
| Grok Build 1.0.46, `grok mcp doctor` | handshake accepted (2026-07-28), 6 tools | handshake accepted (2025-11-25), 6 tools |

The causes, with their sources, are in `docs/integration/mcp.md` Q6:

1. **MCP-ERA.** The server answered `initialize` with `protocolVersion: "2026-07-28"`. A client that does not support the version in the server's answer disconnects, and Claude Code speaks the legacy `initialize` era. In the 2026-07-28 versioning page's matrix a legacy client works only against a dual-era server. Q5 had decided to answer both eras; the code returned the modern string from both.
2. **MCP-RESULT.** Every result lacked `resultType`, `server/discover` returned fields of no revision, `tools/list` lacked `ttlMs` and `cacheScope`, and a successful `tools/call` returned the bare outcome with no `content` block, which is what a host shows to the model.
3. **MCP-SCHEMA.** The `exec` descriptor had a root `oneOf`. The Anthropic Messages API rejects such a tool with a 400 that fails the whole request, so a host that loaded the server would have failed every model turn. No connection check can show this; a descriptor test guards it now.
4. **ACP-VERSION.** A copied constant made both agent surfaces advertise 0.0.0 in release 0.2.0, because the release job rewrites only the manifest. They read the manifest now.
5. **OMP-PROBE.** The Omp extension carried its own copy of the attach probe and tolerated fewer start-up replies than the CLI. The review of the fix then found that the shared probe, by treating a timeout as "no daemon", spawned a second daemon over a busy one and made the waiting hosts abort on its `LOCK_CONFLICT` line. The probe is tri-state now and never spawns over a held socket.

All five landed in pull request 7 (merge commit 2c818c4) and released as 0.2.1 (release commit 8b3ff55). On the installed 0.2.1: both hosts connect as above, and the nine-scenario production live suite passes 31 of 31 (596 s), including scenario 6, which now handshakes as a legacy client and sends a modern request to the same live process. Afterwards no container, workspace, state or secret entry, daemon or supervisor remained, and the three user units were active.

Not verified: a model-driven tool call through any host (it needs a model), and MCP connectivity from Muse Code, Hermes Agent and Omp (no connectivity command, or no usable install on this machine).

## Constraints

- C, `-std=gnu11`, `-Wall -Wextra -Werror`, static, no dependency beyond the C library and the kernel interfaces. No `system()`, no shell.
- The policy is a fixed rule set in source, parameterised only by the workspace path, the scratch path, and the state path. Any change to the rule set is a new helper digest.
- Fail closed: any failure before `execve` exits non-zero and the workload never runs.
- Pure policy logic lives in `realm_policy.c` so that native tests can call it without a container. The `main` file only parses arguments and calls it.
- The seccomp list is a denylist, as in the spike. Its review is a security-gate task (A10) and is recorded in the SUMMARY. A denylist is weaker than an allowlist; the review decides whether it stays a denylist for v2.0.

## Tasks and waves

### Wave 1 (parallel: disjoint files)

- T1, helper program. Add `sandbox/realm-helper/realm-helper.c` (argument parsing and the two subcommands) and `sandbox/realm-helper/realm_policy.c` and `realm_policy.h` (pure functions):
  - `idle`: PID 1 loop. Reaps children on SIGCHLD, exits 0 on SIGTERM, forwards nothing it does not own.
  - `run -- PROG ARGS`: (1) check the kernel Landlock ABI is 3 or higher, else exit non-zero; (2) set `PR_SET_NO_NEW_PRIVS`; (3) install the Landlock ruleset: writable workspace and scratch paths, read and execute on `/usr`, `/etc`, `/proc`, `/dev`, and the state path, everything else denied; (4) install the seccomp denylist (`SECCOMP_RET_ERRNO` with `EPERM`, architecture-checked, the 29 syscalls from the spike); (5) `execve` PROG.
- T2, build. Add `sandbox/realm-helper/Makefile` with targets `all` (static binary), `check` (native tests), `clean`. Flags as in the constraints. Check: `make -C sandbox/realm-helper all` exits 0 with no warning.
- T3, native tests. Add `sandbox/realm-helper/test/` with a test program for the pure functions: the ABI gate refuses versions below 3; the ruleset builder rejects an empty workspace path; the denylist contains exactly the expected syscall numbers; argument parsing rejects `run` without `--`. Check: `make -C sandbox/realm-helper check` exits 0.
- T4, seccomp review input. Add a comment next to each denied syscall with its reason, and a `sandbox/realm-helper/SECCOMP.md` listing the 29 entries. Check: every entry in the list has a reason; the security gate (A10) reviews the list and records its verdict in this phase's SUMMARY.
- T5, image definition. Add `sandbox/Dockerfile`: a builder stage on a pinned gcc base (the digest is chosen and recorded in the SUMMARY at execution), copying the source and building the helper; a runtime stage on the pinned node 24 alpine base (see the digest note in phase 9.3), copying the helper to `/opt/realm/bin/realm-helper`, and writing its SHA-256 and the source digest into image labels. The image build itself is not run in this phase.

### Wave 2 (after wave 1)

- T6, in-container probe. Add `sandbox/realm-helper/probe/probe.c`, built into the image's test stage only. It runs five checks under the helper and prints one line per check: `/tmp` write denied with EACCES; `/workspace` write succeeds; `keyctl` returns EPERM; `NoNewPrivs` is 1; `Seccomp` is 2. A control run without the helper must show `/tmp` write succeeds. Check: the probe logic is covered by a native test with a fake filesystem call seam; the in-container run is part of phase 9.6's live suite, not this phase's gates.

## Decisions this phase uses

- PD-06 (default: in-repo source, pinned builder). PD-10 (the helper is the only Landlock applier, pending 9.5's evidence). PD-16 (single derived image, with the helper and the AgentOS runner).

## Acceptance

1. Given T1 and T2, When `make -C sandbox/realm-helper all` runs with `-Werror`, Then it exits 0 with no warning (PRD-ENF-01).
2. Given an ABI below 3 (native test seam), When `run` is evaluated, Then it refuses and the program to run is never executed (PRD-ENF-01, fail closed).
3. Given `idle` as PID 1 in a native test, When a child exits and SIGTERM is sent, Then the child is reaped and the process exits 0 (PR-08).
4. Given T3, When `make -C sandbox/realm-helper check` runs, Then every native test passes.
5. Given T4, When the security gate reviews `SECCOMP.md`, Then its verdict (denylist kept or changed) is recorded in the SUMMARY (PRD-ENF-01).
6. Given the image record from phase 9.3, Then it carries the helper's SHA-256 and the source digest (PRD-ENF-02).
7. Given the in-container probe in phase 9.6, Then all five checks pass and the control shows `/tmp` writable without the helper (PRD-ENF-03).

## Gates

`make -C sandbox/realm-helper check`, plus the repository gates `npm run typecheck`, `npm test`, `npm run lint`, `npm run check:docs` (the repository gates do not compile C; the make gate is part of this phase's record). A CI job that runs the make gate is a workflow change and needs human review (PR-15); it is not part of this phase unless the owner asks.

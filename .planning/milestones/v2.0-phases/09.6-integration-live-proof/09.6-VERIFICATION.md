## Live suite (PRD-TST-02)
`test/integration/production-driver.test.ts` is gated by `REALM_LIVE_PRODUCTION` and skips in CI and by default. Six scenarios run against the production stack:

1. The default policy confines the sandbox and keeps the workspace, the probe, and the transfer working.
2. `realm up` right after a `down` reaches active.
3. An egress allowlist admits exactly its host:port pairs, and the resolver is synthetic.
4. An image digest that does not exist fails closed with OPENSHELL_START_FAILED and leaves no container.
5. After the daemon is killed with SIGKILL, the next `realm up` reaps what it left and reaches active with exactly one sandbox.
6. `realm mcp` serves exec, write, and read over stdio against the live sandbox.

Results on the final build: the full suite passed 28 of 28 assertions (exit 0), and scenario 5 passed three more times on its own (3 of 3). Residue after the runs: no daemon, no containers, no sandboxes, no state or secret directories, and an empty workspace.

History of the one flaky scenario (kept because it explains the last fix): scenario 5 failed on the first run with REALM_STOPPING (the startup sweep's force-remove was cut off; fixed by bounding the stop grace and the request time), and failed once more on a later commit with OPENSHELL_START_FAILED. The driver's log named the cause: CreateSandbox refused at `create.state_dir`, because the crashed daemon never ran delete and the old sandbox's state directory was still on disk, and whether the gateway's own cleanup had removed it by then was a race. The driver now reclaims a stale state or secret directory when libpod has no container of that name and the driver tracks none live (commit d2db549). A live duplicate, a symlink, a socket in the state directory, and an unreadable inspect are still refused, with unit tests for each.

## Verified live (names and values only)
- `realm up` reaches active in about 22 to 31 seconds; `realm status` reports active. Active requires the runner probe to pass.
- The workload is the AgentOS runner as a managed exec child of the in-container runtime (PID 1). It runs as uid 1001 with CapEff 0, CapBnd 0, NoNewPrivs 1, Seccomp 2 (filter mode), and IPv6 disabled.
- Writes: /tmp, /workspace, and /dev/null are writable; /etc and /home are read-only. /workspace is the pinned host workspace (a file written in the sandbox appears on the host).
- `keyctl`, `add_key`, and `request_key` fail with EPERM (the vendored seccomp profile with an added deny rule).
- A 16 MiB upload and download round trip is byte-identical, with SHA-256 compared on both sides.
- Exec works under the same policy, and a non-zero exit status is propagated.
- Egress is default-deny. The resolver is synthetic: every A query is answered with the next address in 198.18.0.0/15 and is never forwarded (a host packet capture showed no DNS packets for names outside the allowlist). A connection to a non-allowlisted host fails with EACCES; AAAA returns no data; an allowlisted host:port connects.
- `realm down` exits 0 and leaves zero residue. A wrong image digest fails closed at the driver's `create.image` gate.
- Crash recovery: after a SIGKILL of the daemon, the next `realm up` reaps the leftover and reaches active with one sandbox (scenario 5).
- `realm mcp` exec, write, and read work without an Anda bridge (owner decision, 2026-10-28).

The earlier claim that an attach was observed by counting a control-socket connection stays retracted; these three results come from reading the status item.

## Boundary probes (A10 review, live)
The runtime is non-dumpable: /proc/1/environ, maps, and mem are denied; ptrace, process_vm_readv, and pidfd_getfd return EPERM; pidfd_open returns ENOSYS. The workload can connect() to the runtime's control socket, but a TLS handshake without a client certificate is rejected. Creating a user namespace is denied on this host, but the host sets `apparmor_restrict_unprivileged_userns`, so that denial is host-specific (see F4 below). A unix socket planted in the workspace by a host process after the sandbox starts is reachable from the sandbox; the owner accepted this as a documented residual risk (2026-10-28) with the operator rule to keep no sockets in a pinned root.

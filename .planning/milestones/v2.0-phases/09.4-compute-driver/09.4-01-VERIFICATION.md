## Live defects found and fixed in this phase

1. The driver advertised an empty implementation version, and the gateway refused the driver at startup. Fixed in fa235c6: the version comes from the package's own manifest, read at the entry and validated.
2. CreateSandbox never prepared its workspace or state directory, so the lifecycle refused every create. Fixed in 8565dc8: both are prepared before the lifecycle runs. A failed create removes only the state directory it made.
3. The driver refused a create with no command, and a name without the realm prefix. Owner decision, 2026-10-25: accept an empty command, and add the prefix to the container name. Fixed in 3606f4b. Live: a named create without the prefix produced realm-t2-d; a prefixed name stayed unchanged; an unnamed, command-less create produced a realm-prefixed container, all accepted.
4. check:pack did not assert the protos. Owner-approved edit to scripts/check/pack-smoke.mjs in 9e93a21.

## Limits carried to phase 9.5

1. A sandbox stays Provisioning (ConfigurationPending) until the supervisor reports its effective configuration. The CLI's create therefore waits until its own timeout. This is expected until 9.5.
2. The PD-08 stop and start observation needs a Ready sandbox. It is carried to 9.5.
3. AuthenticateSandbox returns UNIMPLEMENTED and is not advertised. It is decided with the supervisor and the launch and active credential files in 9.5.

## Residuals

- Create does not call EnsureWorkspace, because the gateway calls it only for provider credentials. The driver prepares the workspace itself.
- A failed cleanup can leave a state directory, which blocks re-creating that name until delete. This follows the brief's literal rule.
- The workspace directory outlives its sandboxes, by design, because it may hold user data.
- The protobufjs install script stays blocked (owner decision, 2026-10-25). The driver runs without it.

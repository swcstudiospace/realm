## Sequence
1. Lanes A to H edit in parallel; no lane runs a gate.
2. The orchestrator builds, runs typecheck, targeted tests, lint and the full test suite once; failures go to corrective tasks.
3. Reviews: implementation review per lane; security review of the seccomp and egress changes; supply-chain review of the image and CI changes.
4. Local commits per root cause.
5. Live proof: prune, rebuild the image once (the apt pin and in-image compile change it), compare the new runtime binary digest with the recorded one, install, restart the driver and gateway, run the full live suite with the three new scenarios, the RT-02 negative probes, a doctor run and the Omp TUI checks, then the residue check.
6. Records: verification, summary, requirements and roadmap from evidence only.

## Acceptance
1. Each fixed finding has a failing-first unit test and a named commit.
2. Typecheck, lint, check:docs, check:pack, test:scripts, check:mcp and `npm test` pass after the fixes with no test deleted or skipped to get there, and no suppression directive added.
3. The live suite passes on the final image, including a dead runner moving the status to disconnected within the health interval.
4. No new error code, policy schema field, session-record field or tool schema field is introduced.
5. Every item the owner must decide is listed in the verification file with the recorded default.

## Risks and stop conditions
- The seccomp group 2 rules may break the in-container runtime. They are a separate rule object and are dropped alone if the live suite fails.
- The rebuilt image may produce a different runtime binary digest. The difference is recorded as evidence; the live suite then validates the new binary.
- The health loop must not resurrect state after down. Covered by tests with fake time.
- Stop and report if a lane needs a frozen contract, touches more than the files it owns, or a fix cannot be verified.

## Rollback
All work is local commits on feat/realm-v2-0. Revert the commit of the failing lane. The host keeps the previous image tag pinned in the driver unit until the new image has passed the live suite.

# Phase 09.5 Summary: isolation backend and sandbox protocol on the built-in path

Status: complete on the amended plan, VERIFIED with live checks carried to phase 9.6 (owner decision, 2026-10-26). The verification record is 09.5-01-VERIFICATION.md. Where the final-state section below differs from the plan (09.5-01-PLAN.md), the final-state section governs. The plan's own status line ("PLANNED, NOT EXECUTED") is historical.

## Final state (2026-10-26)

- The plan was amended by the owner on 2026-10-26. The plan asked for a realm-owned IsolationBackend and SandboxProtocol server (tasks T1 to T9). The delivered route is the Docker reference driver's built-in path: the driver starts the host supervisor with the built-in backend name `openshell-sandbox` and a unix socket in a directory shared with the container, and the SandboxProtocol server is the upstream runtime that runs inside the container as PID 1. The registered realm backend was written, committed, and then removed as dead code.
- Live T0 on the built-in path, at b41889d: the sandbox reached Ready (ConfigurationReady true, Ready true), the in-container runtime (`openshell-sandbox` with the bootstrap argument) is PID 1, and the host supervisor session is connected. The supervisor runs on the host as the realm account, spawned by the driver. The evidence is in 09.5-01-VERIFICATION.md under "Live evidence".
- PD-15 (supervisor placement) is decided: host placement, as observed. PD-10 (enforcement authority) is decided: the runtime's own policy, and the realm helper leaves the workload path. Both are owner decisions of 2026-10-26, recorded in the verification file.
- Plan tasks T3 to T9 are provided by the upstream runtime on the built-in path, so they are not built in this repository. Their live checks moved to phase 9.6. Plan criterion 9 (gateway configuration) is the one that passes in this phase on tests and on the gateway's own preflight of the rendered file.
- Gates at b41889d: all exit 0 (see the verification record).

Branch `feat/realm-v2-0`. Repository commits are listed under "Commits" below.

## What the phase delivered

1. Wave 1, the registered backend (25 to 26 October). Protos and a backend skeleton, handles bound to a sandbox and invalidated on delete, the supervisor bearer check on Attach, the backend started in the driver process, the gateway's isolation section, `OpenBoundary`, `DiscoverPolicy`, and launch-material intake (1228c0b through 538c0ef). This is the registered-backend work the plan describes for T1, T2, and part of T3 and T9. It was removed in edb1053 once the built-in route was chosen.
2. The route decision (8d44ac3). The 2026-10-26 planning record states the reason: the supervisor's SandboxProtocol service lives in the in-container runtime, so a host-only backend could not reach Attach or Confirm (154bad9 recorded the finding and blocked the phase on an owner decision). The owner chose to build the in-container runtime and mirror the Docker reference driver.
3. The built-in path (217c157, edb1053). The driver now starts the runtime and spawns the host supervisor, with a channel directory shared with the container (`channel.ts`, `runtime-channel.ts`, `supervisor.ts`). The gateway renders the built-in selection instead of a registered backend.
4. The runtime as the container's main process, with no exec route (20a81b6). This is the RT-03 outcome: the runtime is PID 1 and no container-runtime exec route exists.
5. Shared-uid mitigation (3ce4f7a). The TLS key and the CA private key are removed once the listener is confirmed, and the socket path length is checked.
6. Supervisor exit (7dda8f1). The driver observes the supervisor's exit, and delete reports what happened.
7. Lint (03c0382). `child_process` is allowed in exactly two driver files, the channel and supervisor modules (owner decision).
8. Image (14abfbc, d7caa03). The in-container runtime is built in a pinned bookworm builder with a glibc gate, and the gate allows the dynamic loader's own soname.
9. Create-path fixes found live (6a8b56b, b41889d). The create stopped being refused at podman, create refusals are logged by check, and the runtime's low-port sysctl is set in the sandbox create body.

## Decisions recorded in this phase (owner, 2026-10-26)

These are the owner decisions as 09.5-01-VERIFICATION.md lists them. Each is restated here in one line.

- Route: the Docker reference driver's built-in path with a shared unix socket; the registered realm backend is removed.
- RT-03: the runtime is the container's main process and there is no exec route. The wording of RT-03 is not amended (REQUIREMENTS.md, RT-03 row).
- Lint: `child_process` is allowed in the two supervisor spawn modules only.
- Shared uid: the TLS key and the CA private key are removed once the listener is confirmed.
- PD-15: host placement. PD-10: the runtime's own policy.
- Plan amendment: tasks T3 to T9 come from the upstream runtime; the live checks move to phase 9.6.
- PD-08: the driver's refusal of StartSandbox and StopSandbox stays for now. Restart is a later decision.

PD-09 option (a) (suspend and resume stay `UNIMPLEMENTED`) was carried from the plan and is not changed by this phase.

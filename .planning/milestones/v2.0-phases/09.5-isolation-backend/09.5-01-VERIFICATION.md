## Live evidence (built-in path, commit b41889d)
- The sandbox reaches Ready. ConfigurationReady is true (ConfigurationAccepted), Ready is true (DependenciesReady), and the supervisor session is connected.
- The container's PID 1 is the runtime: openshell-sandbox with the bootstrap argument. The container is running, with no restarts.
- The workload process runs as uid 1001, with zero effective capabilities, NoNewPrivs set, and seccomp mode 2.
- The host supervisor runs as the realm account, as a child of the driver. It holds a unix socket to the runtime's control socket, and loopback connections to the realm gateway.
- After startup the channel holds only control.sock. The runtime deleted the bootstrap. The driver removed the TLS key and certificate once the listener was confirmed.
- PD-08, live: the gateway refused stop on a Ready sandbox, and accepted start on a Ready sandbox as a no-op. The driver's refusal is covered by unit tests.
- Delete removed the container, the artifacts, the state, and the supervisor process. The CLI key copies were removed.
- The exec path needs SSH access configured for the supervisor, which the driver does not yet set up. The live Landlock check therefore waits for phase 9.6.

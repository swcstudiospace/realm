<threat_model>
## Trust Boundaries

| Boundary | Risk |
| --- | --- |
| Operator argv and environment to `realm host` | A crafted host name, path or `HOME` redirects writes, or an argument is echoed into logs. |
| Host config directory (writable by the workload) to install, uninstall and doctor | A workload with write access to a host home edits Realm's entry to change what the agent launches, or plants a symlink. |
| `realm host` to the audit chain and `host.log` | Unaudited changes; secrets or config content in log output; a refusal that looks like success. |
| Doctor (also reachable through the daemon) to the state directory | A malicious receipt makes the check read outside the state directory or hang the daemon's doctor. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-21-21 | Tampering | argv and config-home input | high | mitigate | Task 1: strict parser, `--config-home` must be absolute and is re-validated (exists, real path, symlink walk) by plan 21-03; unknown hosts refused; user-supplied names echoed only when `^[A-Za-z0-9._-]{1,32}$`. |
| T-21-22 | Elevation of privilege | env-derived home | medium | mitigate | Task 1: `hostEnvFrom` requires an absolute `HOME`; override variables only from the table (`CLAUDE_CONFIG_DIR`) and only absolute values; no `process.env` read in `src/host` or `src/cli/host.ts` (source-text test, lint). |
| T-21-23 | Repudiation | host change without a record | high | mitigate | Task 1: lifecycle test requires two verifiable audit lines per real operation, none for dry-run or noop, and `host.log` events; admission failure aborts before any write (plan 21-03). |
| T-21-24 | Information disclosure | CLI output and logs | high | mitigate | Task 1: output carries ids, relative paths, actions, byte counts, hashes; refusal text is fixed; test with a secret in the fixture config asserts absence from stdout, stderr, `host.log` and the audit file. |
| T-21-25 | Tampering | workload edits Realm's host entry | medium | mitigate | Task 2: doctor `warn`s on drift with the exact repair command; uninstall refuses to remove a modified entry (plan 21-03); the launch value is a bare command plus fixed args. Residual risk, accepted and documented: a workload that can write the host config home can also edit other host settings; Realm detects changes to its own entry only. |
| T-21-26 | Denial of service | doctor receipt reads | medium | mitigate | Task 2: directory and receipt reads under `withTimeout`, 300-entry and 1 MiB caps from the receipt parser, `fail` instead of throw, local and daemon paths both bounded. |
| T-21-27 | Spoofing | forged receipt in the state directory | medium | mitigate | Task 2: strict parse, the check compares on-disk hashes to receipt hashes and writes nothing; a forged receipt can at worst cause a `warn`; uninstall deletes only items whose bytes match (plan 21-03). |
| T-21-28 | Information disclosure | packaged output | low | mitigate | Task 3: pack-smoke verifies shipped files only; the doc and changelog carry no host-local path or secret (host-paths gate). |

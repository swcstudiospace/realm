<objective>
Give `realm host install omp` a real, fail-closed recipe: ship an Omp extension shim as `adapters/omp`, install it into the Omp agent directory's `extensions/realm/` through the existing `bundle-copy` engine, and refuse the two situations where installing would be wrong.

Purpose: an installed Omp loads the Realm extension at session start with no manual `omp plugin install` link and no `-e` flag, which is the precondition for auto-open (plan 22-03). The install path is the one the public Omp extension page documents for file-only installs (loose module under `~/.omp/agent/extensions/`), and it keeps Phase 21's rules: atomic, receipt-owned, idempotent, no spawn, no new error code.
Output: the `omp` runtime entry, `adapters/omp/index.js`, token expansion and two preflights in the adapter, two refusal reasons, updated pack-smoke list, tests.
Non-goals: no change to the other 18 entries, to the recipe primitives, to `src/omp/**`, to docs (22-03), to the allowlist (22-03), or to any live Omp configuration. A live-host check of the shim is 22-03 Task 4; until then the claim is "proven on a fixture host".

<threat_model>
## Trust Boundaries

| Boundary | Risk |
| --- | --- |
| Sandbox workload → host config | The workload plants a symlink or file where the shim is written, or a hostile directory name, hoping install overwrites or escapes |
| Installed shim → Omp process | The shim runs with Omp's full privileges (extensions are not sandboxed); a tampered shim is code execution in the host |
| Package path → shim source | A path with quotes or newlines could break the string literal and inject code |
| Two load routes → one session | A plugin link plus the shim registers the extension twice |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-22-06 | Tampering | install target | high | mitigate | Phase 21 engine unchanged: realpath home, symlink refusal (`PATH_ESCAPE`), `foreign-content` refusal, `atomicWriteFile` with `expectedPriorSha256`, home must exist. Task 2 re-proves each on the omp recipe. The workload cannot reach the Omp agent dir (not mounted), so this is a hostile-workspace and shared-account defence. |
| T-22-07 | Tampering | installed shim | high | mitigate | Receipt owns the exact expanded bytes; `status` reports `drifted`, uninstall refuses `POLICY_DENIED`; the shim is one import, no environment read, no write. Task 2 tests tamper then uninstall. |
| T-22-08 | Elevation of privilege | URL injection | high | mitigate | `pathToFileURL` plus `JSON.stringify`; Task 2 imports the shim from package roots containing `"`, `\`, space, `%41`, `#`, `?`. Unknown `@realm:` tokens are refused so a shipped file cannot request another substitution. |
| T-22-09 | Denial of service | double load | medium | mitigate | `already-loaded` preflight refuses before any write; `detect().conflicts` lets doctor report it (22-03). |
| T-22-10 | Spoofing | unbuilt or moved package | medium | mitigate | `extension-unbuilt` refuses install rather than write a shim that imports nothing; a moved package is repaired by reinstall (update path tested). |
| T-22-11 | Information disclosure | refusal text | low | mitigate | Reason text is fixed and path-free; logs carry host id, reason code, dry-run flag only (existing `host.install.refused` shape). |

Accepted residual: a user who edits `PATH`/`PI_CODING_AGENT_DIR` to a directory they do not own is installing into that directory by their own request; `--config-home` already names the target explicitly in that case.
</threat_model>

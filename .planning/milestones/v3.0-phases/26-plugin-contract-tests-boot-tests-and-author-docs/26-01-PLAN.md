<objective>
Turn the 19-row runtime table and the installer engine into a contract that is checked by one set of rules, for every host, with proof that the rules can fail.

Purpose: Phases 24 and 25 pinned each host by hand (runtimes.test.ts, the per-host recipe suites) and added four all-host loops. This plan adds the single place where a universal rule is stated once and run against every row, the registry that says which evidence each host has and fails when it is missing, and one generic lifecycle that every recipe must survive. A contributor adding a host (plan 26-03 documents how) gets the row checked and the missing pieces named without editing a test.
Output: three test support files and three test files. Nothing in `src`, nothing in the docs (plan 26-03 consumes the registry).
Non-goals: no new host, recipe kind or engine feature; no change to any existing test; no live host, no network, no Podman; no replacement of the per-host recipe suites (they keep their host-specific seeds and formats); no coverage-floor edit (plan 26-03).
</objective>
